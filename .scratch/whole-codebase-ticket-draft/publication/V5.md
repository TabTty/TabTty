## Parent

[Deepen recording, transport, persistence, vault, SSH and grapheme ownership](https://github.com/TabTty/TabTty/issues/40)

## What to build

Let management explicitly create a missing vault or initialize the confirmed same empty regular file, with verified results and no implicit initialization from credential use.

## Acceptance criteria

- [ ] Expose the explicit management intent with localized missing/empty explanation and existing new-master rules. A new vault receives a new identity/root and does not rewrite selected settings or credential references; ordinary unlock, authentication, all pickers and Explorer paths keep their refusal.
- [ ] Bind confirmation to the opened location and acquired missing/empty evidence. Missing-path creation never overwrites; empty initialization rechecks the same zero-byte regular file and rejects replaced, nonempty, unsupported, stale or unresolved targets.
- [ ] Use the same internal target/namespace admission as verified publication for source, destination, candidate and parked names. Preserve the empty original and report parked-original, target, candidate and recovery facts separately through actual completion.
- [ ] Permit only the existing narrow compensation in the original execution after installation was prevented or definitively settled: return the exact owned empty original to a proven-absent source without overwriting, verify it and report failure. Reconciliation never performs compensation or blind repair; cleanup-only failure does not erase proven success.
- [ ] Adopt root and shared metadata only after required publication/preservation proof, with capacity reserved beforehand and actual secret/I/O owners retained through cancellation. Test the real explicit UI path against collision, changed identity, parking/install/compensation faults, uncertainty and concurrent ordinary commits.
