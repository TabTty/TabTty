[Deepen recording, transport, persistence, vault, SSH and grapheme ownership](https://github.com/TabTty/TabTty/issues/40)

## What to build

Route existing encrypted vault creation, saves and explicit restores through the shared verified file operation while the vault owner retains authentication, root adoption and credential eligibility.

## Acceptance criteria

- [ ] Supply immutable encrypted images, original-basis evidence and existing private-access, writer-lock and preservation policy to the shared file owner. Never transfer master passwords, roots or plaintext credentials to common operation records or diagnostics.
- [ ] Verify equality with an already authenticated encrypted image as that generation, not merely a matching vault ID; independently authenticate and validate selected restore content. Each acquired image supplies both validation and digest evidence, and verification never runs under a mutex it must reacquire.
- [ ] Adopt the candidate snapshot/root only after verified target publication and required backup/recovery preservation. If candidate bytes reached disk but preservation failed or is unknown, keep the prior effective revision, block writes and new credential retrieval, preserve established roots while actually needed, and report the on-disk candidate generation truthfully.
- [ ] Preserve exact original bytes on explicit restore and retain owned conflict-recovery material without overwriting external files. Reinspection never repeats encryption/publication, clears independent external-stale restrictions, or treats ordinary reopening as recovery.
- [ ] Keep actual I/O and owner-dependent verification alive through cancellation or view closure; permit visible quiescent unresolved exit and retain only non-secret inspection evidence after the responsible secret lifetime ends. Coordinate operation/artifact accounting and retirement with the common owner.
- [ ] Use real vault/OpenSSL validation, independent encrypted fixtures and Windows file checks alongside controlled partial backup, uncertain password change, conflict, late verification and cleanup faults. Verify existing authenticated sessions survive blocked new retrieval.
