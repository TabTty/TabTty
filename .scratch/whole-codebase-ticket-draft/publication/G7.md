## What to build

Let users configure the per-paste clipboard text maximum, defaulting to 512 MiB, and review the entire immutable text through the normal confirmation whenever it contains a newline or exceeds 1 KiB.

Related existing work: [#12](https://github.com/TabTty/TabTty/issues/12), [#39](https://github.com/TabTty/TabTty/issues/39). These references identify established behavior or adjacent acceptance work; they are not blocking dependencies and are not to be reopened or reimplemented by this ticket.

## Acceptance criteria

- [ ] Persist application-wide maxPasteTextBytes as a positive finite checked whole-byte value, default 536870912 when absent in an older supported settings file. Zero, negative and overflowing values are invalid; preserve ordinary Save/Cancel/failure semantics and provide English/Japanese UI resources.
- [ ] Capture the effective maximum when each operation starts. Measure the actual selected Unicode text as two bytes per UTF-16 code unit before target conversion, counting unchanged CR/LF and both units of supplementary scalars while excluding the terminating NUL, allocation padding, metadata and other clipboard formats. Equality is eligible; excess rejects the whole source without trimming.
- [ ] For otherwise valid within-limit text, display exactly one existing confirmation iff CR/LF occurs or source size is strictly greater than 1024 bytes. Exactly 1024 bytes without CR/LF uses the direct path; equality with a configured maximum does not independently force confirmation. Use the same captured source and frozen broadcast recipients through preview, preparation and send.
- [ ] Preserve Cancel default, counts, ending-newline indication, pacing and application-run-only Remember transitions. Size-confirmed newline-free text uses the same Send/Cancel behavior with no line-delay events. A direct small paste retains the existing remembered character delay without updating memory.
- [ ] Keep every part of the immutable text accessible through bounded read-only scalar-safe preview pages/ranges, including a huge single line or grapheme. Do not make a whole-text visual copy, split surrogate pairs, apply terminal-storage omission, invent separators or send a preview page instead of the original source.
- [ ] Keep capture, analysis and preflight under actual shared resource ownership with bounded cancellation work. A delayed clipboard provider need not be immediately cancellable; late results remain owned and charged until released without accumulating detached workers.
- [ ] A later saved maximum applies only to newly started operations and never truncates or cancels an existing capture/preview/send. No aggregate setting, persistent confirmation bypass or memory-percentage policy is added. Supplied AI text keeps its separate 256 KiB UTF-8 limit and receives neither clipboard access nor human clipboard confirmation.
- [ ] Verify ASCII/Japanese/supplementary source-size boundaries, maxima below/equal/above 1 KiB, CR/LF independence, old/invalid settings, failed Save/Cancel, concurrent limit changes and full-text access through actual settings, clipboard, WPF/UIA and send paths. Record affected responsiveness/resource evidence and distinguish failed, blocked and not-run checks without claiming unmeasured gains.
