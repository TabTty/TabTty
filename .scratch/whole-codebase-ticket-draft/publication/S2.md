## Parent

[Deepen recording, transport, persistence, vault, SSH and grapheme ownership](https://github.com/TabTty/TabTty/issues/40)

## What to build

Open an SFTP subsystem and perform real transfers using one shared SSH channel owner for identities, requests, delivery, credit and closure while the existing terminal channel stays usable.

Related existing work: [#5](https://github.com/TabTty/TabTty/issues/5), [#6](https://github.com/TabTty/TabTty/issues/6), [#7](https://github.com/TabTty/TabTty/issues/7), [#8](https://github.com/TabTty/TabTty/issues/8). These references identify established behavior or adjacent acceptance work; they are not blocking dependencies and are not to be reopened or reimplemented by this ticket.

## Acceptance criteria

- [ ] Introduce the accepted named channel operations with a prebound awaited incremental SFTP consumer and bounded peer-request policy, using the existing authenticated connection. Keep subsystem/INIT/version, SFTP request IDs, file semantics and UI in the SFTP owner; do not replace the SSH/OpenSSL client or add channels/features.
- [ ] Reserve instance, registry, receive/control and outcome capacity before OPEN. Maintain distinct local/peer IDs, generation, checked send/receive windows and packet maxima; freeze accepted bytes/request bodies/stop offsets. Rejected admission issues nothing, repeated Close joins existing shutdown, and records/observers/waiters have finite versioned bounds.
- [ ] Keep the common reader independent of application consumption, with ordered nonrecursive callbacks outside transport locks. Request-reply FIFO follows actual committed send order; notification has no slot, stopped committed requests retain their original slot, and protocol replies/fixed prior-delivery fences progress without waiting for later output.
- [ ] Separate consumption eligibility, queued grant, committed possible peer entitlement and completed WINDOW_ADJUST. Reserve capacity before grants, handle an early peer response safely, retain uncertain ownership and never double-credit. Preserve payload-byte accounting, 1 MiB windows and 32 KiB data limits with independent interoperability evidence.
- [ ] Validate SFTP lengths before allocation, retain the 256 KiB body maximum and consume only prefixes adopted into bounded parser ownership without awaiting a future callback or local I/O. Charge copy overlaps, parser/reply/frame storage, live/closing channel buffers and actual I/O under existing 2 MiB/32 MiB and separate request/provider guards.
- [ ] Implement opening stop, late confirmation/refusal, directional EOF, once-only CLOSE and distinct protocol closure, delivery, actual release and identity retirement. Unresolved original identities cannot be reused at timeout; preserve SFTP-local versus SSH connection-wide failure semantics and independently observable consumer failure.
- [ ] Demonstrate production browse/upload/download with real peers plus controlled different IDs/limits, tiny fragments, paused consumer/request reply, window-grant races, malformed SFTP versus SSH, late OPEN/CLOSE, rejected final callback and capacity thresholds. The terminal transport migration can then use this same owner without another ledger.
