## What to build

Archive a locked, readable damaged or unlocked vault through a source-bound complete operation, then report the actual archive location and end the old usable owner without creating a replacement vault.

## Acceptance criteria

- [ ] Acquire bounded regular-file identity, length and exact-byte evidence before existing confirmation, rejecting unsupported/reparse/unavailable sources. Recheck the confirmed image and any unlocked editing basis before the move; changed evidence invalidates consent rather than authorizing different bytes.
- [ ] Use the shared verified-file namespace admission authority for all affected names, with a unique sibling non-overwriting move. Preserve external-stale/partial restrictions, selected path, profile references and previous backup; never expose a generic public move or implicitly initialize.
- [ ] Inspect actual source and destination effects after issued work settles, including error-after-success. Intended destination bytes alone are insufficient if source is unreadable, reappears or changes; retain known archive facts and conflict/unresolved state without moving again or touching the new source.
- [ ] Completed archive ends the old usable owner and clears its root after dependent work settles. Notify shared consumers, retain established sessions, display the destination and honor standalone-editor closure after acknowledgement. Presentation failure cannot undo the move or make it replayable.
- [ ] Keep bounded evidence/artifact ownership and actual release separate from cancelled observation, using an explicit handoff for a verified final archive file. Verify locked/damaged input, stale confirmation, source replacement, uncertain move, concurrent commit/initialization, late completion and acknowledgement behavior through real operations.
