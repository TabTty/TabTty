# Integrate the complete native-only terminal candidate

## What to build

Integrate all completed native terminal behavior into one production candidate and remove production managed terminal selection, handoff, mutable replicas, and diagnostic switching. Close the full contracted feature and encoding coverage matrix through actual application paths before whole-product integration is claimed.

## Acceptance criteria

- [ ] Demonstrate all 48 receive/transmit identities and every contracted VT, screen, Unicode, input, reflow, recording, and observation family through the real profile/session/application paths, with no unresolved supported feature treated as an exclusion.
- [ ] Remove production managed starts, handoff/export-import execution, fallback calls, mutable managed terminal replicas, and runtime/diagnostic engine selectors. An isolated comparison reference may remain test-only.
- [ ] Verify crossed encoding, source, resize, alternate-screen, interval, local-echo, and observation scenarios, including terminal replies and recording failure in one operation. Preserve independent expected outputs rather than relying only on reference comparisons.
- [ ] Verify resource refusal, stale generation completion, retained disconnected state, immutable results held across disposal, and actual cleanup ownership. Neither pressure nor an unimplemented supported operation selects managed execution.
- [ ] Treat absent or mismatched native binaries as explicit packaging failure. Preserve the accepted Rust/standard-library dependency boundary and pinned Unicode/mapping data, without new third-party dependencies or macro runtime.
- [ ] Record the exact completed candidate and integrated functional results. Whole-product functional green is assessed here; the subsequent deployment and measured-acceptance gate determines cutover readiness rather than inferring it from native residency.

- [ ] Verify explicit tab/window, bulk and automatic closure against the complete native candidate, including joined A/B requests, refused later review, retained disconnected output, held snapshots, recording faults, stale completion, movement/final-exit ordering and deterministic final release.
