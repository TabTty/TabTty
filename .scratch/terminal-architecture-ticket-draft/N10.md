# Use native stateful JIS terminal encoding

## What to build

Complete JIS receive/transmit state in Rust, using the accepted Japanese mapping and exact ASCII, Roman, Kanji, unsupported-repertoire, and kana behavior through actual terminal input and receive paths.

## Acceptance criteria

Consultation outcome, 2026-11-17: the user approved the shared selected JIS/EUC repertoire, JIS ASCII/Roman and IN/OUT order, kana choices, unsupported repertoire states, and shared recovery/exact-send policy in Rust over a planned Microsoft CP932 base mapper. Native 5022x conversion is not an approved substitute for these explicit terminal policies. Native equivalence remains acceptance work; additional CP932 mapping overrides need separate consultation if an actual mismatch is found. Do not reconfirm the approved scope. These design decisions do not authorize implementation.

- [ ] Implement accepted designations, IN/OUT choices, eight-bit and SO/SI kana, return to the relevant single-byte state, and unsupported two-byte repertoires until redesignation. Preserve independent DATA/stderr partial and charset state.
- [ ] Verify exact backslash, tilde, yen, and overline behavior, extension reverse mappings, and required output designation order even when a designation is redundant.
- [ ] Distinguish incomplete charset/VT controls from incomplete printable units, and verify malformed-unit, chunk, EOF, embedded-control, and recording-provenance boundaries.
- [ ] Preflight complete outgoing text with isolated state. Reject without changing live state or sending a prefix; reserve and issue necessary codec closure and one started paste wrapper at the accepted stop boundary, before automatic replies.
- [ ] Verify profile-to-session display, sending, paste, local echo, and recording with independent expected bytes. Add no managed codec callback, new dependency, or extension of the old UTF-8 handoff exporter.

## Blocked by
