## What to build

Support all 41 accepted single-byte encoding identities for independent receive and transmit settings through actual connection profiles and native sessions. Use the common one-byte framing and exact mapping policy without managed codec callbacks.

## Acceptance criteria

Consultation outcomes: existing Unicode table reuse for ISO-8859-10/11/14/16 in Rust was approved on 2026-11-16, and the specified shared recovery/exact whole-send policy on 2026-11-17. Preserve exact mappings and provenance. For the other 37 single-byte identities, use explicit native Microsoft code pages with that shared policy; static assessment found no additional identity-specific table or patch. Native equivalence remains acceptance work. Consult before adopting any newly required mapping correction, replacement data or custom behavior; do not reconfirm the approved scope. These design decisions do not authorize implementation.

- [ ] Cover the 15 accepted ISO-8859 identities, 15 accepted OEM identities, and cp874, cp1250 through cp1258, and koi8-r without collapsing distinct profile identities.
- [ ] Verify every input byte position, undefined-position replacement, C0 handling, and decoded C1 nonexecution against independently fixed mapping expectations. Include CP864 low-byte mappings, CP1258 combining marks, and embedded NUL with explicit lengths. Verify supported-platform code-page availability; document accepted Microsoft/Unicode data provenance and licensing.
- [ ] Use strict exact reverse mapping with no best-fit, normalization, or width substitution. Rejected sends do not emit a prefix or change encoder/local-echo state.
- [ ] Exercise independently selected receive/transmit identities, DATA/stderr ordering, display, input, and recording through the actual profile/session path. Every delivered scenario remains native.
- [ ] Extend shared interpretation and admission accounting; add no third-party codec dependency, managed codec callback, temporary codec handoff, or runtime selector.
