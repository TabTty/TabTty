## What to build

Replace recording callers' terminal attachment and position-management obligations with complete BeginRecording, CutoffRecording, and AbortRecording operations. Rust and its managed adapter own interval mechanics, bounded Text/Terminal delivery, and terminal-side cleanup; C# retains format, group, Raw, and file ownership.

## Acceptance criteria

- [ ] Route the actual recording caller through the named operations and verify existing normal UTF-8 start, pause, resume, and abort behavior through real files. Do not expose callback repair, interval counters, a public interval handle, or a native-result draining recipe.
- [ ] Return applied, inactive/no-change, or rejected outcomes with resulting terminal recording activity, terminal usability, and failure reason. Native activity does not pretend to describe Raw admission or disk durability.
- [ ] Reject Begin while active before mutation; leave all selected projections inactive after a valid new-interval preparation failure; preserve decoder/parser/position state on inactive Cutoff/Abort.
- [ ] Keep receive-only projection updates while inactive, preserve the captured format selection, and distinguish orderly cutoff, abort, source EOF, and terminal disposal. EOF followed by cutoff does not repeat tails.
- [ ] Keep activation and nonfailing group publication in one ordered event. Validate owner identity there, preserve cancellation-before-commit behavior, and retain delivery/cleanup after a caller stops waiting following commit.
- [ ] Exercise the real Rust operation seam with controlled capture/rejection and actual session/file integration, observing resulting bytes and state rather than callback invocation counts.
