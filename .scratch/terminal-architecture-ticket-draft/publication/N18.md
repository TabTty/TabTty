## What to build

Collect new attributable functional, deployment, presentation, ownership, and performance evidence for the complete native-only candidate, then determine whether integration and production cutover satisfy the accepted gates. Historical partial-native results do not establish this candidate's readiness.

## Acceptance criteria

- [ ] Record exact source, build, artifact, dependency/data identities, machine, and workload inputs. Preserve passed, failed, blocked, and not-run results distinctly; do not turn a missing environment or historical result into a pass.
- [ ] Recheck affected real transport, file, WPF, UIA, English/Japanese, and lifecycle integration behavior, including full-screen applications, disconnected retained output, and snapshots held through cleanup. Preserve distinct external-environment checks rather than rebuilding already accepted features.
- [ ] Run the accepted 20-session responsiveness workloads and overload control checks, including the specified runtime, interaction sampling, storage, concurrent transfer conditions, and p95/max reporting. Include paths crossing resize, alternate screens, recording transitions, and observation.
- [ ] Run the 1-to-6 receiving-tab memory workload with reference retention and all three logs, across visible seeding, hidden reception, EOF/log drain, and restoration. Report whole-process private-memory and working-set peaks against the stated decimal-GB objective.
- [ ] Report queue and resource peaks, refusals, output/log completeness, CPU/storage, retained ownership, and failures without reducing accepted retention or features, dropping output, or silently weakening targets.
- [ ] Verify clean supported Windows deployment with matching bundled native dependencies and explicit missing/mismatched-binary failure. Approve cutover only against the applicable completed gates; leave unresolved failures and unexecuted external checks visible.
