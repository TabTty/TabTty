# Search and publish native terminal history consistently

## What to build

Use Rust-owned bounded history/search preparation and terminal consistency validation through the existing AI observation path. Preserve C# ownership of counterpart authorization, external handles, expiry, framing, queue admission, and ordered publication.

## Acceptance criteria

- [ ] Preserve literal Ordinal and OrdinalIgnoreCase semantics, UTF-16 query/overlap bounds, whole-cluster positions, UTF-8 text limits, and complete response-size checks. Native lowercase or normalization is not a substitute.
- [ ] Produce bounded pages, search coverage, and matching successor metadata; repagination shares the original work budget. A text limit too small for the next cluster returns a resource outcome without splitting or empty-success loops.
- [ ] Validate all relevant content, including negative scanned regions, overlap, context, and remaining continuation range. Detect edit-then-restore, distinguish known retention loss from unavailable proof metadata, and preserve unchanged prefixes and fixed search ends.
- [ ] Keep final terminal validation and existing authority, cancellation, fixed-expiry, staged-handle, and nonblocking queue admission checks in one ordered outcome with terminal mutation excluded. Serialization and proportional allocation remain outside that gate.
- [ ] Failed publication neither activates successors nor consumes source checkpoints or evicts live handles solely for unpublished work. Preserve error precedence and original resource ownership through delayed cancellation and delivery.
- [ ] Verify the actual AI operation and publication path with real native terminal state and controlled clock/queue races. Do not redesign AI permissions, the existing handle registry, or the transport contract.

## Blocked by

- T15 — Read retained native output through presentation and history APIs.
