# Establish the native-only UTF-8 integration baseline

## What to build

Record the exact starting workspace and establish the shared integration branch on which complete terminal replacement will be implemented. Run the existing UTF-8 scenario through the actual profile, session, Rust adapter, transport, rendering, and recording paths. Freeze the existing managed implementation as an isolated comparison reference.

This is an intermediate integration baseline, not replacement readiness. Preserve the recorded pre-migration baseline while the candidate evolves on the integration branch; do not introduce a user-facing engine selector or new fallback. Whole-product green is required at the final gate, while each intervening ticket must demonstrate its delivered native scenario through the real application path.

## Acceptance criteria

- [ ] Record the exact workspace, dependencies, generated data, and build inputs before implementation. Do not assume a committed baseline or existing HEAD; establish an attributable baseline without losing existing work.
- [ ] Activate the candidate adapter through the actual session construction path on the integration branch. Verify ordinary UTF-8 receive, send, display, recording, and retained disconnected output using the existing production interfaces and a real transport integration case.
- [ ] Keep the comparison implementation isolated from the candidate production call graph. Retain independent expected byte/state cases; comparison against the old implementation is supplementary evidence.
- [ ] State which existing tests depend on managed starts or handoff and which scenarios remain unported. Do not report those incomplete scenarios as accepted product exclusions or overall readiness.
- [ ] Preserve session ordering, projection ownership, and existing resource policies. Add no runtime engine selector, new codec handoff, mutable managed replica, or macro runtime.

## Blocked by

None (can start immediately).
