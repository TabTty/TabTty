# AI 協業の検証計画

2026-11-14 に[AI 協業のヒアリング](../drafts/ai-terminal-collaboration-issue.md)の合意済み Q1～Q35 に対する検証方針を確認した。ユーザーは、UI と AI が共有する協業操作の境界と、それを補完する Windows、MCP、実ホストの統合テストを明示的に確認した。その後、`ready-for-agent` を付けて [GitHub Issue #2](https://github.com/TabTty/TabTty/issues/2) を公開した。本書は受け入れ基準を定める。結果と未実施のケースは[実装状況](implementation-status-ja-jp.md#ai-collaboration-validation-2026-11-14)を参照。ソースと契約の整合性レビューは設計の根拠となる。[アプリケーションと API の契約](ai-collaboration-ja-jp.md)、[トランスポートの契約](ai-collaboration-transport-ja-jp.md)、既存の[セッション契約](session-and-recording-ja-jp.md)を併せて参照。

## 検証の層と独立した観測

UI と AI アダプターが使うアプリケーションとセッションのインターフェースを主なテスト境界とする。権限状態、不変の端末スナップショット、上限付きの結果ページ、セッションで順序付けられた入力受付と投入イベントを観測する。非公開メソッドや代替セッション実装だけで検証しない。実装承認後に既存の[端末の境界](tdd-seams-ja-jp.md)を協業操作で拡張する。公開ツール `tabtty_list_shared_sessions`、`tabtty_read_state`、`tabtty_read_history`、`tabtty_search_history`、`tabtty_wait`、`tabtty_send_input`、`tabtty_return_control` をすべて対象とする。GUI 専用の共有と操作権付与も同じ認可の所有者へ届くこと。

期限と競合には差し替え可能な単調時計と制御可能なトランスポート完了境界を使う。実端末モデルにバイトを与え、出力バイトを独立に定めた期待値と照合する。本番エンコーダーの出力を同じ実装でデコードするだけでは不十分。受付、部分投入、完了、失敗を独立に制御する。後の層では実際の stdio、Windows IPC、WPF 入力、接続先ピアを使い、代替手段では確認できない動作を検証する。

セッションと接続、連携先の接続、共有、付与、操作の識別情報、リデューサー順序、バイト数をテスト専用トレースに記録する。合成フィクスチャは既知のペイロードを記録してよい。本番の診断ではテストのために端末の記録やアプリ管理下の秘密を取得しない。可能なら独立した接続先レコーダーで受信バイトを確認する。投入だけでは接続先での実行や効果が一度だけ生じたことを証明できない。

## 第 1 層　アプリケーションとセッションの契約

| ケースと決定事項 | 刺激と必要な観測結果 |
| --- | --- |
| A01 空の初期状態、Q3/Q9/Q31 | 同一表示名の連携先を二つ接続し、どちらもタブを列挙または読めないことを確認する。選んだ一つとタブを共有すると、その連携先だけに当初は閲覧専用で見える。複数タブを共有しても一括で操作権は付与されない。 |
| A02 独立した権限、Q3/Q8/Q10 | 操作権の付与、返却、再付与、引き継ぎ、共有終了を行う。返却と引き継ぎは許可済みの読み取りを保つ。共有終了は利用可能な接続を維持しつつ、以後の読み取りと送信を拒否する。旧権限は復活せず、古い返却要求は新しい権限を取り消せない。 |
| A03 操作範囲、Q5/Q13/Q18 | 公開操作を列挙し、初回要求と継続の各 `oneOf` を検証する。カーソルだけの正当な検索と、カーソルに新しい検索文字列を併記した要求の拒否を含む。未知のフィールドを拒否し、接続、プロファイル、マクロ、ファイル転送、デスクトップ、クリップボード、vault の操作は公開しない。検査用の秘密情報は結果とエラーに含まず、敵対的な端末データから権限を付与したり送信検査を回避したりできない。 |
| A04 画面観測、Q2/Q12/Q22 | 位置付きテキスト、幅広および結合クラスタ、カーソル、寸法、対応する属性とモードを解析する。`tabtty_read_state` は可視性や人間のビューから独立してライブセッションを追従する。幅広クラスタを横切る要求領域は行ごとにクラスタ全体へ拡張し、実際の範囲を報告する。半分のクラスタや架空の矩形切り出しは返さない。 |
| A05 保持範囲、Q1/Q11/Q12 | 出力後に共有し、`vim` が代替画面を所有している間も保持済み通常バッファーを取得する。取得元は明示する。ディスクの記録は読まず、代替画面の再描画をアーカイブせず、破棄行を復活させない。 |
| A06 上限付き検索、Q11/Q30 | 記号を含むリテラル、日本語、大小文字、折り返しや窓の境界、途中のプロンプトを検索する。不変で上限付きの窓と検索文字列の長さ分の重なりを使い、公開前に一致の有無にかかわらず走査領域、文脈、進捗のリビジョンを検証し、走査範囲と継続を公開する。読み取りで人間のペイン、選択、検索結果は動かない。 |
| A07 整合した範囲、Q30 | 1 ページ目の取得後、2 ページ目の前に追記、編集、消去、再フロー、要求内容の除去を行う。同じ長い行に追記しても、安定した範囲アンカーとリビジョンで変更されていない先頭を保持する。変更・欠落した範囲は状態を報告し、位置だけでの置き換えや架空の統合スナップショットは返さない。 |
| A08 入力の挙動、Q13/Q14 | テキスト、対応付けたキー、複数行貼り付け、対応するセル単位のマウス操作を送る。セッションのコーデックとモード、一つの入力所有者、単位全体の厳密な事前検査、ブラケットのフレーミング、順序、ローカルエコー、ペイロード上限を既存の入力契約と照合する。 |
| A09 古い観測、Q25 | 観測と新しい送信の間に接続や操作権の世代、通常と代替の切り替え、寸法、リセットによるレイアウトを変更する。変更して元に戻す ABA も含め、ペイロードを送らない。通常のセル更新だけなら受付可能。テキストに変化がなくても、セッション世代の受付と完了の序数により、次の送信の観測は前の完了後に必要。 |
| A10 上限付き待機、Q10/Q26 | 対象の変更がある場合とない場合で仮想時間を進める。契約に従って changed/no_change/elapsed または明示的な中断を返す。接続先での成功や失敗は返さない。モデルの長い思考時間だけで有効な権限を失効させたり連携先を喪失扱いしたりしない。 |
| A11 進行中の入力と権限付与、Q29 | 人間の送信の待ち行列、間隔付き貼り付け、接続先に報告済みの押下、未確定 IME 中に操作権を付与しようとする。このタブを入力元とし他の送信先を固定した同時送信も含む。理由を示して即時拒否し、完了後に保留中の付与を暗黙に適用しない。後で明示的に付与できる。 |
| A12 人間による引き継ぎ、Q4/Q23 | テキスト、貼り付け、マウス入力中に取り消す。境界後に新しい AI ペイロードは通過しない。未送信末尾を止め、有効で必要な後処理だけを実行し、待機中は **引き継ぎ中** を表示してから人間の入力を受け付ける。引き継ぎを開始したキー、Ctrl+C、Esc、キャンセル済みペイロードは送らない。 |
| A13 拒否と到達未確認、Q24 | 上限、符号化、古い状態により投入前に拒否したら、理由を報告して操作権を維持する。投入された可能性のある段階で失敗したら、一部または不明の到達を報告して操作権を終了する。通常の端末エラーテキストだけでは取り消さない。 |
| A14 切断と再起動、Q15/Q34 | 切断、保持タブでの再接続、ブリッジの喪失と再接続、アプリ再起動を行う。切断済み共有タブは読み取れる場合がある。新しい接続またはブリッジ接続には新しい権限が必要で、古い入力、付与、履歴識別子を受け付けない。 |
| A15 同時送信の遷移、Q16/Q19/Q20/Q28 | 入力不可でもアクティブなチェック済み対象は共有を拒否する。共有開始で非アクティブ時に記憶したチェックを消す。同時送信開始、全選択、範囲リセット、手動チェック、ウィンドウ間移動での選択でも、共有タブはオフとし理由を表示する。共有終了で以前のチェックを復元しない。 |
| A16 同時送信の入力元、Q16/Q19/Q28 | 未チェックの閲覧共有タブを人間の入力元と、別途送信先候補として使う。入力を解決するのはチェック済みで対象となる送信先だけ。入力元への暗黙の送信や、共有を根拠にした送信先への参加は行わない。AI 操作中の入力元は引き継ぎ前に人間の入力を送れない。 |
| A17 機能間の競合、Q16/Q22/Q28 | 共有や付与と同時送信の開始、固定された貼り付けやジェスチャーの選択、範囲をまたぐ移動を競合させる。一つの順序付き遷移が勝ち、固定済み送信先の暗黙の追加や除去はなく、無関係なモードは使える。移動や分割でセッションへの配信は重複しない。 |
| A18 将来のマクロ所有者、Q16/Q29 | 既存の入力所有者の境界で実行中または一時停止中のマクロを表現する。どちらでも AI 操作権は拒否し、許可済みの閲覧共有は使える。この所有権の検査のためのマクロランタイムは実装しない。 |
| A19 手助けと秘密情報、Q18/Q27 | 合成のパスワードや OTP のプロンプトに対して、効果を持たない理由を添えて操作権を返す。続きには新しい付与が必要。TabTty の質問ダイアログや前面化は起きない。リモートエコーには合成の秘密が含まれ得る。完全な伏字化や普遍的なプロンプト検出を報告しない。 |

A07 には保持行 100、5000、100000、一つの長い折り返し論理行、ページ境界をまたぐ編集、一致なしで検索予算を使い切る場合、除去後の継続も含める。契約上の全上限について、上限ちょうど、上限より 1 小さい値、上限より 1 大きい値を検査する。ページ追加でバッファー全体を固定したり、取得済みの割り当てを増やしたりしない。キャンセル、期限切れ、取り消しの読み取りは予約済みスナップショットメモリを解放する。

画面の継続ページは一つの不変の取得結果を維持する。ページ間で再描画し、固定の 60 秒の期限、連携先あたり 2 スナップショットの受付、スナップショット 16 MiB とアプリ 64 MiB の上限、最大グリッドが収まらない場合の明示的な切り出しへの切り替えを試す。切り出したグリッドを全体と報告しない。履歴では既定 200 行と最大 1000 行、UTF-8 テキストの既定 64 KiB と最大 256 KiB、架空の LF を加えないクラスタ境界での継続を試す。人間向けのミラーを含め、ツール結果の直列化上限 1 MiB を検査する。待機は既定 1000 ms、最大 10000 ms、不正な期限を対象とする。単調時計で推論時間と独立して制御する。

A06 では以前一致しなかった走査領域に一致を挿入し、結果の確定前に一致や周辺の文脈を編集または除去する。公開ページと進捗は検証済みの走査範囲を反映するか、変化を報告する。古い不一致が後続の作業を抑止してはならない。複数クラスタの検索文字列を各走査境界にまたがらせ、重なりを保って厳密に一度見つける。走査終了は対象範囲の走査完了を示す。現在の保持履歴全体で一致がないことまでは示さない。

A09 では最初の送信を受付後に停止し、処理中に画面を取得してから送信を完了し、その取得結果で二度目の送信を試みる。完了後の取得結果が存在するまで拒否する。操作シーケンスが偶然一致する以前の権限の取得結果も試す。新しい操作権の期間には使えない。

## 第 2 層　通信プロトコル、ブリッジ、Windows アクセス

LLM を導入する前に、独立したプロトコルクライアントでパッケージのブリッジを操作する。技術契約の全リビジョンとツールスキーマを試し、未対応版を明示的に拒否する。実ホストと同じ IPC 認可経路で通常と敵対的な要求を検査する。従来版 `2025-11-25` の初期化と新版 `2026-07-28` の要求単位のメタデータを独立に検証する。混在要求、メタデータの欠落や不正、検出、エラーエンベロープ、キャンセルの応答規則を含む。従来版を代替として提示しても、未対応の通信モードを受け入れたことにはならない。該当する場合の必須 `ttlMs`/`cacheScope` を含む新版のキャッシュ結果を検査する。従来版エンベロープに新版の動作を漏らさず、認可済み端末データを連携先や共有境界をまたいでキャッシュしない。

| ケースと決定事項 | 必要な検証範囲と証跡 |
| --- | --- |
| W01 stdio のフレーミング、Q6/Q32/Q35 | 関連する全境界で UTF-8 JSON を分割または連結する。不正・未知の入力、2 MiB 上限、途中の EOF、キャンセル、並行読み取り、正当な通知を試す。stdout はプロトコルメッセージのみ、上限付きの stderr エラーに端末や秘密のペイロードは含まれない。 |
| W02 連携先の結び付け、Q7/Q9/Q31 | 申告名のなりすましと別接続のハンドルを試す。未共有と未知のセッションは内容を明かさず `not_shared`、認可済みセッションで不正なカーソルは `cursor_expired`。同一連携先の会話は権限を共用できる。名前や通常の MCP チャットに認証済みの隔離境界はない。 |
| W03 ローカル IPC、Q7/Q31/Q32 | 別ユーザー、同一ユーザーの別ログオン、異なる昇格で実プロセスを使う。リモートパイプ拒否、エンドポイント名の先取り、古いエンドポイント、PID 再利用、実行ファイル不一致、接続重複を試す。実際のアクセス判断を記録する。文字列比較や ACL の模擬だけでは不十分。 |
| W04 重複送信、Q23/Q24/Q35 | 権限ごとの厳密なシーケンス、処理中操作一つ、結果 256 件と最大受付番号を試す。受付時に引数のダイジェストを固定し、基本の権限検査後、新規シーケンスの古さと符号化の事前検査より先に台帳を参照する。処理中、応答喪失、観測期限切れの要求、キャッシュ除去済みシーケンス、引数の変更を再試行する。再送や誤った `not_sent` を返さない。 |
| W05 連携先の喪失、Q15/Q26/Q32 | stdin/stdout を閉じ、ストリームを継承したプロセスが残る状態でホストやブリッジを終了し、IPC の破損、サスペンドと復帰、ハートビートと書き込みの期限を試す。喪失は境界で共有と操作権を取り消す。遅い推論や個々の要求の完了では正常な接続を取り消さない。 |
| W06 閲覧の取り消し、Q8/Q15 | 読み取りや待機が待ち行列、取得、直列化、トランスポート待ちの段階で共有を終える。GUI の取り消し後にブリッジチャネルへ新規確定しない。ブリッジはまだ取り消せる応答を捨てる。確定済みの配信は後から届く場合があり、OS やホストのバッファーからは取り戻せない。 |
| W07 アプリが利用できない場合、Q33/Q34 | TabTty がない場合、終了中、クラッシュ後に起動する。上限付きで利用不可と報告し、GUI、隠れたアプリ、新しい接続、アプリの延命は発生しない。ホストの再試行で権限は復元しない。 |
| W08 設定と配布、Q32/Q33 | クリーンなサポート対象 Windows PC で、空白と非 ASCII を含むパスの構成を手動登録する。TabTty は第三者の構成編集、依存関係やモデルのダウンロード、インストーラー、外部 AI アプリ起動を自動実行しない。 |

W04～W06 では認可前、受付後、最初のトランスポート書き込み前、部分書き込みの間、結果受付前、応答喪失後に処理を止める境界を置く。引き継ぎ、共有終了、サイズ変更、再接続、重複要求、遅延完了を各点で組み合わせる。中心となる受け入れ条件は **未承認のペイロード投入がゼロで、自動再送もゼロ**。必要なフレームやジェスチャーの後処理はトレースで別に示し、新しい要求入力にはならない。完了を証明できなければ不明のままとする。

制御時計で接続期限 5 秒、ハートビート 5 秒、死活監視と書き込みブロック 20 秒を試し、次に実プロセスとパイプの検出を確認する。上限付き JSON の深さ、重複プロパティ、UTF-8、両フレーム長形式をファズテストする。通常要求、接続、所有バッファーを飽和させ、取り消し、キャンセル、死活監視の容量が残ることを確認する。連携先ごとの通常呼び出し 20/s とバースト 40、アプリ全体 100/s とバースト 200、タブごとの新規送信 5/s とバースト 10 を制御時計で枯渇させて補充する。境界ちょうどの受理、上限超過の上限付き拒否、ピアやタブ間の公平な復旧を確認する。操作権の返却、キャンセル、人間の取り消し、非公開死活監視は、頻度と同時実行の両方が飽和しても独立した予約容量を維持し、軽量な反復呼び出しで枯渇しない。

## 第 3 層　ネイティブ Windows UI と入力

実際の WPF イベントルーティング、Windows IME、クリップボード、ポインターキャプチャ、UIA、対応するデバイスとトランスポートのドライバーを使う。セッションインターフェースの代替だけでは満たせない。実行ごとに Windows ビルド、IME、DPI、キーボード配列、画面構成、入力経路を記録する。合成 UI イベントだけでは IME やキャプチャを検証できない。

| ケースと決定事項 | 必要な観測 |
| --- | --- |
| N01 表示、Q17/Q21 | 英語と日本語で、共有と操作を形で区別するタブアイコン、ツールヒントと UIA 名、変わらないプロファイルラベル、選択タブの詳細を試す。保持された切断済み共有タブは接続と AI の状態を両方表示する。ライト、ダーク、システムでも識別できる。 |
| N02 アクセシブルな引き継ぎ、Q4/Q17/Q23 | キーボードのみのメニュー、ステータスバー、ナレーターで同じ操作に到達する。利用者が復元した非アクティブまたは最小化ウィンドウも対象。AI の応答なしでローカルに取り消す。通常端末キーを暗黙の付与として消費したり、引き継ぎキーとして転送したりしない。 |
| N03 IME、Q4/Q29 | 日本語を合成し、付与を試し、キャンセルまたは確定した後に明示的に付与する。ペインやタブをまたぐフォーカス変更は未確定入力をキャンセルする。確定は一度で余分な Enter はない。AI 操作中もローカル選択、コピー、スクロールは使え、端末テキストや入力は遮断する。 |
| N04 貼り付け、Q14/Q23/Q29 | 人間による複数行のクリップボード貼り付けは確認する。AI の複数行貼り付けはクリップボードを読まず、その確認も表示しない。符号化や書記素の境界で引き継ぎ、開始済みの有効なフレームだけを閉じ、残りの後処理を報告する。 |
| N05 マウス、Q13/Q23/Q29 | 対応する追跡と座標形式、複数ボタン、モード変更、キャプチャ失敗と喪失、ジェスチャー中の引き継ぎを検証する。AI 操作でデスクトップのポインターは動かない。対応する解放は新しい接続やモードに送らない。 |
| N06 ビューの移動、Q22/Q25/Q28 | 共有タブのウィンドウ間移動、分割、サイズ変更、タブ切り替え、最小化、最後のタブの分離を行う。許可された移動は識別情報と権限を保つ。グリッド変更で古い観測が無効になり、内側の分割だけではグリッドは変わらず、出力はフォーカスを奪わない。 |
| N07 実トランスポート、Q13/Q15/Q24 | SSH/Telnet と、実 Windows ドライバーで制御するシリアルのループバックまたはピアを対象にする。送信と後処理中に切断、取り外し、停滞を発生させ、接続先のバイトと保持状態を確認する。ドライバー完了だけでは接続先のコマンド実行を示さない。 |

## 第 4 層　独立したホスト、モデル、全画面の接続先

一つのホストでモデルを二つ変える方法ではなく、独立した MCP ホストを二つ使う。以下は検証候補であり、互換性の確認や TabTty への依存関係の採用は別途判断する。

| ホストの構成 | 使用方法と境界 |
| --- | --- |
| Goose + Ollama + 事前準備済みのローカルモデル | Goose の stdio 拡張経路と Ollama プロバイダーを試す。パッケージのブリッジを手動登録し、受け入れ手順に無関係な開発者、デスクトップ、ネットワークツールを無効にする。 |
| LM Studio + 事前準備済みのローカルモデルとランタイム | 独立した MCP ホストと構成、ローカル推論経路を試す。LM Studio はプロプライエタリとして扱う。アプリの利用条件と各モデルのライセンスは個別に確認する。 |

2026-11-14 に確認した一次資料は候補の各構成要素の機能を示す。TabTty との互換性は別途検証する。実装開始時に対応リビジョン、ライセンス、オフラインの前提条件を再確認する。この計画ではホスト、モデル、SDK、依存関係はインストールしない。[Goose プロバイダー](https://goose-docs.ai/docs/getting-started/providers/)、[Goose 拡張](https://goose-docs.ai/docs/getting-started/using-extensions/)、[LM Studio MCP](https://lmstudio.ai/docs/app/mcp)、[LM Studio のオフライン動作](https://lmstudio.ai/docs/app/offline)、[LM Studio 利用条件](https://lmstudio.ai/app-terms)。

ホストごとに、まずツールメッセージを観測し、検出とスクリプトによる読み取り、送信、返却のサイクルを確認する。その後、ツール対応モデルを記録し、固定した同じ自然言語の課題とフィクスチャで実行する。TabTty とツール契約の正しさは、ホストやモデルが正しい呼び出しを選んでタスク状態を推測できるかと別に検証する。

| シナリオ | 独立に確認する結果 |
| --- | --- |
| 閲覧専用の調査 | 以前の合成エラーを保持履歴から説明し、古い出力をページング・検索し、現在出力を観測する。未共有タブにアクセスできず、端末ペイロードの送信はゼロ。 |
| 通常の編集作業 | 明示的な付与後に使い捨てのリモートフィクスチャを一つ変更して保存し、テストピアで期待ダイジェストを照合して操作権を返す。変更ごとの TabTty 確認は導入せず、現在の権限外で送信しない。 |
| `top` | バージョンを固定したピアと決定的な負荷を使う。更新行、カーソル、モード、寸法を観測し、対応キーを操作し、サイズ変更して再観測したあと、画像対応モデルを必要とせず操作権を返す。更新だけですべての入力が古くなってはならない。 |
| `vim` | 使い捨ての UTF-8/日本語フィクスチャを開き、移動、複数行の挿入、保存を行い、正確なファイル内容を独立に検査する。対応マウス入力も別に試し、`vim` を終了せず退避済み通常履歴を読み、間隔付き挿入中に引き継ぐ。 |
| プロンプトと手助け | 合成のパスワードや OTP を使う。AI が効果を持たない理由を添えて操作権を返し、人間が入力して新しい付与で再開する。共有終了で後続出力を見えなくできる。配信済みの内容は外部に残る。 |
| 中断または結果不明の操作 | 冪等でないフィクスチャ操作の間にブリッジ、トランスポート、または応答を失わせる。接続先の効果を数えて権限状態を確認する。自動再試行で操作を再現せず、不明の結果を成功確認済みと報告しない。 |

接続先の OS、シェル、terminfo、`TERM`、`top`/`vim` のバージョンと設定を固定する。互換性の保証範囲は[対応端末の契約](terminal-and-encodings-ja-jp.md)に限る。未対応制御と AI の推論ミスを区別して記録する。リモートコマンドやファイルの結果にはフィクスチャの独立した判定が必要。モデルの主張や画面が変わらないことだけで判定しない。ホストとモデルごとに失敗も含めた観測件数を報告する。成功するまで再試行して失敗を隠さない。モデルの誤推論そのものは TabTty のプロトコル障害とは別に扱う。未承認の送信や再送はモデルにかかわらず中核機能の失敗。

各ホストのアプリ、推論ランタイム、重み、ブリッジ、ライセンス、必要な構成を事前に用意し、インターネットへの外向き通信を遮断してコールドスタートする。パッケージやモデルの取得、クラウドへの切り替えをせず、読み取り、付与、編集、返却、引き継ぎを一通り行う。ホストの更新、カタログ、拡張の確認を含め、試行と許可された通信を記録する。遮断された任意の確認と必須のオンライン依存関係を区別する。どちらも作業を黙って停滞させてはならない。閉域ネットワーク内で明示的に許可したサーバーでの推論を提供する場合はその構成でも実行する。操作側のホストは TabTty の PC 上に置く。

## リソース、応答性、配布条件

[リソースと検証](resources-and-validation-ja-jp.md)の Windows 基準機と 20 セッションの負荷を再利用する。20 タブすべての共有、同時に二つの連携先、上限付きの読み取りと検索と待機、間隔付き AI 送信一つを使う。単一セッション 100000 行のページング、最大グリッド、遅い読み取り側、予算の飽和、停滞ピアを含む。AI 読み取りで保持を拡張せず、受信やログ状態を複製せず、端末の更新や UI を妨げないことを示す。

負荷下で 30 分の実行ごとに、決定的なローカル操作を少なくとも 600 回予定する。初期目標は、元の入力時刻からディスパッチャー待ちを含めて、ローカル UI と入力受付で p95 が 100 ms 以下、過負荷での引き継ぎ受付で p95 が 250 ms 以下。最大値、長い停滞、後処理時間は個別に記録する。引き継ぎ受理は新規入力を即時に取り消す。250 ms 以内の接続先での効果や停滞トランスポートの後処理は別途測る。これらは技術目標。モデルの推論時間は別に報告し、ローカルの取り消しの遅さを隠さない。技術契約の API、キュー、スナップショットの全上限を境界と超過時に確認する。

実装報告にはケース ID、合格・失敗・未実施の状態、TabTty コミットとパッケージハッシュ、ブリッジ・IPC・API・プロトコルのリビジョン、Windows とハードウェア、ホスト・プロバイダー・ランタイムの版、モデル識別子と重みのダイジェストと量子化とライセンス、推論設定とプロンプト、接続先フィクスチャのダイジェストと構成、時間測定とトレースの成果物、リソースのピーク、ネットワークの方針と観測、既知の制約を含める。合成データを使い、実パスワードや非公開の端末記録を添付しない。

設計の準備完了には、Q1～Q35 の追跡可能性、具体的に観測可能な契約、固定の初期上限、開発を妨げる製品判断の未決事項がないことが必要。準備完了を報告できる。実装には明示的な承認が必要。承認後の配布には第 1～3 層とリソース条件の合格、独立した両ホストでのプロトコル互換性とオフライン操作の実証が必要。ホストとモデルのタスク結果は別途公開する。対応範囲を縮めるには明示的な仕様決定が必要。予定だけで証跡を合格扱いしない。

## 保持履歴のアーキテクチャ追加検討

アーキテクチャ Q12～Q19 は[観測から公開までのインターフェース](ai-history-observation-ja-jp.md)をテスト対象とした。以下は今後のリファクタリングの検査。実端末モデルにデータを与え、アダプターで公開、時間、スケジューリングを制御する。A05～A07、W06、リソース負荷、独立したプライベートチャネル、Windows、ホストの検査を維持する。従来の履歴アルゴリズムのテストはこのインターフェースの検査に置き換える。準備だけのアサーションで公開を検証したとは扱わない。画面、待機、入力の観測は引き続き回帰検証の要件。

| ケース | 必要な観測結果 |
| --- | --- |
| H01 通常の履歴と検索 | 準備と受付の間の編集も含め、どちらも実際の公開まで内容と権限を検証する。 |
| H02 途中の編集 | 編集して同じテキストに戻しても旧範囲を拒否する。変更のない先頭への追記と再フローのみでは有効性を保つ。 |
| H03 証明の完全な範囲 | 一致しなかった走査領域、重なり、文脈、必要な残りの範囲の変化は、一致が変わらなくても検出する。 |
| H04 未公開の後続 | 検証失敗、キャンセル、期限切れ、キュー拒否ではその試行から有効な後続を作らず、仮 ID だけを理由に既存ハンドルを除去しない。元の期限、取り消し、独立した上限による除去は適用する。 |
| H05 チェックポイントの再利用 | 元のハンドルは不変で固定期限も維持する。後続は受付成功時にだけ独自の固定期間を得る。再利用ごとに範囲と権限を再検証する。 |
| H06 結果のサイズ | エスケープとミラーを含む合計結果 1 MiB の境界と超過で、受付前に対応する走査範囲と継続を用いて再ページ分割する。公開しなかった一致を飛ばさない。 |
| H07 最小の内容 | 実装は対応する最大クラスタを収容できる。明示テキスト上限が次のクラスタ未満なら、進捗や空の成功ループなしで resource_limit を返す。 |
| H08 上限付き検証 | 大きな履歴や長い行でも最終公開の排他中に全行走査やインデックス再構築を行わない。競合では試行回数を制限し、busy を返せる。 |
| H09 所有権と互換性 | 仮登録、コピー、キュー内、キャンセルしても所有中のデータを実際の解放まで計上する。通常の切断後の保持履歴の閲覧を維持し、再接続や共有喪失の規則で無効にする。画面取得、待機、入力の位置情報の契約を維持する。 |
