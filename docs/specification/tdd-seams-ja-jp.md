# TabTty の TDD の境界

S1 は、提案後にユーザーが続行を指示したことで確認済みとなった。

## S1. 端末出力

端末出力モジュールは、受信した端末ペイロードのバイト列と受信元を受け取る。呼び出し元は結果の端末行をスナップショットとして取得できる。セッションとテストは同じインターフェースを使う。[セッションと記録の契約](session-and-recording-ja-jp.md)を参照。

この境界では、逐次デコードと可視端末状態の誤りを検出する。ネットワークのネゴシエーション、ログファイルへの書き込み、WPF 描画にはそれぞれ別の境界が必要となる。

最初のテストでは、同じ受信元から UTF-8 バイト列 `E3 81` と `82` を順に渡す。最初のチャンクの後のスナップショットは空で、次のチャンクの後には `あ` だけが含まれる。観測結果には端末のスナップショットを使い、期待値には文字リテラルを使う。

テストはセッションの呼び出し元と同じ端末出力インターフェースを使う。

現行実装は UTF-8 デコード、独立した受信元、先頭の UTF-8 シグネチャ、受信 EOF、スクロールバックを保持する固定サイズ画面に対応する。テスト対象は CR、LF、BS、HT、VT、FF、遅延折り返し、行の確定、CUP/HVP、カーソル相対移動、行消去、画面とスクロールバックの消去、表示テキストからの OSC/DCS ペイロードの除去。エスケープ解析の状態は受信元ごとに保持する。現時点では列数を Unicode スカラー値単位で数える。書記素クラスタの幅、その他の VT 操作、レガシーエンコーディング、記録は後続段階で扱う。

依存ライブラリのない .NET テスト実行ファイルを `dotnet run --project tests/TabTty.Core.Tests` で実行する。検査に失敗すると非ゼロの終了コードを返す。
