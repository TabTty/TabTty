## 所有権とライフサイクル

一つのアプリケーションコーディネーターがウィンドウ、登録、選択した vault、受付予算を所有する。一つのセッションが不変の接続スナップショット、トランスポート、受信元、端末モデル、入力キュー、記録グループを所有する。2026-11-13 に合意した Q165/Q170/Q172 に従い、一つの端末タブが同じセッションの一つ以上のペインでその所有者を表す。ペインを追加してもトランスポート、受信パイプライン、入力所有者、記録グループは増えない。同時送信は、ペイン数にかかわらず選んだタブのセッションに一度だけ送る。タブ移動でトランスポートやファイルの所有権は移らない。他の分割ビューの操作は Q199 で確認済みの[同時送信と分割ビュー](broadcast-and-split-views-ja-jp.md)に集約する。決定履歴は `../drafts/broadcast-and-split-issue.md` に記録する。接続試行ごとに一意の世代を割り当てる。再接続では世代と端末状態を新しくし、記録が有効なら新しいパートを開く。遅延した結果は元の世代を持ち、元のリソースだけを解放できる。

SSH セッションの世代は、必要に応じて開く [SFTP チャネル](file-transfer-ja-jp.md#ssh-and-sftp-channel)も所有する。端末タブを移動してもチャネルと転送作業を保持する。切断は世代を無効化してファイル作業を停止する。再接続後に転送を明示的に開くと新しい世代を使う。

セッション状態は PreparingProfile、PreparingLogs、Connecting、Authenticating（SSH のみ）、StartingTerminal（SSH のみ）、Connected、Disconnecting、Disconnected。ローカルダイアログは該当する期限の計測だけを中断する。接続先の動作は続く。キャンセルは後処理前に試行を無効にする。どの遷移も入力を再送したり暗黙に再接続したりしない。Telnet は TCP 接続後、シリアルは開く処理と構成の成功後、SSH はセッションチャネル、PTY、シェルの応答成功後に Connected になる。SSH の起動待ち中に早期の端末ペイロードも処理する。

セッションごとに一つの順序付き状態リデューサーを使う。セッションごとに OS スレッドを確保する必要はない。トランスポートのチャンク、完了した入力やエコー、サイズ変更、記録境界、EOF、閉鎖操作をリデューサーに渡し、受付時に増加するイベント序数を割り当てる。UI の描画は不変スナップショットを使う。受信処理は描画フレーム、検索、強調表示を待たない。独立したセッションを公平にスケジューリングする。

### 端末ペイロードのトランスポート所有権

[全体アーキテクチャ検討](../drafts/whole-codebase-architecture-deepening.md#2-terminal-payload-transport-ownership)の Q4-Q6 で、起動、準備済み入力の送信、確定寸法の適用、切断を目的別の完結した操作とする設計を確定した。トランスポートの I/O より先に、型付きの受信情報を非同期に処理する一つの consumer と、現在の確定寸法を取得する手段を結び付ける。トランスポートは具象 `TerminalSession` を生成せず、依存もしない。呼び出し元に読み取りと確認応答の手順を公開しない。操作名は説明用である。

C# のトランスポートはプロトコルのフレーミングと交渉、起動、寸法の通信表現、準備完了・交渉済みエコー・受信 EOF・閉鎖の通知を所有する。セッションは入力権限と順序、Rust と記録への受け渡し、ローカルエコー方針、寸法の選択を所有する。Rust は文字符号化、VT 解釈、端末状態、再フロー、記録内容を所有する。Telnet の IAC/NVT 変換はフレーミングであり、交渉済みリモートエコーは順序付き通知としてセッションのローカルエコー方針と組み合わせる。SFTP と各トランスポート固有の処理は専用操作を維持する。認証、ホスト信頼、秘密情報の既存の所有者は変更しない。

起動前にセッションと選択した記録を準備する。SSH の PTY/シェル準備完了前も正当な早期出力を受信元と受信順を保って処理し、準備完了が先行する受信処理を追い越さないようにする。起動拒否、期限切れ、キャンセルでも先に処理した出力を保持し、下記の障害規則に従って、受付済みの受信処理を元の世代で終えてから最終閉鎖を通知する。一つのトランスポートは一回の起動試行を所有し、重なる要求はその試行に合流する。失敗しても再起動しない。Telnet とシリアルの準備完了条件は維持する。

consumer には、ペイロードまたは通知を順序付きで一つずつ、再帰せずに渡す。ペイロード処理の完了には、Rust での処理、別途計上する記録受付またはその限定的な失敗、生成された応答の上限付き受付、受信メモリーの解放が必要である。その後にだけ消費済み credit を返せる。別の保留中受信キューへのコピーでは足りない。応答の送信、ディスクのフラッシュ、描画は待たない。別途受け付けた所有権なしでペイロードメモリーを callback 完了後まで保持できない。プロトコル制御は独立して進め、未完了の読み取り、通知済み credit、ペイロード、受信元メタデータ、制御作業を、小さなメッセージが大量にある場合も上限内で計上する。回復可能な背圧または既存の対象セッションの資源障害方針を使い、無制限のキューや通知しない欠落を許可しない。consumer 実行中にトランスポートのロックを保持せず、接続先 credit、鍵再交換、起動、I/O の待機中にセッションのリデューサーを占有しない。callback 自身または後続の受信処理が終わらなければ完了しない処理を callback から待たない。EOF/閉鎖の callback はライフサイクル全体の完了を待たずに順序付き通知を確定する。

送信は、セッションが許可した符号化済み入力と完全な単位の境界を受け取る。トランスポートのフレーミングと分割は、文字符号化、貼り付け間隔、ローカルエコーを引き取らない。結果は受付前の拒否、受付済みだが未送信の作業、確実に送出した完全な単位、部分的または不確かな末尾を区別する。完全な単位の結果を速やかに返してエコーと間隔制御に使う。ローカルの送出成功は接続先の受信を証明せず、不確かなデータは再送しない。寸法はセッションの現在の確定値を使い、長いダイアログ後の PTY 起動で生成時の古い値を使わない。起動中の変更を集約して通知可能な最新寸法を送り、準備完了までリデューサーを占有しない。新しい寸法による置き換え、シリアルで通信通知がないこと、失敗を区別し、通知成功を接続先の描画成功とみなさない。

受信 EOF は受信方向だけを一度確定し、許可された逆方向入力と記録パートの所有権を維持する。EOF がなければ閉鎖が最終受信の締め切りを設定する。観測の取消しでは受付済み作業を止めない。貼り付け停止または明示的な送信取消しは、世代を無効にせず、完全な単位での停止と正常な接続でのコーデック・ブラケットの終端処理に従う。接続試行のキャンセルまたは切断は試行を無効にして新しい入力と準備完了による有効化を防ぎ、一回の終了処理に合流して未送信作業を取り消す。SSH は接続先の閉鎖処理に最大2秒の猶予を設け、チャネル閉鎖またはプロトコル・トランスポート終了まで有効な出力を処理し続ける。ローカルの要求だけでは受信を締め切らず、プロトコル終了後の遅延ソケットデータを端末ペイロードにしない。

上限付きの不変な結果・状態は、操作完了、保留中の受信処理、実際の解放を区別する。発行済み I/O、バッファー、ハンドル、資源の計上は実際の完了まで所有を保ち、保留中の受信処理の所有権も解決する。遅延した callback と結果は元の世代に属し、置き換え先を有効化・変更できない。consumer が一部を適用した後に失敗した場合は通常の受け渡しを停止し、再送や一括ロールバックを約束しない。閉鎖の callback を受け付けられなくても独立した状態から障害を報告する。安全に保持できる出力を残し、記録の不完全さを示し、未処理分に消費済み credit を返さずに保留中の所有権を解決する。記録だけの障害では、有効な端末更新・応答と正常なトランスポートを維持する。候補1の記録所有者は、最終化、書き込み完了待ち、待機継続、明示的な損失許容の判断を独立して所有する。トランスポート解放は記録や保持中出力の解放を意味しない。

この設計は、合意済みの[操作全体の契約](../drafts/whole-codebase-architecture-deepening.md#complete-operation-contract-accepted-in-q6)と[検証計画](../drafts/whole-codebase-architecture-deepening.md#candidate-2-verification-plan)に従い、別途依頼される実装へ進める状態である。通常の interface を実際のセッション順序制御・Rust と制御可能な I/O・時計 adapter で検証し、独立したプロトコル検証ベクトルと実接続先・デバイスとの結合テストを維持する。今回の検討では実装、試作、実行時検証を行っていない。検証計画は今後の必須作業である。

このトランスポートの seam の内側では、合意済みの[共通 SSH チャネル契約](transports-and-authentication-ja-jp.md#ssh-チャネルの共通所有)が、端末と SFTP の状態、credit、要求応答、後処理を集約する。端末起動は、プロトコルの成功、先行する受信処理の成功、現在の未停止世代の確認を揃えて準備完了を公開する。その consumer とは独立してプロトコル処理を進める。チャネル解放は、この節のセッション・Rust・記録の所有権や端末閉鎖の猶予を変えず、上位所有者の資源も暗黙に解放しない。

## 受信と表示操作

Raw は合意済みの端末ペイロード境界で、文字のデコード前に受け付ける。SSH 端末チャネルの DATA と stderr はメッセージの受信順を保つ。Telnet では IAC、オプション、NVT 変換を先に行い、シリアルでは受信バイト列を渡す。認証、プロトコルメッセージ、SFTP チャネルのデータと stderr は端末パーサーとすべてのセッションログから除く。

SSH の各受信元は、デコーダー、VT パーサー、文字集合の状態、最後の印字可能文字、先頭の UTF-8 シグネチャの状態を所有する。Telnet とシリアルの受信元は一つ。チャンクをまたぐ不完全な単位を保持する。ローカルエコーに統合する前に完了した受信元の操作を解決する。たとえば REP はその受信元のテキストの繰り返しに解決する。埋め込まれた実行可能な C0 操作は独自の実行序数を取得し、最終的な完了済みシーケンスの表現から除外する。

受信操作は統合表示モデルに適用し、Text の記録を設定している場合は受信専用モデルにも適用する。ローカルエコーは統合モデルだけに適用する。二つのモデルでカーソル位置とテキストが異なる場合がある。編集エンジン、接続設定、合意済みサイズ変更規則は共通とする。記録の一時停止中も受信専用モデルを維持し、再開時に状態を作り直さない。統合済み文字列からローカルエコーを除く方法は許可しない。

テキストまたは制御の単位を Terminal または代替画面の Text に記録できるのは、その単位の元のバイトがすべて現在の連続した記録区間に属する場合だけ。単位の由来はチャンクをまたいで保持する。不完全な CSI 内で実行した C0 は独立した単位として対象にできる。ローカルエコーは既に完了した操作とする。Raw はバイト単位で判断するため、他形式で対象外となった文字の新しい後半部分を含められる。

## 通常画面の Text の識別とバージョン

共通の書記素契約では、各保存文字列の先頭 256 Unicode スカラー値を保持し、より長い書記素も処理し続ける。このため通常画面の Text は受信専用投影に残る編集後の文字列を記録し、省略した継続部分は含まない。代替画面の Text と Terminal はそれぞれ元の適格なスカラー値・操作の流れを受け取り、Raw は適格な元のペイロードバイトを保持する。受信元やグリッド末尾の一つが保存上限に達しても、他の投影、記録の適格性、受信元の分節状態の処理を省略しない。REP は受信元固有の保存文字列を使う。通常の上限付き省略によってセッションや記録を失敗させたり、不完全状態を設定したりしない。実際の I/O・資源障害は既存方針に従う。[共通の書記素規則](terminal-and-encodings-ja-jp.md)を参照。

保持行には安定したコンテンツアンカーと、画面上の折り返しを示すリンクを持たせる。再フローで変わるのは行の配置だけである。残っている各範囲にテキストリビジョン、記録区間の由来、明示的な空白やタブに由来するか、そのリビジョンが提出済みかを記録する。メタデータはセッションの予算に計上する。情報は内容の保持期間だけ残し、過去の全行を無制限に記録しない。

受信した LF は、離れる論理行のうち対象となる内容を、残っている折り返し部分を含めて確定する。同じ受信元から直前に受信した CR と合わせて CRLF 境界にする。同じ受信元の別操作が挟まれば組は成立せず、ローカルエコーや別の受信元との組も成立しない。チャンク境界では組が途切れない。CR 自体はカーソルを変更するだけで確定しない。VT、FF、IND、NEL、RI、カーソル位置指定、ローカル折り返し、UI のスクロールではログに LF を加えない。

セルは論理的な内容順に直列化し、折り返しを区切りなしでつなぐ。明示的に受信した空白は末尾も保持し、未使用または消去された末尾セルを除外する。追跡した TAB は、最終範囲が直列化した位置からの通常の 8 列タブ展開に等しく、残っているテキストを隠さない場合だけ出力する。それ以外では最終的な空白とテキストを出力する。無関係な空白から TAB を推定しない。クラスタは分割しない。実際に受信した空行の境界は改行を記録する。消去だけでは空の記録を作らない。

提出後、該当する内容のリビジョンと境界だけを記録済みにする。別の新しい空行で受信した新しい LF は別の出力である。変更のない確定済み内容に戻っても古い境界は再提出しない。その後に実際にテキストを編集すると未記録のリビジョンが生まれる。次回の確定では更新後の残存行を追記し、既存ファイル領域は編集しない。同じセルを書き直しても内容が変わらなければリビジョンは増えない。

容量制限またはスクロールによる除去の前に、保持範囲から完全に消える対象の未記録範囲を LF なしで直列化し、印を付けて除去する。後の確定では残りの未記録の続きと実際の境界だけを提出する。行がスクロールバックに入っただけでは記録しない。明示的な消去、削除、上書き、挿入による切り詰めでは、編集前のスナップショットを取らずに未確定内容を取り除く。ED2/ED3 の対応も含む。保持されている記録済み部分を置き換えると、後に改訂スナップショットを記録できる。シェルコマンドの復元や以前の先頭部分の書き換えは試みない。

改行を伴わないフラッシュでは、保持されている対象の変更済み内容を上から下へ処理する。合成した区切りや記録済みバージョンを追加しない。したがってカーソル位置指定によって記録が実際の表示を完全には再現しないことがある。Q150 で合意済み。ロガーはプロンプト、シェルのエスケープ、カーソル移動、ローカルの Enter をコマンドの受理として解釈しない。

## 記録状態と境界

グループの状態は Disabled、Opening、Recording、Pausing、Paused、Failed、Finalizing、Closed。形式と有効なログ設定は接続スナップショットで固定する。選択した形式のファイルを開けない場合や最初のデータを書き込めない場合は接続を失敗させる。記録開始後の書き込みに失敗するとグループ全体が Failed になり、接続を維持して明示的な再試行を受け付ける。[ログの開始条件](../drafts/receive-logging-issue.md#log-filename-template-redesign)

「同名のログがある場合」の設定は、記録パートを開くたびに適用する。どの設定でも存在しないファイルは作成する。同名ファイルがあれば「エラー」(`error`、既定) は記録開始に失敗し、「上書き」(`overwrite`) は既存の内容を置き換え、「追記」(`append`) は新しい区間の記録対象だけを末尾に書く。Text・Raw・Terminal とも通常の形式で記録し、区間の間に改行などの区切りを挿入しない。選択した全形式のファイルを開いてから、内容の消去や書き込みを始める。書き込み中のファイルが一つでもあれば、どの設定でも記録開始に失敗する。

記録の開始・再開・再試行には、毎回同じ準備処理を使う。準備処理は接続時の記録設定を使い、新しいパートのファイル名を展開して保存先を再確認する。必要な場合は連番を予約し、選択した全形式のファイルを開く。引き渡し前に失敗またはキャンセルした場合は、取得済みのハンドルを閉じ、名前の予約を解放する。書き込み担当が引き受けるのは今回のパートのファイル一式とする。パート番号と記録区間を有効にする時点は記録のライフサイクル管理が決める。準備済みのパートを受け取った後に有効化できなくなった場合は、受け取った側がそのパートを閉じる。

記録のライフサイクル管理が、すべての記録形式で入力をどの区間に含めるかと、その区間を閉じる時点を一元的に決める。一時停止と EOF または閉鎖が競合しても、対象の末尾は一度だけフラッシュする。ファイルの書き込み、受付済みデータの処理、ファイルの解放は書き込み担当が所有する。区間が終わった後も書き込み担当がファイルを保持している場合、そのファイルが必要な次のパートは、解放を確認してから有効にする。[#183](https://github.com/TabTty/TabTty/issues/183)

| 境界 | 必須の処理順 |
| --- | --- |
| 初回接続 | 選択した全形式のファイルを開いてからトランスポートを開始する。Disabled ではファイルなし。 |
| 一時停止 | リデューサーに締め切りを置き、対象の Text の末尾を LF なしでフラッシュし、受付済みの作業を終え、永続化のフラッシュを行って各パートを閉じる。新しい出力は引き続きモデルを更新する。 |
| 再開と再試行 | 新しいパート一式を開き、リデューサーのイベントで新しい区間を開始する。開始に失敗した場合は切断する。記録は新しい区間の対象データから行う。 |
| 通常画面の Text の再開 | 区間前の内容を含む保持済み論理行とその後の続きは対象外にする。混在行を終わらせる最初の受信 LF は省き、次の新規行を対象とする。 |
| 代替画面の Text の再開 | 新しく受信した完全な対象単位をすぐに受け付ける。画面のダンプは出力しない。 |
| Terminal の再開 | 独立したローカルエコーを含め、新しい完全な対象操作をすぐに受け付ける。状態復元用の接頭出力は付けない。 |
| 代替画面への切り替え | 切り替え前に通常画面の対象となる末尾を LF なしで一度だけフラッシュし、通常モデルと由来情報を退避する。 |
| 代替画面からの復帰 | 代替画面で保留中の CR を解決し、通常内容のダンプをせず復帰する。退避した通常内容は最終寸法で一度だけ再フローする。 |
| 受信 EOF | 受信元のデコーダーとパーサーを確定し、対象の Text の末尾を一度だけ確定する。受付済み作業をフラッシュするが、閉鎖または一時停止までパートとセッションの所有権を維持する。 |
| 閉鎖 | 最終受信の締め切りを設け、未送信入力をキャンセルし、一度だけ確定する。その後トランスポートとログの後処理を独立した上限で行う。 |

代替画面の Text では CRLF を判別するため、受信した CR を一つ保留する。次の隣接操作が LF なら CRLF を出力し、それ以外ならその操作の前に CR を LF として出力する。区間、画面、EOF の境界では区間を混ぜずに解決する。印字可能なテキストと TAB を記録し、LF を維持して他の非印字制御を省く。

Terminal では完了した表示操作を UTF-8 テキストと正規化した 7 ビット VT 制御に符号化する。別名は対応する形式に正規化し、完了した表示操作の全パラメーターを含め、パーサー状態に依存する REP は解決済みテキストに変換する。表示に影響するカーソル、編集、モード、SGR、画面変更を含める。問い合わせと応答、BEL、外部 OSC 効果、未対応または不完全な断片、トランスポートコマンド、診断は除く。セルが変わらない表示操作も記録する。受信元の CR と LF はそのまま保持し、ローカルエコーの Enter は CRLF にする。ローカル折り返し、サイズ変更、再生時の初期設定を付加しない。

## 書き込みと障害

各パートには一つの所有者を設けて順番に書き込む。バッファーを上限付きの I/O チャンクに分けても、論理レコードは分けない。キュー内、ステージング済み、転送中、失敗したが保持中のバッファーを、実際に所有権が終わるまで計上する。受付は永続化を保証しない。グループ上限 8 MiB、約 1 秒のバッチ化目標、進捗なし 10 秒で失敗、閉鎖時 5 秒での選択を維持する。

失敗時は新規受付を停止し、受付済みの先頭部分を可能な限り完了する。途中まで書き込んだバッチを同じファイルに再送したり、失敗した I/O がどこまで保存されたかを推定したりしない。明示的な再試行では、テンプレートの展開結果が前回と同じファイル名でも、新しい所有者が新しいパートを開く。遅延完了は新しい所有者に影響できない。古い I/O が後処理の許容枠を使っていれば、再開や再試行は待つか、失敗を表示する。損失を了承して閉じる操作は未発行作業を放棄し、発行済み作業のキャンセルを要求する。バッファーは実際の完了時だけ解放する。閉鎖時に待ち続ける選択は、停滞時の自動放棄より優先する。

[全体アーキテクチャ検討](../drafts/whole-codebase-architecture-deepening.md#1-session-log-finalization-and-waiting-ownership)の Q1-Q3 で、C# の recording module が一時停止、受信完了、切断完了、明示的な閉鎖と、既存の再開・再試行を目的別の完結した操作として所有する設計を確定した。Rust は記録内容と端末側の締め切りを所有する。Closure module は5秒後の選択を表示し、同じ recording 所有者へ判断を伝える。呼び出し元は上限付きの結果・状態と読み取り専用の実解放の観測を受け取り、操作の lease や後片付けの手順を持たない。検討記録のメソッド名は説明用であり、型名の確定ではない。

明示的な閉鎖を受け付けた時点で、長い書き込み完了待ちや選択画面の回答待ちより先に、未完了の記録を保護する。「待機を続ける」はその保護を維持する。ログ損失の選択は未完了の記録がある場合だけ表示し、その後も明示的に未保存のまま閉じる操作を利用可能にする。保存完了、不完全な記録、後処理の引受け、実際の解放を区別し、トランスポートだけが未完了の場合と混同しない。重なった要求は受付済み作業と一度だけの内容確定を共有し、観測の取消しでも所有処理は継続する。EOF は受信方向の完了とパート・セッション所有の保持を維持する。既存の資源受付と後処理引受けの所有者は変更しない。

この設計は、同検討記録の操作全体の検証表を含めて、別途依頼される実装へ進める状態である。通常の interface を、実際の Rust の処理と制御可能なファイル・時計 adapter で検証し、実ファイル・WPF・トランスポートの結合テストも保持する。今回の検討では新たな実行時テストを行っておらず、実装や試作は承認していない。

複数形式のパートを開く処理はファイルシステムのトランザクションではない。一部のファイルを開けなかった場合、開けたハンドルを閉じて失敗を報告し、作成した空ファイルは残す。トランスポートは開始せず、一部の形式だけを暗黙に記録しない。

### 記録パートに使う連番の割り当て

テンプレートに `<serial:start,width>` があれば、同名時の設定にかかわらず新しい連番を割り当てる。確認済みの記録先で、新しい名前の生成と既存名の照合に同じログファイル名テンプレートを使う。既存名の数字を数値に戻し、このテンプレートで再び書式化したときに元の数字列と一致するものを連番に数える。名前の残りは Windows のファイル名比較に従い、今回は1形式だけを開く場合も3形式すべての接尾辞を調べる。設定した開始値と、該当する最大の連番に1を加えた値のうち、大きい方から割り当てる。パートのベース名を予約し、競合するファイルの有無を再確認してから、その予約で選択した全形式を開く。同時に開始した別々のパートには、記録形式が重ならない場合も別々のベース名を割り当てる。

最初のフォルダー走査と予約後の再確認では、列挙から制御が戻るたびに、また名前の予約やファイルを開く直前にも、キャンセルと準備期限の満了を確認する。どちらかを確認したら探索を打ち切り、そのパートでは後片付けだけを行う。フォルダーの読み取りが応答待ちの間も、画面にはキャンセルを表示できる。準備枠は、実際の処理と後片付けが終わった時点で解放する。

| 受け入れケース | 期待する結果 |
| --- | --- |
| 上書き設定で Raw と Text を選び、既存の Text ファイルを別の書き手が開いた状態で初回接続を試す。別のセッションの記録再開時にも同じ条件を作る。 | どちらも取得済みのハンドルを閉じ、既存の Raw ファイルの内容を保つ。初回はトランスポートを開始せず、再開に失敗した場合は接続済みのセッションを切断する。 |
| `Run_0007.raw.tttylog` と `Run_00042.log` があるフォルダーで、`Run_<serial:0,4>` を使って Text 記録を始める。次に `Run_9999.term.tttylog` を加えて別のパートを始める。 | 作成するファイルは順に `Run_0008.log` と `Run_10000.log`。このテンプレートで42は `0042` になるため、`00042` は連番に数えない。既存ファイルの内容は保たれる。 |
| 空のフォルダーで同じテンプレートを使い、Raw のみの記録と Text のみの記録を同時に始める。 | それぞれに別のベース名を割り当てる。一つのパートで Raw と Text を選んだ場合は、両ファイルに同じベース名を使う。 |
| 初回の記録準備で、未確認の項目が残るフォルダーの読み取り中にキャンセルする。読み取りを保留してから応答を返す。名前を予約した後の再確認でも同じ操作を行う。 | 応答待ちの間は準備枠を保持する。制御が戻ったら次の項目を読まずに探索を終え、ログを開かない。後片付けで取得済みの予約と準備枠を解放する。既存ログの内容を保ち、キャンセルした接続のトランスポートは開始しない。 |

## クリップボード貼り付け

クリップボードに本文を要求する前に、送信先が単一セッションか同時送信かを確定する。処理中の貼り付けは、対象範囲が変わっても別の送信先へ転送しない。単一セッション向けに取得した本文または確認の応答が届いた時点で同時送信が有効なら、その貼り付けを破棄する。

2026-11-18 に明確化した全体アーキテクチャ Q24-Q27 は、当初 Q26 の共有予算による所有と、維持する既定 512 MiB の設定可能な原文上限・1 KiB 超の確認を組み合わせる。旧 1 MiB の符号化済みペイロード上限と、Q28-Q29 の独立した合計予算案は置き換える。これは仕様の決定であり、候補6の最終 Q23 確認は 2026-11-18 に完了した。この統合によって実装や実行時検証を承認しない。

操作開始時に、不変の Unicode クリップボード本文一つとアプリ全体の設定 `maxPasteTextBytes` を確定し、実際の原文保存領域を送信先間で共有する。既定は1回あたり 512 MiB（536,870,912 バイト）。送信先の文字コードへの変換前に、選択した実際の本文を UTF-16 コード単位あたり2バイトで数える。元の CR/LF を含め、終端 NUL、割り当ての余白、メタデータ、他のクリップボード形式は除く。補助平面のスカラー値は2コード単位を使う。長さ・容量の算術を検査する。確定した上限ちょうどなら通常の検証・資源受付へ進み、超過は全文を拒否して正規化や切り詰めをしない。符号化後の別上限は設けない。保存設定が変わっても、取得・プレビュー・送信中の操作は開始時の上限を保持する。[アプリケーション設定](persistence-and-windows-ja-jp.md)を参照。

不正な Unicode と、TAB/CR/LF 以外のリテラル C0、DEL、C1 制御文字を、置換や削除なしで拒否する。これは Unicode の検査であり、正当な送信先文字コードのバイトや生成した符号化制御を除去する規則ではない。ペイロードや開始マーカーの送信前に全文、厳密な符号化、エンコーダーの終端、必要なフレーミングを検証する。末尾近くの失敗でも未開始の貼り付け全体を拒否する。後のクリップボード変更で承認済み本文を置き換えない。Enter の追加、改行の正規化、端末表示用の先頭 256 スカラー値を送信ペイロードへ流用する処理は行わない。

他の検証を満たし確定上限内にある本文について、キーボードとコンテキストメニューの貼り付けは、末尾の改行も含め CR または LF があるか、元の本文が 1,024 バイトを超える場合に一度だけ確認する。改行なしで 1,024 バイトちょうどなら直接送信する。両条件を満たしてもダイアログは一つで、原文上限ちょうどという理由だけでは確認しない。上限超過は承認するのではなく拒否する。同じ送信／キャンセル操作、既定のキャンセル、読み取り専用の全文プレビュー、書記素数・行数、末尾改行の表示、識別可能な制御文字、間隔フィールドを使い、永続的な確認省略は設けない。ブラケットペーストでも確認を省略しない。同時送信では、この一つのダイアログに固定した送信先一覧を加える。プレビューは何も送信せず、クリップボードを変更しない。

確認画面とそのアクセシビリティ用テキストでは、TAB、CR、LF、書字方向を上書きする文字を含む Unicode 書式制御文字、通常のスペース以外の空白を、コードポイントが読める記号で示す。原文に記号の開始文字が含まれる場合もエスケープし、実際の制御文字と区別できるようにする。CR、LF、CRLF ごとに表示上で一度改行し、CRLF は同じページに表示する。同時送信では固定した各送信先について、接続方式と宛先（SSH はアカウントを含む）に続けてタブ名を表示する。両方の値で制御文字と記号の開始文字をエスケープする。送信先のチェックボックスではツールチップとアクセシビリティ用の名前にも同じ宛先を示す。送信には取得時の原文と確定済みの送信先を使う。改行や書字方向の不可視文字がレビューに及ぼす影響は [Unicode UTS #55 §1.2](https://www.unicode.org/reports/tr55/) を参照。

上限付きの読み取り専用ページ・範囲から全文にアクセスできるようにする。巨大な1行や1書記素でも、表示コントロールへの全文コピーを必須にしない。表示上の継続断片はサロゲートペアを分割しないスカラー境界で区切り、元の範囲と対応させる。本文の挿入や省略はせず、表示断片を送信ペイロードにしない。全文解析は上限付きの継続状態とオフセットを使い、大きな記述子の配列や書記素全体の追加バッファーを要求しない。解析と事前検査は上限付きの作業区間で実行権を譲り、キャンセル可能にする。クリップボード提供元のデータ生成は即時キャンセルを保証せず、遅いリソースを実解放まで所有する。取消しのたびに新たな未管理ワーカーを作らない。

文字間と追加行間の遅延は、整数 0～10000 ms を受け付ける。入力書記素と改行単位の完了時に間隔を適用し、CRLF は分割しない一つの改行とする。次のペイロード単位の前に文字間遅延を待ち、直前が改行なら行間遅延も加える。先頭・末尾の待機、内部チャンク末尾や生成したコーデック／ブラケットバイトによる待機、表示折り返しによる行間イベントを追加しない。追加待ち時間の見積もりは転送・接続先処理の時間と分けて示し、間隔待機は速やかにキャンセル可能にする。

共通の遅延値と「この遅延設定を保持する」チェックはアプリの起動中だけ保持し、初期状態は 0/0 ms・未チェック。保持をチェックした送信の受理で共通の値と状態を更新し、未チェックで受理した送信では編集値を今回だけ使って以前の記憶値を消去する。キャンセルや古い回答では変更しない。サイズで確認する改行なしの本文にも同じ遷移を使い、行間イベントは生じない。小さい直接貼り付けは、保持が有効なら記憶した文字間遅延、無効ならゼロを使い、記憶値を変更しない。本文サイズ設定は永続化するが、これらの遅延は永続化しない。

既存のアプリ全体 4 GiB の[計上枠](resources-and-validation-ja-jp.md)に、端末状態と、貼り付けが所有する原文、共通解析・索引、取得、プレビュー、送信先メタデータ、実際の個別作業・コピーを、割り当ての重複期間も含めて計上する。セッションごとの端末状態 2 GiB は維持する。実際に共有する保存領域は一度、ネイティブ／マネージド間のコピーや遅延リソースを含む実コピーはそれぞれ計上する。独立した貼り付けプールや、プロセス実メモリ全体の保証ではない。

各送信先の個別変換、事前検査、キュー／送信中バッファー、結果メタデータは、既存の 2 MiB・同時 256 単位の入力作業枠を通常入力と共有し、コーデック／ブラケットの終端容量の予約も既存の扱いを維持する。共有原文・共通プランの全体を送信先ごとの 2 MiB に再計上しない。アプリ側の予約は実解放まで所有権を伴い、計上所有者の変更で抜けや二重計上を生じさせない。最初の送信確定前に、全送信先の残りの送信・停止・終端処理の上限付きピーク容量を予約する。確認しても容量や符号化の成功は保証されず、事前検査・予約の失敗ではペイロードも開始マーカーも送らない。既存の容量規則と元の期限に従って新規作業を拒否・延期し、新しい待機方式は加えない。複数セッションのロックで循環待ちにならないよう部分予約を解放・再試行する。容量を空けるために保持済み端末出力を捨てたり、保存した保持行数を減らしたり、無関係なセッションを閉じたりしない。既存の送信・終端予約は維持し、後の作業へ譲らない。送信先ごとの符号化済み全文コピー、自動スプール、アプリ全体の貼り付けの一律直列化、空きメモリ割合、独立した合計設定は追加しない。本文と遅延・取消済みのリソースは実解放まで計上する。結果のローカルエコー状態と後続の端末変更には、引き続き既存の端末状態受付を適用する。

## 入力順と将来の呼び出し元

通常のキー入力と IME の確定文字を含む確定済みテキストは、端末セッションが符号化して順に送出し、送出を確認できた完全な単位を設定に従ってローカルエコーする。手入力、同時送信、AI 操作はこの処理を共用する。同時送信は対象の確定と再確認を担い、AI 操作は送出時点で操作許可と画面の観測情報の有効性を確認する。マウス操作とペーシング付き貼り付けは、それぞれ既存の状態と有効期間を維持する。

キーを直接渡す場合も、事前に準備した入力を渡す場合も、同じ送信内容とエコーの規則を使う。テンキー Enter は数値モードでプロファイル指定の CR、LF、CRLF のいずれかを送り、エコーがオンなら CRLF を表示する。アプリケーションキーパッドモードでは `ESC O M` を送り、エコーは省略する。モードはセッションで実際に送信する順番が来た時点で判定する。Enter、Backspace、Tab の対応付けと、ネイティブ側の特殊キーの符号化は維持する。[#182](https://github.com/TabTty/TabTty/issues/182)

通常入力と同時送信では、各送信先のセッションに順番が来た時点の端末モードでキーを符号化する。たとえば［↑］が先行入力を待つ間にその端末のカーソルキーモードが変われば、［↑］には新しいモードを使う。セッションが通信処理に渡したバイト列は、書き込みが完了するまで維持する。同じ時点で、そのキーまたは確定済みテキストに適用するローカルエコーの設定も確定する。たとえばエコーがオンのときに `AB` を渡し、送信結果を待つ間にオフにしても、`A` までの送出が確定した場合は `A` だけを1回表示する。次の入力には、その入力を通信処理に渡す時点の設定を使う。

アプリの通常のキー入力は、送出と必要なローカルエコーの完了を待つ。画面は通常の描画時に取得する。その取得に失敗した場合は表示の失敗として扱い、確定済みの送信結果を変えたり入力を再送したりしない。送信後の画面を行の一覧として返す既存の公開メソッドは、引き続き、設定に従ったローカルエコーを反映した画面を返す。

検証では、アプリからキーを1回入力し、送出が1回で、送信処理自体では画面スナップショットを書き出さないことを確かめる。別のケースで送出確定後の画面取得に必要な容量を不足させ、送信は成功し、後続の画面取得だけが失敗を返し、接続先の受信は1回であることを確認する。容量がある場合は、既存の公開メソッドから送信後の画面を取得できることも確認する。

入力単位全体を複製したエンコーダー状態で事前検査する。符号化できない入力で実状態を変えたり先頭部分を送ったりしない。ユーザー入力、貼り付け、端末応答、将来の呼び出し元を一つの送信所有者で直列化する。トランスポート制御パケットは別扱いとする。貼り付け全体を事前検査しても、エコーは貼り付けの完了まで待たない。確実に送出した完全なスカラー値・不可分なコーデック単位、または対応付け済みキー操作をその都度エコーする。送信チャンクが書記素の途中で終わっても、間隔・個数の単位である書記素は完了扱いにしない。不完全な符号化文字はエコーしない。トランスポートが途中で失敗すると、接続先での受信範囲が不明な場合がある。再送はしない。未送信単位はローカルエコーしない。Enter、BS、TAB、移動のエコーはセッションで合意済みの最小限の対応付けに従う。

間隔付き貼り付けは取得済みの不変本文を使い、最初の送信前の順序付き準備遷移で、現在の送信先エンコーダー・設定・権限・ブラケットモードを検証する。開始前に残りの上限付き作業とコーデック終端・終了マーカー用の容量を予約する。通常の成功した送信は、256 スカラー値を超える書記素も含め、入力の全スカラー値を上限付きチャンクで送る。明示的な停止は、短い書記素でも長い書記素でも、その途中の次の完全なスカラー値または必要なより大きい不可分のコーデック・制御単位で効かせ、CRLF は分割しない。最後の書記素の先頭部分だけが送信済みになることはあるが、符号化文字や制御列を意図的に途中切断しない。接続が正常なら必要なコーデック終端と開始済みブラケットの終了マーカー一つを LF なしで送る。自動端末応答はその終端の後にキューへ入れる。以後の接続先のモード変更は次回の貼り付けに適用する。貼り付けが送信を所有している間は追加の対話端末入力を拒否する。キャンセルと切断は使える。

Rust の送信エンコーダーは、現在の貼り付けチャンクについて、入力単位と符号化済みバイトの対応位置および必要なコーデックの終端を返す。貼り付け停止ではトランスポートのフレーミングを考慮してその位置を使う。接続が正常な状態で JIS の `日本語` の `日` の途中で停止したら、`日` を送り終え、ASCII に戻し、開いているブラケットを閉じる。エコーは有効な場合に `日` だけを表示する。通常入力の部分送信でも同じ規則で、送出が確定した完全な単位だけをエコーする。最終単位を完了するための JIS リセット、Alt の接頭辞、Telnet の IAC エスケープも進捗計算に含める。フレーミング専用のバイトはエコー用の文字を増やさない。入力全体の事前検査を維持し、境界情報の保存は現在のチャンクまたは通常入力単位に限る。大きな貼り付けのメモリ使用量のピークと短い通常入力の割り当て量を、それぞれ同一入力で変更前後に測る。[#186](https://github.com/TabTty/TabTty/issues/186)、[#187](https://github.com/TabTty/TabTty/issues/187)

ライフサイクル、送信、受信の操作は WPF ビューから独立して公開する。将来の観測者が端末やロガーに渡すデータを消費したり、描画フレームに依存したりしないようにする。認証情報参照と交換可能な命名方針を維持する。現段階でマクロランタイム、将来を見越した API、再生用ストアは追加しない。

## 承認後に必要な検証

代表的な UTF-8/CP932/JIS と制御シーケンスをすべてのバイト境界で分割して試す。stderr とローカルエコーの混在、チャンクをまたぐ CRLF、各単位の途中の記録締め切りも含める。表示幅の端での LF、行の除去を伴う再フロー、記録済み行の編集、カスタム TAB 停止位置、代替画面への遷移、ファイルを開いている間の一時停止、EOF 後の CLOSE、部分書き込み、古い完了、停止と鍵再交換と切断の競合、受信中のタブ移動を含める。結果のバイト列とイベント順を検査する。

従来の 1 MiB を超える有効な入力、原文上限と 1 KiB の確認境界、プレビュー中の設定変更、巨大な行・書記素のプレビューと正確な送信、短い／長い書記素内の停止も含める。保存上の省略と Raw・Terminal・代替 Text・送信本文の独立、貼り付け保存領域の共有と実コピー、アプリ全体・送信先の容量不足、予約済み終端処理、実解放の遅延を検証する。同時送信の全文事前検査では、最後の送信先の失敗や期限切れで開始マーカーも送らないことを確認する。この時点では実装テストは未実施。
