# ユーザー通知ポリシー

Windows アプリでユーザーに通知するときの仕様。通知マトリクスには移行前（`f37d1c4`）の34項目を収録している。[English](notification-policy.md)・[移行前の通知マトリクス](../drafts/notification-inventory-ja-jp.md)

## 通知方法の選び方

| ユーザーに必要なこと | 表示方法 | 表示を終える条件・代表例 |
|---|---|---|
| 現在の状態や進捗を確認する | 対象画面のステータスバー左側、または対象メインウィンドウのステータスバー右側 | 状態が続く間は表示する。接続、ログ記録、貼り付けの進捗、AI操作権は個別に更新する。端末タブでは全分割ペインが下部の固定1行（30 DIP）を共有する。 |
| 継続中の処理に好きなタイミングで介入する | 操作ボタン付きフローティング表示 | 操作できる間は表示する。AIの「引き継ぐ」「共有終了」、マクロの「一時停止」「停止」など。 |
| 普段と違う操作になった理由や戻し方を知る | 時限ありのフローティング表示 | ユーザーに見える時点から表示する。マウス操作が接続先に切り替わった場合は、従来どおり6秒間、戻し方を案内する。先に操作先が戻れば消す。 |
| すでに起きた重要な出来事を見落とさずに知る | 特定の画面では **OK** 付きのフローティング表示。ウィンドウやアプリ全体ではバーの右側から開ける報告 | 確認するまで残す。画面に属する例は、記録開始後のログ書き込み失敗、個々の端末への入力がどこまで届いたか不明な場合、前回と異なる宛先への再接続成功。OKは既読にする操作。復旧・再試行には別の明示操作を使う。 |
| 次の処理を決めるために回答する | 判断・入力用ダイアログ | 対象を明示し、その処理が選択・入力を待つ。SSHホスト鍵の承認、AI操作権の付与、貼り付け確認、SFTPの上書き、マクロからの質問など。既存のキャンセルと安全な既定選択を維持する。 |

通常の成功は「vault：解除済み」のように結果の状態で伝える。アーカイブ先のパスなど、後で必要な情報は参照できるようにする。検索、入力欄の検証、ユーザーが開く詳細画面、ファイル別の転送結果は各作業の一部として扱う。タブ見出しの印は対象を見つける手掛かりになる。表示先がまだない起動エラーや、画面を閉じる前に結果を伝える必要がある場合は、報告用ダイアログを使える。SFTPの終了時には未確定の件数・パス・全件の詳細を保持する。[ファイル操作の終了時報告](file-operations-ja-jp.md)

## ステータスバーの表示範囲

左右の配置は、何の状態を伝えるかで決める。他の項目が更新されても、それぞれの状態を読み取れるようにする。[実装計画 #247](https://github.com/TabTty/TabTty/issues/247)

| 状態が該当する範囲 | 配置 | 表示する情報 |
| --- | --- | --- |
| 個々のタブ、ペイン、編集画面、そこで行う操作 | 対象画面のバーの左側 | 接続と入力の状態、ローカルエコー、マウス操作先、AI共有と操作権、強調ルールの警告、マクロの状態と結果、ログ記録の状態とパート番号。管理画面自身の状態と、時間がかかるファイル操作の進捗も左側に表示する。 |
| ウィンドウ全体、または複数のウィンドウ | 対象のメインウィンドウに1か所ずつ、バーの右側 | 同時送信の範囲、送信可能数と選択数、次回開始時の範囲、送信先が未選択または全件送信不可、同時送信の後始末。このウィンドウの同時送信はそのウィンドウ、全ウィンドウの同時送信は各参加ウィンドウに表示する。 |
| アプリで選択中の保管庫 | 各メインウィンドウに1か所ずつ、バーの右側に常時表示 | 選択中の保管庫を解除している間は「vault：解除済み」、未初期化を含むそれ以外の状態は「vault：未解除」と示す。起動時、ロック解除・再ロック時、保管庫の切り替え時に共有状態を反映する。表示のための初期化やパスワード入力は不要。個別に開いた別の保管庫ファイルの状態は、その編集画面に属する。 |

ウィンドウの右欄は、端末、管理・設定画面、タブのない画面のいずれでも表示する。タブの切り替え・移動や分割後も、ウィンドウやアプリ全体の各状態を対象ウィンドウに1回ずつ表示する。フローティング表示は特定の対象画面に属する通知に限る。ウィンドウやアプリ全体の状態と結果は、端末が表示されていないメインウィンドウでも右欄から確認できる。

貼り付け進捗は操作元のタブに属する。同時貼り付けの送信先ごとの進捗も、操作元のタブの左側に表示する。右側には同時送信モードと送信可能数・選択数を表示し続ける。接続先へのマウス操作の中止を含む同時送信の結果は、その同時送信が及ぶウィンドウの右欄で示す。送信に失敗した場合や到達範囲が不確かな場合は、どの送信先にどこまで届いたと分かっているかを報告に残す。同時送信を終了した後も、既読にするまで右欄から確認できる。いずれかのウィンドウで既読にすると各表示先に反映される。報告の到着時には入力フォーカスとアクティブなタブを保つ。

メニューからの操作では、開始時に対象のタブ、ファイル、画面、ウィンドウまたはアプリの状態を特定する。処理中にタブを切り替えても、その対象に合わせて進捗と結果を表示する。たとえばファイルの保存はその編集画面に属する。メインメニューで選択中の保管庫をアーカイブ・復元した場合は、右欄から結果と該当するアーカイブ先を確認できるようにする。個別の保管庫エディターで開いたファイルの処理結果は、その編集画面に表示する。上書きの判断やマスターパスワードの入力などは、該当するダイアログで回答を待つ。

タブの移動に失敗した場合は、移動元のタブに報告する。タブグループの分割・削除に失敗した場合は、配置を変更しようとしたウィンドウの右欄に報告する。

## 右上の積み上げ

- フローティング表示は、対象画面のコンテンツ領域の右上に同じ形式で並べる。端末タブでは、接続前のマクロを含めてタブごとに一組とし、分割ペイン間で共有する。タブを別ウィンドウに移したときは表示も追従する。編集画面と転送ウィンドウはそれぞれ自分の通知を持つ。
- **古いものを上に置き、新しいものは一番下に追加する。** 同じ処理の進捗や同じ障害の再報告は元の位置で更新する。途中の1件が消えたら、下の項目を相対順のまま詰める。重要度や更新時刻で並べ替えない。
- 項目を互いに重ねず、タブ、分割境界、検索欄の操作領域も確保する。表示・更新・消去で端末の行列数、描画領域、スクロール位置、入力フォーカスを変えない。案内文の上ではポインター入力が端末に届き、ボタンはキーボードとUI Automationからも操作できる。英語・日本語とライト・ダークの両方に対応する。
- **すべての本文が収まらないとき**は、AIの「引き継ぐ」「共有終了」やマクロの「停止」を直接押せる場所に保つ。他の通知は件数付きで展開し、同じ時系列順にスクロールして全件を読めるようにする。未確認の重要通知を押し出して捨てない。時限案内は本文が見えている間だけ時間を数える。
- ボタンは、その通知を出したタブ・接続試行・マクロ実行・ファイル操作に結び付ける。対象が終わった操作は取り除く。確認前に障害が復旧した場合は、元の通知に復旧結果を追記し、ステータスバーには現在の状態を示す。

## 非アクティブなタブ

別の分割グループに見えていても、現在ユーザーが操作していないタブは非アクティブとして扱う。操作中のタブ内で入力欄やボタンにフォーカスを移しても、そのタブはアクティブのままである。追加通知の要否は発生時に判定し、タブ切り替えや移動では未確認通知を引き継ぐ。同じ出来事を再通知しない。背後のウィンドウで起きた出来事も、手前での入力を妨げない。

| 非アクティブなタブで起きたこと | その場でどう知らせるか | ユーザーが操作したとき |
|---|---|---|
| 通常の進捗、任意の操作、時限案内 | タブの状態を更新する。時限案内はタブがアクティブになり、まだ意味がある場合に表示する。 | タブを選ぶと現在の状態と操作が見える。 |
| 既読確認を要する重要な事後報告 | タブに未確認の印を付け、**そのタブが属するウィンドウに、フォーカスを奪わないモードレス通知ウィンドウも表示する。** タブ名と内容、「対象タブを表示」「OK」を示す。タブ側にも同じフローティング表示を保持する。 | 「対象タブを表示」で発生元へ移る。どちらでOKを押しても同じ1件が既読になり、当該項目とその未確認印が消える。障害が続く間はバーの状態が残る。 |
| ユーザーの判断・入力が必要 | タブを選び直すのを待たず、対象タブ・宛先または操作を明示した回答用ダイアログで知らせる。タブにも回答待ちを示す。 | ユーザーが意図してダイアログにフォーカスを移すと回答できる。キャンセルは元の操作の規則に従う。タブから開いた場合も同じ質問に戻る。 |

通知の到着だけでタブやウィンドウをアクティブにせず、別の端末に向けた文字や Enter を回答として取り込まない。同じウィンドウの背後タブから複数の事後報告が来た場合は、1つの通知ウィンドウに古い順でまとめられる。各事象の既読状態・各質問の回答は表示先の間で一つに保つ。回答・キャンセル・失効済みの要求を、タブ移動や再接続後に再適用しない。事後報告の表示中も端末入力・同時送信は続く。回答待ちで止めるのは、元の操作の規則が許す範囲で、その回答に依存する処理に限る。

## 新しい通知を追加するには

最小化されたウィンドウに属する判断要求では、ウィンドウの最小化を保ち、ダイアログをタスクバーから開けるようにする。重要な出来事の通知でユーザーが **タブを表示** を選んだときは、そのウィンドウを復元して対象タブを選択する。

最初に通知の対象を決める。端末に属する通知は、その接続の `TerminalTab` に渡す。ペイン分割やウィンドウ間のタブ移動も同じタブが引き受ける。管理画面では操作を始めた `FormView` を使う。ウィンドウまたはアプリ全体に属する非同期メニュー操作では、開始時に `WindowStatusReports.Capture` に対象ウィンドウまたはアプリ全体を指定して報告先を取得する。

| 通知すること | 共通フレームワークの使い方 |
|---|---|
| 状態・進捗 | 実行中の処理から現在の状態を読み、ステータスバーを更新する。管理画面で処理時間に応じて進捗を出す場合は `FormView.BeginProgress(resourceKey)` を呼び、処理終了時に返り値を破棄する。 |
| 普段と異なる操作の案内 | `Notices.ShowHint(key, 表示文, 表示時間)` を使う。操作モードが先に戻ったら、そのキーを `Remove` する。表示時間の計測はスタックが受け持つ。 |
| 継続中の処理への介入 | `Notices.ShowContent(key, content, keepVisible: true, compactActions: buttons)` を使う。同じキーで更新し、処理が終わったら `Remove(key)` する。ボタンは対象の接続や実行に結び付ける。詳しい本文が収まらない場合に備え、コンパクト表示用の操作ボタンを渡せる。 |
| 特定の画面で発生し、確認が必要な出来事 | `Reports.Report(incidentKey, 表示文)` を使う。キーは「接続世代とログのパート番号」のように一つの出来事を識別する。確認前に復旧したら `Reports.UpdateIfPending` で元の報告を更新する。フローティング表示、別ウィンドウ、タブの未確認表示は連動する。 |
| ウィンドウまたはアプリ全体の処理結果 | `WindowStatusReports` に概要と詳細を渡す。ユーザーは右欄の概要または **［表示］→［操作結果］** から詳細を開いてコピーできる。1 件の報告を確認すると、すべての対象ウィンドウでその報告が既読になる。[共有の操作結果](../../src/TabTty.App/WindowStatusReports.cs) |
| 判断・入力の要求 | 操作に応じたダイアログを作り、`TerminalTab.PresentDecisionAsync(dialog, token)` で回答を待つ。キャンセルを対象操作の寿命に結び付け、安全な既定値を設定し、回答を使う直前に対象を確認する。保管庫のロック解除を複数タブが待つ場合は `TabDecision` が各タブを追跡する。 |

たとえばログの書き込みに失敗したら、記録状態を「停止」に更新し、そのパートについて1件の報告を出す。再試行に成功したら、未確認の報告には再開後のパート番号を表示する。ユーザーがどちらの表示で **OK** を押しても、その報告は両方から消える。新しい機能もこの仕組みを使えば、ウィンドウのフォーカスや通知の配置・重複を個別に管理せずに済む。[NoticeStack](../../src/TabTty.App/NoticeStack.cs)・[ViewNotifications](../../src/TabTty.App/ViewNotifications.cs)・[タブの判断要求](../../src/TabTty.App/TerminalTab.Decisions.cs)・[FormView](../../src/TabTty.App/FormView.cs)

## 受け入れ確認

再接続では通知中の入力継続とウィンドウ間のタブ移動を確認する。フローティング表示では、複数の通知と検索欄を同時に出したときの操作と端末サイズを確認する。[再接続と入力](../../tests/TabTty.App.Tests/BroadcastAndSplitViews.cs)・[AIと検索](../../tests/TabTty.App.Tests/AiCollaborationTests.cs)

1. 同じタブでAI共有開始、マウス操作先の切り替え、記録開始後のログ書き込み失敗を順に発生させる。上から「AI操作」「マウス案内」「ログ警告」と並ぶ。同じ記録障害の再報告で項目は増えず、案内が消えたら警告が詰まる。OK後も「記録停止」とAI操作は残る。
2. 狭い分割表示、開いた検索欄、長い日本語表示で、複数の通知をあふれさせる。両テーマとキーボード操作で、古い報告も読め、AIの引き継ぎを直接押せること、端末の行列数・スクロール位置・選択・マウス操作を妨げないことを確かめる。
3. タブAに入力中、非アクティブなタブBで記録を失敗させる。通知窓がBを明示し、フォーカスはAに残る。Bを別ウィンドウに移してどちらかでOKを押すと、Bの該当する通知だけが消える。ホスト鍵確認やマクロの質問でも、Aに打った Enter がBの回答にならないことを確かめる。
4. 同じ宛先・異なる宛先へ順に再接続し、変更した場合だけ事後報告が出ること、表示中も端末入力・同時送信を継続できることを確かめる。一方、信頼確認や上書きは回答を待つ。事後報告のOKでは再試行が始まらない。
5. メインウィンドウを2つ開き、一方を分割し、もう一方で管理画面を開く。起動時、どちらかのウィンドウでの初回利用による保管庫の解除、再ロック、選択中の保管庫の変更のそれぞれで、両ウィンドウの右側に現在の状態が1回ずつ表示される。管理画面自身の処理が進行中ならその左側に進捗も表示される。端末が表示されていないウィンドウでも右欄を確認できる。
6. 1つの端末タブでAI共有、マウス追跡、マクロ実行、強調ルールの停止、記録を順に発生させる。各状態がそのタブの左側に表示され、タブを移すと追従する。ウィンドウ内、続いて全ウィンドウの同時送信を開始する。範囲と対象数は各参加ウィンドウの右側に1回ずつ、同時貼り付けの送信先ごとの進捗は操作元タブの左側にだけ表示される。
7. 同時送信中に接続先へのマウス操作を中止し、右欄で結果を確認する。送信失敗後にモードを終了し、右欄から各送信先の結果を読めること、1回の既読操作が各表示先に反映されること、報告の到着で入力先が変わらないことを確かめる。メインメニューから選択中の保管庫のアーカイブまたは復元を開始してタブを切り替えた場合は右欄、保管庫エディターで開いたファイルを操作した場合はその画面で結果を確認できる。
