# AI 協業のトランスポートとローカル連携先の結び付け

2026-11-14 の技術契約。AI のヒアリング Q1～Q35 で合意済み。ユーザーはテストの境界を確認し、集約した仕様を [GitHub Issue #2](https://github.com/TabTty/TabTty/issues/2) として公開するよう依頼した。その後、実装を承認した。製品の規則は[ヒアリング](../drafts/ai-terminal-collaboration-issue.md)と [ADR 0005](../adr/0005-expose-existing-terminal-sessions-over-local-mcp.md) に記載する。権限、ライフサイクル、端末操作、結果は[協業の契約](ai-collaboration-ja-jp.md)で定める。[検証計画](ai-collaboration-validation-ja-jp.md)も参照。

## 配布と設定

外部 AI ホストは、標準ストリームをリダイレクトして同梱の `TabTty.McpBridge.exe --stdio` を直接起動する。中間シェル、ダウンロード実行機構、デーモン、コンソールウィンドウは介さない。ブリッジは既に実行中の `TabTty.exe` にプライベートな Windows 名前付きパイプで接続する。GUI、端末接続、HTTP リスナー、受信 TCP ポート、推論接続は作らない。ホストやモデルは許可されたネットワークを使用できる。その方針の構成は TabTty の範囲外。

同じバージョンの Windows 配布物でブリッジを GUI の隣に置く。オフライン起動に必要な Microsoft .NET ランタイムとブリッジリソースを同梱する。GUI が対応するアーキテクチャと配布形態を使う。インストールに `npx`、`uvx`、パッケージレジストリ、初回起動時のランタイムダウンロードを要求しない。これはパッケージの要件。ブリッジと GUI の非公開インターフェースのバージョンは一致すること。不一致では対処可能なインストールエラーを報告し、別の実行ファイルやトランスポートへ切り替えない。

コピーできるホスト向け手順と実際のインストール先の絶対パスを提供する。ホストの論理設定は実行ファイル `<TabTty installation directory>\TabTty.McpBridge.exe`、引数 `["--stdio"]`。秘密の環境変数は使わない。`mcpServers` を使うホストの JSON 例を示す。

```json
{"mcpServers":{"tabtty":{"command":"C:\\TabTty\\TabTty.McpBridge.exe","args":["--stdio"]}}}
```

`C:\TabTty` は例示のパス。ホストの設定ファイルはホストが所有する。TabTty が黙って編集したり、AI ホストやモデルをインストールしたり、第三者の認証情報を保存したりしない。別の TabTty ブリッジ設定、検出ファイル、永続的なペアリングトークン、権限データベースは不要。ホストに起動設定を保存しても出力や操作へのアクセスは付与されない。

## プライベート接続と識別

現在の Windows ログオンには `\\.\pipe\TabTty.Ai.v1.<logon-SID>` を使う。SID は入力されたユーザー名ではなくプロセストークンから取得する。GUI は排他的に最初のインスタンスを作り、接続の受付前に規定数のサーバーインスタンスを開く。照合前にクライアントが切断した場合も、所有中のインスタンスを再利用する。所有者が競合した場合はエラーを表示して AI 接続を無効にする。競合先を代替 GUI として使わない。アプリ実行が終了するとエンドポイントは存在しない。パイプ名は検出に使う。

DACL は現在のログオン SID に限定し、ユーザーアカウント全体、Everyone、Anonymous、ネットワークへの広い権限は付与しない。リモートクライアントを明示的に拒否する。通信を始める前に、両端でユーザー、ログオン SID、Windows セッション、昇格状態、必須整合性レベルの SID が一致することを確認する。低整合性と中整合性はいずれも非昇格になりうる。どれか一つでも異なる場合や読み取れない場合は接続を拒否する。直接の起動元にも同じ検査を適用する。通常は非昇格で実行し、検査に失敗しても現在の権限のまま終了する。[Windows の必須整合性制御](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control)。GUI はインスタンスをすべて開いた後、ログオン SID に許可する権限をクライアントに必要な個別の権限に制限し、既存のサーバーハンドルを保持する。クライアントへの ACL にはインスタンス作成権限と汎用書き込み権限を含めない。Microsoft の文書には許可の広い既定 DACL とログオン SID による制限の説明がある。`CurrentUserOnly` はユーザーと昇格を検査するが、ログオンの方針全体は担わない。[パイプのアクセス権](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)、[パイプのオプション](https://learn.microsoft.com/en-us/dotnet/api/system.io.pipes.pipeoptions?view=net-10.0)、[リモート拒否と最初のインスタンス](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createnamedpipea)。

接続済みパイプの相手 PID を Windows から取得し、照会と同期権限でプロセスハンドルを開き、接続期間中は保持する。作成時刻、トークン、生存状態、正規の実行イメージを検証し、このインストールにある想定の GUI またはブリッジと照合する。ハンドルを開いた後に相手 PID と生存状態を再確認する。競合や識別情報にアクセスできない場合は接続を拒否する。再利用可能な数値 PID だけで認可しない。[クライアント PID](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeclientprocessid)、[サーバー PID](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid)。

検証後、GUI は暗号学的にランダムな 128 ビットの `counterpart_id` と、現在の接続間で一意の 16 進数 8 桁の `pairing_code` を割り当てる。ID をこのアプリ起動、パイプインスタンス、稼働中のブリッジプロセスのハンドルに結び付ける。非公開のハンドシェイクでは独立した 128 ビットのノンスを交換し、要求を受け付ける前にインターフェースバージョン 1 と両方のノンスを応答で返す。ノンスは接続を区別する。認証の代用や移転可能な権限には使わない。同じ実行ファイル、PID 値、名前、起動設定であっても再接続は新しい連携先とする。

GUI の連携先選択には照合コード、Windows が記録したブリッジの親プロセスの実行ファイルパスと PID、検証したブリッジの場所、未確認であることを示した上限付きの申告 AI 名を表示する。接続中に最初に申告された空でない名前を 1 行のテキストとして扱い、文字列からメニューのアクセスキーを作らない。詳細には、権限は連携先に属し、そのホストの複数のチャットが使える場合があると説明する。`tabtty_list_shared_sessions` は同じコードを返すため、利用者が照合できる。確認画面でも親プロセスのパス、PID、照合コードを示す。対象の接続は照合コードで確認し、確定時にそのタブの閲覧権限だけを付与する。ホストが対応する場合は別々のブリッジで別連携先を表せる。

`clientInfo`、タイトル、アイコン、URL、説明、要求 ID、チャット識別子は認可の主体の確立に使わない。提供されたアイコンや Web サイトのリソースは取得せず無視し、文字列は効果を持たない上限付きテキストとして表示する。識別検査で結び付けるのはローカルプロセスとチャネル。発行元、モデル、人、タスクの内容は検証しない。この設計では、同じユーザーのプロセスに十分なアクセス権を持つ敵対的コードの隔離、改変されたインストールの保護、認可済みホストによる受信出力の再転送防止は保証しない。

## 認可の決定

GUI のセッションモジュールが共有レコード、操作権の付与、世代、入力順、取り消しをすべて所有する。ブリッジはプロトコルのアダプターとして機能する。各操作は GUI の遷移ロジックと同じ認可インターフェースを通る。連携先はプライベート接続から解決する。クライアントの提示した連携先 ID を別接続の証拠にしない。ツール契約に従い、要求には明示的なアプリケーションハンドルを求め、操作ごとに結び付きと現在の権限を検証する。

共有前に公開するのはプロトコル情報、静的なツールスキーマ、その接続の準備と照合の状態だけ。共有タブの列挙は空の一覧を返す。共有していないタブの数、名前、接続先、プロファイル ID、レイアウト、画面内容、他の連携先の詳細は開示しない。未知、期限切れ、別連携先のセッションハンドルはすべて `not_shared`。無効な操作 ID の `control_required` は認可済みセッション内だけで返す。そのセッション内で未知、期限切れ、別連携先の観測ハンドルは一律 `stale_observation`、範囲または継続のハンドルは `cursor_expired`。より詳細な範囲の変更や喪失の情報は、ツール契約で検証済みの認可された範囲に限って許す。権限は既定で拒否し、プロトコル初期化だけでは付与しない。[OWASP の認可ガイダンス](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

結果をブリッジの配信チャネルに確定する前と、入力の受付前に認可を再検査する。共有終了は未確定の観測や待機をキャンセルし、キュー内の作業を無効にする。確定済みの配信は後から届くことがあり、取り消せない。ブリッジも取り消しを通知されたら未出力の結果を破棄する。境界と後処理は協業の契約で定義する。タブやウィンドウの移動で所有者は変わらない。ブリッジに障害があっても利用者はローカルで引き継げる。ブリッジからの要求自身を承認したり、共有を開始したり、操作権を付与したり、vault の値を読んだり、古い権限を復元したりできない。

## MCP のリビジョンとメッセージ

計画したアダプターには明示的にテストする二つの通信モードを実装する。従来版 `2025-11-25` と新版 `2026-07-28`。これは互換性の目標であり、この時点で既存 AI ホストの試験は未実施。公開ツール名と引数の意味は両方で共通とし、各版固有のエンベロープを使う。

従来クライアントは `initialize` で開始する。`2025-11-25` を返し、ツール利用前に `notifications/initialized` を待つ。未対応の従来版が提示されたら対応済み従来版を返し、互換性がない場合はクライアントが切断する。従来版の交渉で新版の動作を提示しない。`ping` は従来版のライフサイクルに従って利用できる。[従来版のライフサイクル](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)。

新版要求は各要求の `params._meta` に `io.modelcontextprotocol/protocolVersion` と `io.modelcontextprotocol/clientCapabilities` を含む。以前の要求から継承しない。必須メタデータの欠落は `-32602`、未対応版は対応リビジョンを添えて `-32022`。`server/discover` を実装し、サーバーの識別情報、機能、対応する両リビジョンを返す。新版の成功は `resultType: "complete"` を使う。新版のバージョンまたは機能フィールドを含む要求は従来版の初期化後も新版として扱う。従来版のツール呼び出しには従来版のハンドシェイク完了が必要。不正または不完全な新版メタデータを版の切り替えとして解釈しない。[バージョン管理](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)、[検出](https://modelcontextprotocol.io/specification/2026-07-28/server/discover)、[基礎フィールド](https://modelcontextprotocol.io/specification/2026-07-28/basic/index)。

新版の `server/discover` と `tools/list` は `ttlMs: 300000` と `cacheScope: "public"` を返す。対象は静的なプロトコル識別情報、機能、ツールスキーマに限る。連携先や端末データは対象外。検出の `_meta["io.modelcontextprotocol/serverInfo"]` には名前 `TabTty` とパッケージ版を含む。リスト変更機能のない `tools: {}` を通知する。七つのスキーマは権限によらず固定。`tabtty_list_shared_sessions` と端末ツールの結果は公開検出データとしてキャッシュしない。従来版の応答は新版専用の `resultType` とキャッシュフィールドを省く。新版では `ping` は未対応。非公開のハートビートは独立した内部機構。[ツールメッセージ、スキーマ、レート制限](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)、[リビジョンの変更点](https://modelcontextprotocol.io/specification/2026-07-28/changelog)。

新版がステートレスでも、stdio プロセスをチャットの識別情報には使えない。明示的なアプリケーションハンドルで TabTty の状態を指定する。プロセスへの結び付きは Q31/Q32 に基づく TabTty のローカル認可上の制限。MCP の会話継続性を意味しない。ツールだけを通知し、リソース、プロンプト、サンプリング、elicitation、サブスクリプション、バックグラウンドタスク拡張、モデル呼び出しは提供しない。各版の必須の基本動作とキャンセルを実装し、未対応の任意メソッドは通常どおり拒否する。操作上の失敗にはツールエラー、不正なメッセージには標準プロトコルエラーを使う。MCP の予約済みエラー範囲にアプリ独自のコードを割り当てない。

標準入出力は UTF-8 で、一行につき一つの JSON-RPC オブジェクト。文字列内の改行はエスケープする。JSON バッチ、BOM、バナー、進捗テキスト、JSON 外の端末データ、シェル出力は stdout に書かない。版ごとのキャンセル規則に従う。新版でキャンセル済みの要求には後から応答しない。キャンセルは受け付け済みの端末バイトを取り消せず、安全な自動再試行を意味しない。[stdio のフレーミングとキャンセル](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)。

## 上限、死活監視、障害

以下は初期の技術的制限。[ツール契約](ai-collaboration-ja-jp.md)と既存のリソース予算を補足する。どの予算でも端末保持内容を早期除去しない。

| 項目 | 上限と動作の計画 |
| --- | --- |
| 公開フレーム | LF を除く UTF-8 JSON 全体で 2 MiB。解析や割り当ての増加前に逐次適用する。 |
| プライベートフレーム | 長さ付き UTF-8 JSON 本体 2 MiB。割り当て前に検査する。制御用に予約した通信は 1 フレーム 16 KiB まで。長さは固定 4 バイトの符号なしリトルエンディアン。 |
| JSON | 深さ 32、1 メッセージ 65,536 トークンまで。重複したプロパティ名、不正 UTF-8、非有限数、不正なエンベロープ、不正な引数の型を拒否する。 |
| メタデータ | クライアントメタデータは合計 16 KiB。表示名とバージョンは各 128 Unicode スカラー値以下。上限内の未知の任意メタデータは無視する。 |
| 接続 | 未共有を含めアプリごとにブリッジ接続八つ。超過は既存の連携先を置き換えず失敗とする。 |
| 未完了作業 | 連携先ごとに通常要求 16、タブごとに受理済み入力操作は一つまで。超過は busy で拒否し、無制限のキューには入れない。 |
| 呼び出し頻度 | 通常は連携先ごとに 20 件/秒（バースト 40 件）、アプリ全体で 100 件/秒（バースト 200 件）。新規入力にはタブごとに 5 件/秒（バースト 10 件）も適用する。操作権返却は接続ごとに独立した 4 件/秒（バースト 8 件）とし、標準入力の受付時と GUI のパイプ受信時に確認する。 |
| 直列化 | テキストのフォールバック、構造化結果、メタデータ、エスケープ、エンベロープをフレーム容量に含める。上限前にページ分割し、JSON を任意の位置で分割しない。 |
| ツール結果 | テキストのフォールバックと構造化データを含む直列化済み結果は 1 MiB。2 MiB フレームのエンベロープ用に余裕を残す。 |
| バッファー | アダプターが所有する有効なペイロードは連携先ごとに 8 MiB。処理中や失敗しても所有中のフレームを含め、ツール契約のアプリ全体の一時作業 64 MiB に計上する。 |
| 接続開始 | パイプ接続とハンドシェイクは 5 秒。GUI がなければ利用不可を報告して終了し、GUI の起動や待機はしない。 |
| 進行の死活監視 | ツールやモデルの動作とは独立して 5 秒ごとに非公開ハートビート。20 秒間有効なハートビートがなければ接続を終了する。 |
| ブロックしたストリーム | 書き込みが 20 秒ブロックされたら終了。応答を無制限にためたり、端末受信にバックプレッシャーを掛けたりしない。 |
| 不完全なフレーム | 最初のバイトからフレーム完了まで 20 秒。保留フレームのないアイドル状態は許す。 |

取り消し、キャンセル、死活監視の容量を、通常作業とレート制限の枠から独立して予約する。ツール呼び出しが超過したら `retry_after_ms` を伴うツール `busy`。プロトコル検出の超過は JSON-RPC/MCP の予約範囲外の上限付き JSON-RPC サーバーエラー `-31001` と同じ待ち時間メタデータを返す。両方の通信モードで一貫して使う。過負荷応答では再試行を予約せず入力シーケンスを消費しない。ハートビートに端末内容はなく、AI の推論中の応答を求めない。静かな推論やツール要求完了では操作権を終わらせない。サスペンドから復帰したら追加作業の受付前に期限を検査する。プロセスハンドルの終了、stdin EOF、stdout やパイプの破損、識別失敗、回復不能なフレーミング障害は速やかに接続を終了する。上限内の有効フレームのプロトコルエラーには適切なエラーを返す。上限超過やフレーミング不能の入力は内容をエコーせずトランスポートを閉じる。

GUI とブリッジはそれぞれ Windows からブリッジの直接の親プロセスを取得する。両端で照会と同期ハンドルを保持し、親の PID と作成順、前述のトークン情報の一致を確認し、生存を監視する。GUI は自身が取得した親のプロセスハンドルから実行ファイルのパスを取得する。起動元が汎用ランタイムの場合もあり、特定のモデル、チャット、発行元の身元は確定できない。[親 PID](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/ns-tlhelp32-processentry32w)、[プロセス作成時刻](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)。

起動元が生きている間、ホストから同じ標準入出力ハンドルを委譲された別プログラムは、その接続を通じて権限を使える。同じホスト接続を使う別チャットや侵害された正規ホストを受信側で識別することはできない。別のブリッジを起動したプログラムは、パスや申告名が同じでも未共有の新しい接続から始まる。

ホストは連携中、直接起動したブリッジとストリームを維持する。起動元の終了を観測したら、孤立または継承されたストリームで権限を維持できない。ライフサイクルの結び付けを確立できなければ設定を拒否する。プロセス喪失時は GUI 契約を通じて、その連携先の共有と操作権をすべて取り消す。GUI 終了は全接続とブリッジを閉じる。ブリッジがアプリの実行を維持することはない。再起動や再試行は新しい空の権限状態から始まる。失敗後のコマンド再送や透過的な再接続は行わない。部分的または到達未確認の入力にはツール契約の引き継ぎと復旧の動作を維持する。

## 依存関係、診断、検証

小規模な TabTty 独自の MCP アダプターを選ぶ。Microsoft .NET BCL の `System.Text.Json`、`System.IO.Pipes`、安全なプロセスハンドル、暗号学的乱数、範囲を限定した文書化済み Win32 相互運用を使う。GUI の認可インターフェースはパイプトランスポートと通信版の差をセッションロジックから隠す。公式 C# MCP SDK は Microsoft、Anthropic、MCP の共同保守。その説明だけでは直接依存関係の方針に適合すると判断できない。このドラフトでは採用や例外申請は行わない。[Microsoft の SDK 出所](https://learn.microsoft.com/en-us/dotnet/ai/get-started-mcp)。

stderr に許すのは上限付きのイベントコード、バージョン、時刻、秘密を含まない失敗分類だけ。ホストは取得できる。要求と結果の本文、端末内容、入力文字列、照合ノンス、権限、認証情報の参照と値、クライアントメタデータ、プロセスコマンドライン、例外ダンプを除外する。診断ログと合意済みセッション記録は別にする。端末出力には手動入力した秘密やリモートまたはローカルのエコーが含まれる場合がある。すべてのプロンプトの検出や伏字化は保証しない。必要な場合は機密性の高い端末作業前に共有を終了する。[認証方針](../drafts/authentication-issue.md)、[OWASP のログ除外項目](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#data-to-exclude)。
