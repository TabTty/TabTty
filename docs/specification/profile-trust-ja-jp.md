# 接続プロファイルの登録と信頼

2026-11-19 の実装向け仕様。[English](profile-trust.md)。開いたプロファイルを一律に信頼していた Q112 の取り決めを改訂する。SSH、Telnet、シリアル接続に適用する。マクロに関する項目はマクロ対応ビルドに適用する。

## 接続時の判断

**プロファイルを信頼するか尋ねるのは、接続を要求されたときだけ**とする。上限を設けてファイルを一度読み込み、検証した内容を保持する。開いた場所の登録状態と、その版の信頼を照合し、ファイルごとに次の表を適用する。

| 接続の契機 | 登録状態 | この版の信頼 | 動作 |
| --- | --- | --- | --- |
| 手動で開く・再接続 | 未登録 | どちらでも | ［今回だけ接続］［登録して接続］［キャンセル］ |
| 手動で開く・再接続 | 登録済み | 信頼済み | そのまま接続 |
| 手動で開く・再接続 | 登録済み | 未信頼 | ［今回だけ接続］［この版を信頼して接続］［キャンセル］ |
| マクロの `Connect` | どちらでも | 信頼済み | そのまま接続。登録状態を維持する |
| マクロの `Connect` | どちらでも | 未信頼 | ［今回だけ接続］［この版を信頼して接続］［キャンセル］。登録状態を維持する |

手動には Explorer の［開く］、コマンドラインからのファイル起動、アプリ内のファイル選択、登録一覧からの接続を含む。再接続のたびにその時点のファイルを照合する。既定のボタンは［キャンセル］で、対象の要求だけを中止する。［今回だけ接続］はその接続試行だけを許可し、既存の登録・信頼を変更しない。

［登録して接続］は登録を完了し、読み込んだ版を自動的に信頼して、その内容で接続する。二度目の信頼確認は行わない。その後に通信や認証が失敗しても、確定した登録と信頼は残る。［この版を信頼して接続］は、開いた場所のその版を記憶して接続する。この操作で登録は増えない。

マクロ起動時の承認は、そのマクロと順序付き引数を対象とする。プロファイルの判定は、基準ディレクトリの変更などを反映し、実際の `Connect` のパスが確定した時点で行う。ここで記憶した信頼はほかの許可済みマクロでも使える。そのファイルを後で手動で開いたとき、未登録であれば必ず登録の選択肢を表示する。

## 登録・編集・解除

- **新規登録の成功時に、登録した場所のその版を自動で信頼する。** 登録一覧の［登録］、［登録して接続］、新規作成・複製の保存が正常に確定して登録を作る場合に適用する。登録操作に対象ファイルと自動信頼の意味を示す。単独の［登録］では接続を開始しない。ファイルの起動要求を受け取った時点や、そのタブの場所を確保した時点では登録しない。
- メインウィンドウから信頼済みの版を編集した場合は、保存が確定した内容に信頼を更新する。すでに外部で変更された未確認の版を読み込んで既存ファイルを通常保存した場合、または Explorer などから単体で開いた編集画面で保存した場合は、その保存による信頼を付与しない。必要な確認は次の接続時に行う。別の経路から同じ編集画面を前面に戻しても、元の保存権限は変わらない。表示、編集、保存、閉鎖ではプロファイルの信頼を尋ねない。
- 登録時の自動信頼は、未登録から登録済みに変わったときに適用する。既存登録の読み込み、登録一覧の表示、表示名や利用履歴の更新で信頼を付け直さない。導入前の登録は維持し、信頼記録のない版は未信頼として扱う。
- 登録解除が成立したら、登録とともに、その場所に結び付くプロファイルの信頼をすべて削除する。マクロから記憶した信頼も対象とする。ファイル削除が成功して登録を取り除く場合も同じとする。別の場所にあるファイルの信頼は独立する。改めて登録した場合は、その時点で登録した版を信頼する。

## 判断の対象

信頼は、この PC の Windows ユーザー、開いた場所の正規化済み絶対パス、ファイル全体のバイト列の SHA-256、セキュリティに関係する設定の解釈規則の版に結び付ける。場所の比較と相対ログパスの基準には既存の Windows 向け規則を用いる。信頼記録はプロファイル・vault の外に保存する。新しい版を信頼したらその場所の旧版への承認を置き換える。別の場所にあるコピーには独立した判断が必要になる。[プロファイルの場所の規則](persistence-and-windows-ja-jp.md)

接続の確認画面には、ファイルの場所、接続方式、ホスト・ポートまたはシリアルポート、SSH ユーザー名と認証方法、使用する認証情報の参照、記録形式と解決済みのログ保存先を表示する。共有への保存を明示し、前回の情報がある場合は変更点を示す。制御文字を識別できる形で表示し、秘密値は表示しない。マクロ経由ならマクロ名も表示する。外部から指定されたネットワーク上のプロファイルは、ファイルを読む操作自体が共有先へのアクセスになる。その場合に必要な読み取り許可はアクセス前に取得し、効力はファイルの読み取りに限る。

接続判断が済んでから、ログ保存先へのアクセス、接続先の名前解決、ポートのオープン、認証情報の使用を開始する。記録、マクロのプロファイルパスワード参照、通信には、確認した同じ読み込み結果を使う。接続開始時に実際のログ保存先を確認し、接続後にドライブ割り当てなどで別の宛先に変わった場合は、そこへの記録を保留する。記録の開始や再開によってプロファイルの信頼を付与・更新することはない。SSH ホスト鍵の確認と vault の解除はそれぞれ従来の手順で行う。ある接続試行が確認待ちでも、ほかの端末は入力を受け付ける。再接続成功後の宛先変更を知らせる最前面のモードレス通知は、信頼判断や同時送信のチェック状態に影響しない。

保存済み認証情報を使う SSH プロファイルの確認画面には、読み込んだ版のプロファイルに記録された確認用アカウントを表示する。ホスト鍵の検証後、最初の SSH ユーザー認証要求を送る前に、そのアカウントを利用可能な保存済み認証情報のユーザー名と照合する。認証情報が利用できず別の方式で続行する場合も、確認した版のアカウントを使い続ける。[SSH 認証仕様](transports-and-authentication-ja-jp.md#認証とユーザー向けメッセージ)

## 一括リセットと保留中の操作

設定に独立した二つの操作を設ける。各リセットの確認には消去対象を明示し、既定を［キャンセル］とする。

| 操作 | 消去対象 | 次回の動作 |
| --- | --- | --- |
| ［マクロの信頼を一括リセット］ | この PC の現在のユーザーが記憶したマクロの許可・拒否のすべて | 各マクロの次回起動時は初回の確認を行う |
| ［接続プロファイルの信頼を一括リセット］ | この PC の現在のユーザーが記憶した、登録済み・未登録双方のすべての版の信頼 | 次の接続時に表の規則で判断する。登録一覧、お気に入り、利用履歴は維持する |

他方の信頼、SSH ホスト鍵、vault の情報はどちらの消去対象にも含めない。すでに開始を許可した接続や実行中のマクロは続行する。実行中のマクロがこれから `Connect` を呼ぶ場合は、その時点のプロファイル信頼で判断する。

複数のウィンドウで登録・信頼の変更と接続の判断順序をそろえる。登録解除・リセットの対象になった保留中の確認や保存による信頼更新は失効させる。古い回答や遅れて完了した保存から信頼が復活したり、その判断で接続したりしない。なお有効な接続要求は現在の状態で判定し直す。対象外の要求と別の種類の信頼は独立して扱う。

登録と自動信頼、登録解除と信頼削除は、障害や再起動をまたいでも一貫させる。永続化が失敗した場合や成否が不明な場合は、その結果で接続を許可したりリセット完了と表示したりせず、状態と再試行方法を示す。古いバックアップから消去済みの信頼を復活させない。

## 受入条件

1. 未登録ファイルを手動で開き［今回だけ接続］を選ぶ。次の手動オープンでも三択になる。そこで［登録して接続］を選ぶと、同じ版への再接続では確認が出ない。
2. マクロで未登録の版を信頼する。別の許可済みマクロは同じ版をそのまま使える。Explorer で開くと［登録して接続］を含む三択になる。
3. 一覧から単独で登録し、外部で編集する。編集時に信頼の確認は出ない。次の接続や記録が始まる前に、登録済み・未信頼の三択が出る。
4. 接続中に登録を解除する。既存タブは利用できる。次の手動再接続は未登録の三択となり、マクロで同じ版に接続するときも改めて判断する。
5. 登録済みと未登録の両方に信頼記録がある状態でプロファイル信頼を一括リセットする。再起動後も両方の信頼は消え、登録一覧とマクロの許可・拒否は維持される。
6. マクロの許可と拒否がある状態でマクロ信頼を一括リセットする。どちらのマクロも次の起動時に初回確認に戻り、プロファイルの版の信頼は維持される。
7. 確認・保存の途中に対象の信頼をリセットする。古い操作が完了しても信頼は復活しない。その後に改めて登録を開始して成功した場合は、その時点の版を信頼する。
