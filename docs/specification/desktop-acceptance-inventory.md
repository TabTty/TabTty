At handoff, identify the Hyper-V host accessible to the agent through VMConnect and the actual VM names. Handle any required sign-in at the console. The agent checkpoints the clean guest, configures the serial mapping and scratch disk, provisions the peer, and connects the VMs to a private virtual switch for testing. [Hyper-V switch connectivity](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/features-terminology#virtual-switch)

The generation 2 COM mapping needs a guest application probe. Microsoft lists generation 2 COM support, while its terminology guide describes named-pipe application ports for generation 1. Record a pass only when TabTty opens the port and both ends receive the expected bytes. If that path fails, record the result and evaluate a signed virtual COM pair with appropriate test-use terms on a disposable guest copy. Both approaches leave the physical signal and adapter cases in row 10 unverified. [Hyper-V serial procedure, sources and fallback](../drafts/hyper-v-serial-validation.md)

The agent stages the unmodified release ZIP on a temporarily redirected transfer drive or an ISO attached to the virtual DVD drive. Copy the ZIP to the guest's local disk, compare its SHA-256 with the host's, then disconnect the redirected drive or eject the ISO before extracting and launching. Redirection makes host paths available in the guest, so local staging avoids accidentally launching another build or targeting a host drive during fault injection. [VMConnect local resources](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/use-local-resources-virtual-machine-connection) · [VMConnect virtual media](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/virtual-machine-connection)

**Confine failure injection to the VMs.** Use disposable guest data for capacity exhaustion, ACL changes, corrupt files, deletions, share/network loss, abrupt shutdown and destructive credential or host-key recovery. In rows referring to E1, operate E2's desktop for those steps. Before filling the scratch volume, verify its label, disk identity and size and check the host's storage headroom for VHDX and checkpoint growth and merge. Keep the guest OS disk, host volumes, redirected drives and ordinary network shares outside the fill target. Preserve the evidence before restoring the guest. [Virtual disks](https://learn.microsoft.com/en-us/windows-server/administration/performance-tuning/role/hyper-v-server/storage-io-performance#virtual-disks) · [Checkpoint storage](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/checkpoints#deleting-checkpoints) · [VMConnect redirection](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/enhanced-session-mode)
