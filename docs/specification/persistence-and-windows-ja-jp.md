# プロファイル、設定、パス、ウィンドウの所有権

2026-11-10 時点の仕様。Q109～Q116、Q155～Q158 の内部契約を確定する。信頼済みプロファイルからの起動の境界と、保存済み設定が反映されるタイミングは従来どおり。この仕様による実装やファイル移行の承認はない。

2026-11-16 に合意したエクスプローラーとエディターの仕様は、プロファイルをタブで編集し、起動経路を端末ウィンドウに限定していた以前の記述に優先する。

## 共通 JSON ルール

UTF-8 のオブジェクト、`schemaVersion: 1`、大文字と小文字を区別する英語のプロパティ名、ID には小文字でハイフン付きの正規 UUID 文字列を使う。新しい書き込みは BOM なしとし、ユーザーが編集できるこれらの JSON ファイルでは先頭の UTF-8 BOM を一つ許可する。不正な UTF-8、プロパティの重複、一意性が必要な ID の重複、コメント、末尾の空白以外の文字、未対応のスキーマバージョンや必須機能、不正な型、必須フィールドの欠落、未知の列挙値を拒否する。読み込み時に新規プロファイルの既定値で自動修復しない。null 許容フィールドには明示的に null を入れる。継承は省略から推測せず明示する。

各ルートは一意な文字列の配列 `requiredFeatures` も持つ。v1 では空配列とする。未知の必須機能は拒否する。同じ対応バージョンで保存する際は、各オブジェクト階層の未知の任意プロパティを上限付き JSON として保持する。実行や新しいスキーマのダウングレードは行わない。フィールド順に意味はなく、配列順には意味がある。整形時に空白を保持する必要はない。

すべての読み込みに構造検査とリソースおよび型の制限を適用する。詳細な設定の整合性、正規表現の妥当性、設定ガイダンスは、エディターを開くとき、編集時、保存時に適用する。接続ではポートの可用性、対応する上限、認証情報、ファイルアクセスなどの通常の実行時検査を行う。追加のプロファイル承認画面は設けない。

## プロファイル v1 のフィールド

表のフィールドはすべてエディターが出力し、特記がなければ必須。既定値は新規プロファイルに適用する。欠落したフィールドの修復には使わない。

| オブジェクト | フィールドと解釈 |
| --- | --- |
| ルート | `schemaVersion`、`requiredFeatures`、`profileId`、`displayName`、`connection`、`terminal`、`logging` |
| connection | `type` は `ssh`、`telnet`、`serial` のいずれか。`waitSeconds` は既定 30、範囲 1～300。以下のうち該当するトランスポートのフィールドだけを含む。 |
| SSH | `host`、`port`（既定 22）、`username`、`authentication`、`liveness` |
| authentication | `methods` は `publicKey`、`password`、`keyboardInteractive` の順序付きで重複のない部分集合。初期値は `[password]`。`privateKey` と `password` はそれぞれ null または認証情報参照。未保存で取得できない入力は認証時に求める。 |
| 認証情報参照 | `vaultId`、`entryId`、`kind`（`privateKey` または `password`）。秘密情報、パス、インポート元のパスフレーズを含まない。 |
| liveness | `enabled` は既定 false、`intervalSeconds` は既定 30、範囲 1～3600。`unansweredWindows` は v1 で 3 に固定。 |
| Telnet | `host`、`port`（既定 23）、`initiateBinary`（既定 false）。ユーザー名、認証情報、ログイン照合フィールドは含まない。 |
| シリアル | `portName`、`baudRate`（既定 9600）、`dataBits`（既定 8、7/8）、`parity`（既定 `none`、`odd/even/mark/space`）、`stopBits`（既定 1、1/2）、`flowControl`（既定 `none`、`xonXoff/rtsCts/dsrDtr`）、`dtr`（既定 true）、`rts`（既定 true） |
| terminal | `advertisedType`（既定 `xterm`）、`receiveEncoding`（既定 `utf-8`）、`sameEncoding`（既定 true）、`transmitEncoding`（既定 `utf-8`）、`jis`、`ambiguousWidth`（既定 1、1/2）、`enter`、`backspace`、`localEcho`、`font`、`retainedRows`、`highlightSetId`（null または UUID） |
| jis | `kanjiIn`（既定 `B`、`@/B`）、`kanjiOut`（既定 `B`、`B/J`）、`receiveKana`（既定 `eightBit`、`eightBit/soSi`）、`transmitKana`（既定 `eightBit`、`eightBit/soSi`）。適用範囲はコーデックの契約で定める。 |
| font | `mode` は `inherit` または `override`。`family` は継承時 null、それ以外は指定されたインストール済みフォント名。`sizePoints` は継承時 null、それ以外は 6～72。 |
| retainedRows | `mode` は `inherit` または `override`。`value` は継承時 null、それ以外は 100～100000 の整数。 |
| logging | `raw`、`text`、`terminal` は既定 false。`directory` は既定 `Logs`。 |

`enter` は `cr`（SSH/シリアルの既定）、`lf`、`crlf`（Telnet の既定）のいずれか。`../drafts/terminal-interaction-issue.md` の合意どおり、`backspace` は `del`（SSH/Telnet の既定）か `bs`（シリアルの既定）。`localEcho` は SSH で `off`、Telnet で `followRemote`（既定）または `off`、シリアルで `off`（既定）または `on`。対象外の保存済み端末フィールドは動作に影響せず、関連する場合だけ編集できる。sameEncoding=true の場合、実効送信エンコーディングは receiveEncoding に等しい。明示的に保存した送信設定は後で使えるよう保持する。

エンコーディング ID は `utf-8`、`cp932`、`euc-jp`、`jis`、`cp949`、`cp936`、`cp950`、`koi8-r`、小文字の `cp` に合意済みの OEM/Windows 番号を付けたもの、または `iso-8859-` に 1～11、13～16 のいずれかを付けたもの。合意済みの 48 種類に限る。プロファイル ID はコンテンツの識別子であり、ローカル登録の識別子は別に管理する。

## アプリケーションストア

| ファイル | 共通のバージョンフィールド以外の必須データ |
| --- | --- |
| settings.json | `language` は既定 `system`（`en/ja/system`）、`theme` は既定 `system`（`system/light/dark`）、`bell` は既定 `visual`（`visual/off`）。`defaultTerminalFont` は family が Consolas、sizePoints が 12。`defaultRetainedRows` は 5000。任意の `autoCloseDisconnectedTabs` は真偽値、既定 `true`。任意の `credentialVaultPath` は絶対 `.tttykey` パスまたは既定位置を示す null。任意の `broadcastAcrossWindows` は真偽値、既定 `false`（同時送信の拡張）。 |
| highlighting.json | `sets` は順序付き配列で初期状態は空。各セットは `setId`、`name`、`enabled`、`rules` を持ち、各ルールは `ruleId`、`name`、`enabled`、`pattern`、`ignoreCase`、`style` を持つ。 |
| style | null 許容の `foreground`/`background` は `#RRGGBB` 形式。`bold` と `underline` は null 許容の真偽値。null は端末属性を継承する。優先順位の低いルールからは継承しない。 |
| state.json | `registrations`、`lastWindow`、vault パスのフィールド導入前の設定用の旧 `selectedVaultPath`。アプリケーション状態のみを含む。 |
| registration | 独立した `registrationId`、開いたパスの正規形と表示用表記、`favorite`、UTC の null 許容 `lastUsed`。ファイルの不在はローカルで観測し、プロファイルを書き換えない。 |
| lastWindow | DIP 単位の通常時の位置とサイズ、モニター ID、作業領域、DPI の観測値、最大化フラグ。最小化状態では復元しない。 |
| host-keys.json | トランスポート契約で定義するバージョン付きのホストレコード。vault やポータブル設定から独立する。 |

言語、テーマ、ベル、保存したルールは保存成功後ただちに適用する。自動で閉じる設定は、保存後に発生した切断から適用する。同時送信の範囲は Q181 に従い開始時に確定する。Q187 で対象を拡大した通常の終了コマンドは、保存した全ウィンドウ設定にただちに従う。Q197 は範囲モードの変更時に全選択へリセットする。次回開始時というタイミングは Q199 で確認済み。実行中の同時送信モード、送信先のチェック、ウィンドウ単位の初回利用やリセット待ちの状態、分割レイアウトは永続化しない。[同時送信と分割ビュー](broadcast-and-split-views-ja-jp.md)を参照。

保持された切断済みタブは、接続名の前に切れたリンクのアイコンを表示する。ツールヒントとアクセシブルなタブ名に、ローカライズした切断状態を含める。現在のウィンドウにある切断済みタブは、タブバーのコンテキストメニューから閉じられる。Q192（2026-11-14）は以前の自動・一括閉鎖の例外を置き換える。最後のタブを取り除いたら、端末、設定、エディターのタブを合わせて数えた上でウィンドウを閉じる。空の分割グループはタブに数えない。タブ移動では空になった元ウィンドウを閉じる前に移動先を確定する。ウィンドウの初期構築は最後のタブの除去に当たらない。

2026-11-16 に改訂したアーキテクチャ Q10 で、ユーザーによるこの一括コマンドと切断済みタブの自動削除は、いずれも対象タブに関連する転送ウィンドウを、個別タブ／ウィンドウの明示閉鎖と同じ後処理・報告方針で閉じると合意した。すでに切断済みの対象には接続終了の警告を出さず、必要な後処理、報告、待機・損失の選択は既存方針に従う。切断や接続先の喪失後に端末タブを保持する場合は、転送結果も保持する。[閉鎖設計](tab-and-window-closure-ja-jp.md)を参照。一括処理と自動削除の動作変更は未実装である。

フォントと保持行数の既定値、プロファイルから解決した値は次回接続時に確定する。`system` のような選択値を保存する。貼り付け間隔と記憶チェック、一時ズームとエコー、ロック解除状態、タブの内容はどのストアにも保存しない。翻訳は安定した識別子を持つ言語別リソースで管理する。初期対応は英語と日本語。システム言語は Windows の表示言語の優先順に従い、英語にフォールバックする。テーマは Windows のアプリ用設定に即時追従し、周囲の UI だけに適用する。

上限はプロファイル 1 MiB、設定 64 KiB、強調表示、状態、ホストレコードは各 16 MiB、JSON の深さは 16。表示名は 256 スカラー値、ホスト名は IDNA 変換後の ASCII で 253 バイト、パスは UTF-16 で 32760 コード単位、通知する端末種別は印字可能な ASCII で 64 バイト。強調セットは 1000、セットごとに 100 ルール、パターンは UTF-16 で 4096 コード単位。登録済みプロファイルとホスト接続先は 10000。必須機能は 32 個、各 ASCII で最大 64 バイト。未知のプロパティの内容も同じサイズと深さの制限に含める。これは読み込み時の内部上限であり、すべての最大値を同時に使ったときの実用性能は保証しない。

## 開いた場所と登録

ローカルアプリデータの場所は Windows から取得する。非パッケージ版のストアはその下の `TabTty` ディレクトリに置く。新規プロファイルには既知の「ドキュメント」フォルダーの `TabTty\Profiles` を提案する。外部のプロファイルは元の場所で開く。ログディレクトリはプロファイルを開いたディレクトリからの相対位置として解決する。通常の絶対 DOS/UNC パスと通常の相対ログパスを許可し、区切り文字とドット構成要素を正規化する。ドライブ相対の `C:Logs`、ルート相対の `\Logs`、デバイス名前空間、代替データストリーム、埋め込み NUL は拒否する。環境変数やチルダは展開しない。長いパスには内部で拡張プレフィックスを使えるが、ユーザー向けの新しいパス構文は設けない。

登録は、正規化した開いた場所で識別する。リンクの最終リンク先、ファイル ID、保存されたプロファイル UUID は登録の識別に使わない。大文字と小文字を区別するディレクトリの区別を保持し、一律に小文字化せず、所属ディレクトリの Windows の規則で名前を比較する。ファイルシステムから取得できる場合は短い表記と長い表記の等価性を解決し、別々のリンクパスは統合しない。同じ場所と確認できない場合は登録を分け、履歴を保持する。相対ログは引き続き開いた場所を使う。

外部コピーや新しい場所には、新しい登録 ID を割り当て、お気に入りや履歴は引き継がない。profileId が重複しても移動と判断しない。明示的に分かっている移動では古い登録を削除し、新規登録する。場所をまたぐ登録の連続性は設けない。移動追跡がない場合、アクセスできない旧パスは削除されるまで不在と表示されることがある。識別情報は別のパスに移さない。ファイルハンドル ID とダイジェストは編集競合の検出に使える。

## 保存と復旧

編集の下書きと元ファイルの識別情報、ダイジェストを保持する。保存では検証、元のスナップショットとの比較、同一ディレクトリへの候補ファイルの書き込みとフラッシュ、置き換えまたは上書き禁止の新規作成、実際の結果の確認を順に行い、実効リビジョンを公開する。検証済みの前世代を一つ `.bak` に保持する。外部変更を検出したら再読み込みと確認を求める。自動での統合や上書きは行わない。失敗した場合は下書きと最後の有効な設定を保持し、実際の結果を報告する。誤って保存済みと表示しない。ファイルの置き換えは単一ファイルに限る。

置き換えの結果が不明な場合は、対象、候補、バックアップのバイト列を期待値と比較し、有効なファイルが確定するまで関連する書き込みを凍結する。エラー時に名前と内容が維持されたとは限らない。破損ファイルは、明示的なバックアップ復元、一時的な既定値の利用、終了のいずれかを選べるようそのまま保持する。一時的な既定値を使うストアは、元ファイルを重複しない名前で保持した上で明示的に復旧または再作成するまで読み取り専用とする。新しいスキーマを破損として暗黙に復旧しない。初回利用でファイルが存在しない場合は既定値を使う。強調表示の失敗は致命的に扱わない。ローカル状態の保存エラーはまとめて扱い、切断しない。

一時的な既定値と初回利用時の既定値は、アプリ設定、強調表示、ローカル状態のストアだけに適用する。プロファイルが存在しない、破損している、または未対応の場合は接続や再接続ができない。有効なプロファイルを復元するか明示的に保存する。ホストストアの障害は明示的に復旧する。既知のホストを暗黙に未知のホストに変えて初回承認の対象にしない。

## ウィンドウ、ファイル起動、モーダルの順序

Windows ユーザーごとの一つの `TabTty.exe` インスタンスが、端末ウィンドウと独立した編集ウィンドウを所有する。プロファイルと保管庫の起動には認証済みの同一ユーザー向けローカルチャネルを使い、操作種別とパスに上限を設ける。ディスパッチ時に世代を検査する。操作種別とパスの無効な組み合わせは拒否する。無効な［編集］の要求を接続として実行しない。

ファイルからの起動は[保留件数の上限](resources-and-validation-ja-jp.md)まで FIFO で受け付ける。処理をブロックするモーダルの表示中はキューに入れ、ファイル準備の期限を開始しない。接続要求は、存続中の端末ウィンドウのうち最後にアクティブだったものに送り、最小化されていれば復元する。端末ウィンドウがなく、終了も確定していない場合は新しく作る。非同期読み込みの前に、受信順に新しいタブの位置を確保する。各ファイルで通常の準備と接続を実行し、失敗はそのタブに表示する。Q158 のプロファイルとログの独立した 30 秒の期限は、それぞれの段階で計測を始める。接続先の端末ウィンドウを選ぶ際は独立した編集ウィンドウを候補に含めない。

エクスプローラーから編集で初回起動したときは、指定された編集ウィンドウを表示する。編集ウィンドウだけが開いている状態でファイルを指定せずに通常起動すると、端末ウィンドウにプロファイル選択を表示する。最後のタブを閉じたときは、その端末ウィンドウを閉じ、別の編集ウィンドウと下書きを維持する。アプリの終了判定には端末ウィンドウと独立した編集ウィンドウを数え、すべて閉じた時点で終了する。

同じ保管庫ファイルのロック解除操作は一つを共有し、待っているすべての試行が同じ結果を受け取る。キャンセルや失敗では待機中の試行を終了し、確認を繰り返さない。ダイアログの所有元が閉じた場合は、同じコーディネーターで操作を完了するか、存続中のウィンドウに引き継ぐ。[保管庫の所有権と後処理](vault-format-ja-jp.md#秘密情報の所有者と後処理)を参照。

タブの移動では、移動先への挿入を確定できるまで元の所属を維持する。確定時に変更するのは表示上の所属だけで、続けて空になった元ウィンドウを閉じる。失敗やドラッグの取り消しでは元の状態を保つ。移動中の保護により、所属先を切り替える間に最後のウィンドウが終了するのを防ぐ。ファイル起動、閉鎖、移動の確定はコーディネーターの順序に従う。各セッションは一つの端末タブに属し、移動中の保護下にある場合を除き、そのタブは一つのタブグループとウィンドウに属する。同じタブ内の複数ペインは同じセッションのビューとして扱う（2026-11-13 に Q165/Q170/Q172 で合意）。閉鎖の確認をキャンセルすると、保留中のファイル起動を再開する。最終終了の確定後は新しい起動を拒否し、保留中の要求をキャンセルする。通知領域に隠れて動き続けることはない。

[転送ウィンドウ](file-transfer-ja-jp.md#transfer-window-and-operation-ownership)は SSH 端末タブと現在の接続世代に結び付く。タブを分離または移動しても、転送ウィンドウと作業を維持する。タブや端末ウィンドウを閉じる確認には進行中のファイル操作を含める。切断や接続先の喪失後に端末タブを保持する場合は、転送結果も保持する。自動削除を含む実際のタブ削除では、上記の閉鎖方針に従い、関連する転送ウィンドウを閉じる。

モニターごとの DPI に対応した WPF ウィンドウを使う。通常時の位置とサイズを DIP で保持し、対象モニターの現在の倍率と作業領域に合わせて変換し、画面内に収める。初期の通常サイズは 1000×700 DIP。モニターが許す場合の最小値は 480×320 DIP。必要に応じて作業領域まで縮める。最大化は別に復元する。分離したウィンドウは元の通常サイズでドロップ位置の近くに開く。レイアウト通知はトランザクション単位で最終グリッドにまとめ、変更されたグリッドにはセッションのサイズ変更契約を適用する。

## エクスプローラーと編集ウィンドウ

現行の非パッケージ版 Windows 11 向け配布で、`.ttty` と `.tttykey` に［開く］と［編集］を登録する。拡張子ごとの既定のアプリは Windows の設定に従う。TabTty が選ばれている場合は以下の動作を提供する。［編集］は［その他のオプションを表示］から使えればよい。複数選択では、Windows の選択件数の制限内でエクスプローラーが渡すファイルを処理する。

| ファイル | ［開く］、ダブルクリック、Enter | ［編集］ |
| --- | --- | --- |
| `.ttty` | 基本的な読み込み検査後に元の場所で登録し、ファイルごとに新しい端末タブで接続を開始する。複数選択で［開く］を選ぶか Enter を押した場合も、渡された全ファイルで接続処理を行う。 | ファイルごとにプロファイルの編集ウィンドウを開く。複数選択に対応する。 |
| `.tttykey` | 既存の一ファイルを保管庫の編集ウィンドウで開く。 | 既存の一ファイルを同じ保管庫の編集ウィンドウで開く。 |

受け付けた各プロファイルの処理は独立する。一つの読み込みが失敗したら対象パスのエラーを表示し、他のファイルの編集や接続は続ける。エクスプローラーが別々に起動要求を送る場合も、アプリが受け取った順序に従う。保管庫は起動要求ごとに一ファイルを受け付ける。

TabTty 内のプロファイルの新規作成と編集には独立したウィンドウを使う。エクスプローラーの［編集］では既存ファイル用のフォーム、レイアウト、詳細な検証、明示的な保存手順を共有する。そのファイルを元の場所で編集・保存する。プロファイルの登録と接続は［開く］の操作で行う。保存済みの資格情報を選ぶ操作では、必要に応じて選択中の既存の保管庫をロック解除し、参照を選ぶ。プロファイルを開くときと保存するときにはロック解除を求めない。エクスプローラーから開いた編集画面の資格情報選択で保管庫が空または不在の場合は、その旨を表示する。初期化は保管庫管理で行える。

ファイルの種類ごとに、正規化した開いた場所につき独立した編集ウィンドウを一つ使う。同じ場所を再度開くと、下書きを保持したまま既存ウィンドウを復元し、前面に出す。プロファイル一覧とエクスプローラーからの編集には、プロファイルの登録と同じ場所の識別規則を適用する。別の場所へのコピーは、内部 ID が同じでもそれぞれのウィンドウで編集できる。各ウィンドウの編集対象は開いたときの場所に固定する。

保管庫の管理タブと独立した編集ウィンドウは、フォームと管理操作を共有する。管理タブでは選択中の保管庫を扱う。エクスプローラーからは指定ファイルを開き、必要に応じてマスターパスワードを求める。指定ファイルが選択中の保管庫なら、タブ、別ウィンドウ、接続でロック解除状態と確定したリビジョンを共有する。別のファイルは個別にロック解除して編集し、選択中の保管庫の設定を維持する。空、不在、破損、未対応のファイルはエラーとし、エクスプローラーからの起動では初期化しない。`.tttykey` として保存された有効な暗号化手動バックアップは通常のファイルとして開ける。

設定で選択中の保管庫を変更しても、開いている編集ウィンドウは同じファイルを扱う。管理タブと次回以降の接続には新しい選択を使う。新たに選んだ保管庫が編集ウィンドウでロック解除済みなら、その状態を引き継ぐ。関係するファイルの保存やロック解除が処理中なら、完了後に切り替える。［復元］と［退避］の確認には対象パスを表示する。独立した編集ウィンドウで退避に成功したら、退避先を表示し、確認後にウィンドウを閉じる。復元やマスターパスワード変更の完了後は、同じパスで編集ウィンドウを維持し、表示を更新する。

### 編集機能の受け入れ条件

| 場面 | 期待する動作 |
| --- | --- |
| `.ttty` を二つ選択して［開く］を選ぶか Enter を押す | 場所ごとに登録し、二つの端末タブで通常の接続処理を行う。端末ウィンドウがなければ一つ作成する。 |
| `.ttty` を二つ選択して［編集］を選ぶ | 二つの編集ウィンドウで個別に保存できる。未起動なら編集ウィンドウのみを表示する。編集による登録や接続は発生しない。 |
| 編集中のプロファイルを別の入口から開く | 下書きを保持した既存ウィンドウを復元して前面に出す。別の場所にあるコピーは別ウィンドウで開く。 |
| 複数選択のうち一つの読み込みに失敗 | 対象パスのエラーを表示し、他の受け付け済みの処理を続ける。 |
| `.tttykey` を一つ開くか編集する、または複数を指定する | 一ファイルの場合は編集ウィンドウを開く。複数パスを含む保管庫の起動要求は、開いたりロック解除したりする前に拒否する。 |
| 選択中の保管庫の項目を別ウィンドウで変更 | 管理タブと次回の資格情報取得で同じ確定済みの内容を使い、再度ロック解除を求めない。 |
| 別の場所に置いた保管庫のコピーを編集 | コピーに保存し、接続では選択中のファイルを使う。コピーの編集ウィンドウを閉じると、そのロック解除状態を破棄する。 |
| A と B を開いた状態で選択を A から B に変更 | A と B の編集対象はそれぞれ維持する。管理タブと次回以降の接続では B の既存のロック解除状態を使う。 |
| プロファイル編集中に最後の端末ウィンドウを閉じる | 編集ウィンドウと下書きを維持する。通常起動でプロファイル選択を表示する。最後の編集ウィンドウを閉じて終了すると、共有していたロック解除状態も破棄する。 |
| 空または不在の保管庫を開く、または有効な保管庫を編集ウィンドウで退避 | 空・不在の場合はエラーを表示する。退避に成功した場合は退避先を表示し、確認後に編集ウィンドウを閉じる。 |

今後の検証対象は、すべての保存と復旧の結果、未知のフィールド、重複 ID とキー、同じ ID のコピー、不在または取り外し可能なプロファイル、リンク経由の相対パス、大文字と小文字を区別するフォルダー、モーダル中の起動、最後のタブの移動と閉鎖の競合、最小化時の起動、モニター取り外しと DPI 変更。この時点で実行時の検証は未実施。
