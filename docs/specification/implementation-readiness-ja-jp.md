## 初期リリースの範囲

- C#/WPF/.NET 10 LTS のアプリケーションとADR 0007のRust端末moduleを使い、Windows 11 x64 向けに自己完結型で配布する。ARM64 は任意。TabTty 独自のネイティブ端末コントロールを使い、xterm.js、WebView2、SSH.NET、ssh.exe、ConPTY は使わない。
- Microsoft/OpenSSL の依存関係方針と、範囲を限定した OpenSSH bcrypt_pbkdf の例外を適用する。ADR 0007はADR 0006のRustと標準ライブラリの例外を継承する。SSH のプロトコルとセッション処理は TabTty が担い、暗号処理は OpenSSL が担う。
- UI は英語と日本語に対応し、既定でシステムの言語に従い、英語にフォールバックする。周囲の UI はシステム、ライト、ダークのテーマに対応する。端末は既定で黒地に白文字を表示し、ANSI 色指定を反映する。
- SSH/Telnet/COM は保存済みの `.ttty` プロファイルが必要。信頼済みファイルからの起動では、最後にアクティブだったウィンドウに新しいタブを開く。ウィンドウ間のドラッグや統合でも接続を維持する。Telnet とシリアルのログインは手動とし、初期リリースにマクロランタイムは含めない。
- SFTP v3 は、呼び出し元タブで認証済みの SSH 接続内に必要時のみチャネルを開き、2 ペインでファイルとフォルダーを転送、管理する。接続先の名前には、転送ウィンドウを開く時点で取得した実効送信エンコーディングを使う。[SFTP の契約](file-transfer-ja-jp.md)を参照。
- Raw と Text は受信専用。Terminal は有効なローカルエコーを含む。各モードの厳密な挙動、ファイル名、一時停止と再試行、サイズ変更と行の確定、障害時の方針はそれぞれの仕様に従う。
- ポータブルな共有 `.tttykey`、起動ごとに初回利用時のロック解除一回、選択した秘密情報の一時的な利用、ホスト鍵の明示的な信頼と置き換え、インポート元の鍵のパスフレーズは UTF-8 のみ。正規化や別エンコーディングでの自動再試行は行わない。
- 正規表現に一致した箇所だけの強調表示、保持出力の検索、ネイティブ IME とアクセシビリティ、貼り付けのプレビューと送信間隔の調整、起動中のみの値の記憶、合意済みの既定値。

## 文書作業段階で完了したレビュー

一次資料とリポジトリの事実確認では、端末とコーデック、SSH と vault、プロファイルとウィンドウの各領域を検討した。集約により、JIS Roman と従来の ASCII の扱い、未対応の JIS 文字集合、CP932 と C1 の分類、消去と履歴保持、UIA の GetText、タブ切り替え時の IME キャンセル、接続先への右クリックの所有権、Windows の IDNA 処理系の選択、vault の外部変更時のライフサイクルの相違点を解消した。文書とソース資料の確認を行った段階であり、実装テストと独立したセキュリティ監査は今後の作業となる。

vault が保持するランダムな DEK は、暗号化ごとに HKDF でペイロード鍵を導出するためのルートと明記した。これにより、ペイロード全体の AES-GCM 暗号化と、繰り返し入力を求めない動作を保つ。複製または復元したファイルでの鍵の使用を規定する。グローバルカウンター、衝突の完全な回避、ロールバック防止、認証取得は保証の範囲外となる。固定の v1 フレーミングと AAD、合意済みのマスターパスワード変更手順は引き続き明記する。

## 実装準備完了の範囲

準備状況には、合意済みの製品判断、外部ファイルの契約、イベントと障害時の動作、初期リソース方針、検証計画を記録する。[実装状況](implementation-status-ja-jp.md)で、範囲ごとのコードと実行済みの検査を追跡する。実装後、リリース前にプロトコルの相互運用性、暗号のテストベクトル、アクセシビリティ、クリーンな PC への配布、性能、障害復旧の検査に合格する必要がある。

リリース条件には、独自 SSH、vault、ネイティブコードの独立したセキュリティレビューと、現行の一次ガイダンス、サポート対象の Windows/.NET/OpenSSL のバージョン、依存関係の出所とライセンス、保守方法の再確認を含む。実現不能または安全でない契約がテストで見つかった場合は、報告して仕様を明示的に修正する。互換性の低下、出力の喪失、認証情報の保護の弱体化を黙って行わない。

初期の ZIP 配布は手動更新とする。Store の ID と署名、パッケージ化後の保存、移行、アンインストール方針、認証は Store 対応時の条件となる。マクロ言語とランタイムと API、任意の ARM64 対応、再生ビューアー、ログのカスタム名用 UI は後続機能であり、初期仕様の準備完了を妨げない。
