## 範囲と所有権

[文字コードの決定記録](../drafts/terminal-codec-consultation.md)に対応する47種類を記録した。文字変換は Win32 の厳密変換または Windows 同梱 ICU を使用する。JIS の切替シーケンスと文字集合は ICU が決める。Rust は変換器の連携、受信元の分離、VT 制御の区切り、操作の事前検証、上限、結果の引き渡しを担当する。

既存の[端末とエンコーディング](terminal-and-encodings-ja-jp.md)、[セッションと記録](session-and-recording-ja-jp.md)、[履歴観測](ai-history-observation-ja-jp.md)の契約を Rust ですべて実現する。
合意済みの動作を引き続き正とする。完全な対応とは、意図的な対象外項目も含めてこれらの契約を満たすことであり、すべての xterm/VT 拡張を実装することではない。
ADR 0001 の SSH の責務分担と ADR 0002 のタブの同一性を維持する。

| 責務 | 目標設計での所有者 |
| --- | --- |
| 受信・送信の全47エンコーディング、独立した受信元の状態、厳密な送信検証と不正な単位の処理 | 承認済み変換器を呼び出す Rust の端末 module |
| VT 解析、文字集合・表示属性・モード、通常画面と代替画面、Unicode クラスタと幅、保持行、リフロー、アンカーとリビジョンのメタデータ | Rust の端末 module |
| 端末状態に依存するキー・マウスのエンコード、応答、厳密な入力の事前検証、コーデックの終端処理、ローカルエコーの効果 | Rust の端末 module |
| 受信専用 Text 投影と統合表示・Terminal 投影、記録の適格性とリビジョン、シリアライズした Text の位置、上限付き Text/Terminal バイト列 | Rust の端末 module |
| 上限付き画面・履歴取得、リテラルな履歴検索、チェックポイント、内容と保持状態の検証 | Rust の端末 module |
| 接続・プロファイルのスナップショット、セッションの世代と順序、入力権限とキュー、貼り付けのペーシング、同時送信の対象、トランスポートへの書き込みと確認 | 既存の C# セッション・アプリケーション module |
| 記録形式と投影の選択、Raw の受付、ファイル名とパート、ファイルの準備、ディスクへの書き込み、実際の I/O の後処理 | 既存の C# 記録 module |
| AI 連携先の権限、外部ハンドルと有効期限、JSON・フレームのサイズ制御、順序付けした公開 | 既存の C# AI 協業 module |

セッションを引き続きライフサイクルと順序の所有者とする。マネージド adapter を通じて端末イベントを直列化し、Rust がその端末上の意味と正となる状態を所有する。
C# は所有権を持つ不変スナップショットと表示キャッシュを保持できるが、変更可能な C# の端末複製は維持せず、Rust の端末操作を完了するためにマネージドのコーデックやパーサーを呼び出さない。

Text 記録を設定した場合は、引き続き受信専用投影が必要となる。
受信専用投影と受信・ローカルエコーの統合投影は同じ Rust 編集エンジンを使うが、内容とカーソル位置は異なる場合がある。
二つの投影は記録上の異なる意味を実現するためのものであり、ネイティブとマネージドのシャドーコピーではない。
EOF は受信を終了させるが、保持する表示と履歴の所有権は終了させない。
切断とタブ移動では、実際の所有者が解放するまで該当する Rust 状態を保持する。再接続では新しいセッション世代を作成する。

## マネージド実行を置き換える対応範囲

| 現在のマネージド処理経路 | 必要なネイティブ動作 |
| --- | --- |
| モデル作成時の従来エンコーディング | 対応するすべてのエンコーディングを Rust で開始する。DATA/stderr の独立した未完了状態、JIS・かなの状態、厳密な送信の事前検証を含む |
| 受信後のサイズ変更 | 保持行と論理的な内容のアンカー、記録の由来、幅広クラスタ、保持対象からの除去の意味を維持して、通常出力と退避中の出力をリフローする |
| 代替画面と追加の制御 | 契約した画面・モード・制御の動作をすべて実装する。受信元ごとの REP、スクロール領域、タブ、保存・復元、リセット、応答、入力モードを含む |
| 記録の開始・一時停止・再開・再試行・EOF | 端末モデルを置き換えずに、記録適格性の区間遷移とネイティブ側の記録位置の連続性を適用する |
| AI の画面・履歴アクセス | 正となる Rust モデルから、上限付きの不変な観測結果と不透明な検証メタデータを直接生成する |
| 観測者の接続 | 別の端末実装を選択せずに、順序付きで上限のある結果を提供する。将来のマクロ制約を維持する |
| スナップショット・効果のサイズや割当量の逼迫 | 上限付きのネイティブ準備処理と既存の明示的なリソース方針を適用する。リソース逼迫を理由に C# を選択しない |
| ネイティブバイナリの欠落・不一致、または診断用のマネージド選択 | 配布構成の失敗を報告する。本番にはマネージド端末モードを設けない |

製品契約の対象外で、形式が正しい未知の制御は、仕様どおりに消費・無視する。
契約で対応すると定めた制御を Rust が未実装である場合は、置き換え準備が未完了という欠陥として扱い、新しい製品上の対象外項目や引き継ぎの理由にしない。
この設計を満たすために、エンコーディング、保持内容、記録形式、受信元の独立性、観測機能を黙って削減しない。

## 順序、効果、interface

セッションごとに一つの順序付き変更ストリームを維持する。受信、受け付けた入力とエコー、サイズ変更、記録の遷移、EOF、閉鎖を含む。
Raw はプロトコルのフィルタリング後、デコード前に受け付ける。
SSH/SFTP のプロトコルバイト列は、端末解析とセッションログの対象外のままとする。
ファイルライター、ネットワーク待機、WPF のディスパッチ、JSON のシリアライズは端末状態の変更処理の外で行う。

通常の interface は端末に対する操作意図を受け取り、所有権と上限を持つ結果を返す。
その実装に、解析、投影状態、位置の追跡、整合性メタデータを隠す。
コールバックの接続手順、変更可能な行、呼び出し元が制御する Rust/C# の選択を公開してはならない。
合意済みの Q4 で、以下の名前付き記録操作を選定した。ネイティブ ABI の配置と実装固有の所有権を表す型は、実装設計の詳細として残す。

ネイティブ側の受付では、要求された操作全体を検証し、変更前に、上限付きの状態と効果に対するピーク時の予算を予約する。
上限付きのバッチ処理でも、既存のスケジューラーの公平性とキャンセルの機会を維持する。
拒否した入力では、使用中のエンコーダー状態を進めたり、入力の前半だけを出力したりしない。
既存の入力契約に従い、トランスポートへの送信受付結果で、エンコーダーの進行とローカルエコーを確定する時点を決める。先行した推測上のエコーと自動再送は引き続き対象外とする。

スナップショット、観測ページ、キューに入った記録の効果は、状態変更や破棄をまたいでネイティブメモリを借用できない。
明示的な所有権を持つ不変の結果を使い、ネイティブ状態、コピー、処理中の出力、後処理を実際の解放まで計上する。
受付はディスクへの永続化や接続先での受信を意味しない。
遅延した結果は、元のセッション世代・記録世代に属する。

seam では、セル、Unicode スカラー、書記素のオフセット、UTF-16 のオフセット、UTF-8 のバイト数を区別して定義する。
一つの整数オフセットを交換可能なものとして使わず、既存の意味を維持する。
C# の表示・レイアウトと UIA の adapter は、変更可能な端末状態を再構築せずにこれらの結果を使用する。

## 書記素操作の共有

[固定した端末規則](terminal-and-encodings-ja-jp.md#固定データによる絵文字認識)に従い、結合、セル幅、描画補助の適格性、スカラー・書記素・UTF-16・UTF-8 の計測を一つの Rust 規則で決める。C# はセッションの順序、権限、ペーシング、同時送信の調整、通信とファイル I/O を担当し、WPF はシェーピングと表示を担当する。C# 実行環境の Unicode カテゴリーやフォントのシェーピングで端末上の意味を決めない。マネージドの代替処理、差し替え可能な Unicode プロバイダー、新しい第三者 crate は導入しない。

Q21 では、既存の端末・入力・観測の seam に、名前付きの完結した操作と、所有権を持つ不変の単位計画を置く案を採用した。貼り付け全体の解析は稼働中の端末モデルなしで行えるが、受付済みの入力・プレビュー操作に属し、その保存容量を計上する。通常の呼び出し元は解析、送信、観測の完結操作を要求し、スカラーごとのループ、カーソル手順、内部ページ反復、ネイティブの予約手順を組み立てない。それらはマネージド adapter に隠す。第二の公開 Unicode 手順を増やさず、責務全体を引き受ける depth、規則を集約する locality、既存の利用側に対する leverage を得る。

成功を返す前に、最終ページを含む不変の入力全体を厳密に解析する。不正な UTF-16 や禁止制御があれば、未開始の操作全体を拒否し、置換、正規化、本番エンコーダーの進行、前半だけの送信、ローカルエコーを行わない。内部ページでサロゲートペアを分けてもデコード文脈を持ち越す。ページ終端は入力終端や書記素境界ではない。巨大な有効書記素は有限の継続状態とオフセットで走査し、書記素全体を別の一時バッファーへ複製しない。小さな索引や上限付き索引を使い、全スカラー・全書記素の個別記述子を必須としない。所有する入力計画を、表示用の 256 スカラー接頭部で置き換えない。

共通の分割と個数は、各送信先での符号化可能性や入力権限を証明しない。固定した全送信先が、現在の世代、エンコーダー、設定、モードの前提で入力全体を厳密に事前検証し、必要な資源を確保してから、最初のペイロードや開始マーカーを送る。再検証では既存予約を認識して二重計上しない。原文の共有保持、実 UTF-16 本文バイト数による設定可能な上限（既定 512 MiB）、CR/LF または本文が 1,024 バイト超の場合の確認、同時送信準備の30秒期限、終了用予約は[入力の所有権](session-and-recording-ja-jp.md)、[同時送信の準備](broadcast-input-operations-ja-jp.md)、[貼り付け資源](resources-and-validation-ja-jp.md)に従う。物理的に共有する原文を一度だけ計上し、端末状態と実際の貼り付け作業・コピーとともにアプリ全体の 4 GiB 枠へ含める。各送信先は他の入力と共通の既存 2 MiB／256単位の入力作業枠を使い、貼り付け用の別枠を追加しない。共有原文全体をこの作業枠へ再計上しない。セッションごとの端末状態 2 GiB 上限と、ローカルエコー状態の受付規則は維持する。Q27 により Stop は書記素の途中でも次の完全なスカラー、またはそれより大きい不可分なコーデック・制御単位で停止できる。CRLF は分割しない。内部チャンクの完了を、書記素の個数や追加の文字間待機として数えない。

受信元・REP の綴り、各投影の編集可能なグリッド末尾、シリアライズした Text の位置は独立させる。各保存文字列は先頭 256 スカラーを保持し、有限の分割状態は省略分を含むすべての適格入力で進める。幅と描画補助は保持接頭部で決める。一つの所有者の上限到達で受信元の操作全体から早期復帰したり、他の投影や適格な記録ストリームを飛ばしたりしない。Estimate と Execute は定義を共有し、それぞれの有効な状態から開始する。保持する 256 番目までは途中の幅変化を順序どおり適用し、それより後の省略部分で保存済みの寸法を変えない。通常・代替 Text、Terminal、Raw、REP への影響は[保存接頭部の契約](terminal-and-encodings-ja-jp.md#保存する接頭部と全入力による分割状態)に従う。この正常な保存省略はセッションや記録の障害にしない。

観測結果は、同じ取得、世代、投影、範囲に属するテキストと正となる保存済み範囲を所有し、明示的なオフセット単位と必要なセル・描画情報を持つ。VT で分かれた範囲、幅ゼロ内容、幅広セルの継続位置、投影による区切りを保持する。UIA は出力文字列を再分割して範囲を再構成せず、WPF は提供された描画補助情報を使う。所有権によって変更・破棄後も結果を読めるが、その結果が後の操作の有効な前提になるとは限らない。UIA の安定アンカーと除去時の縮退、AI 履歴の権限・期限・内容・保持の検査は別の規則として維持する。内部ページを理由に UIA の `GetText` を切り詰めたり AI の外部ページ・結果上限を変更したりしない。次の保存範囲が収まらなければ、進捗を偽らず既存の狭い資源・プロバイダー障害を返す。

Unicode 17.0.0、UAX29 r47、UAX11 r44、Emoji 17/UTS51 r29 に固定する。ビルドのマニフェストには `EastAsianWidth.txt`、`auxiliary/GraphemeBreakProperty.txt`、`DerivedCoreProperties.txt`（InCB）、`extracted/DerivedGeneralCategory.txt`（Mn/Mc/Me）、`emoji/emoji-data.txt`、`PropList.txt`（Variation_Selector プロパティ全体）、`emoji-sequences.txt`、`emoji-zwj-sequences.txt`、`emoji-variation-sequences.txt`、`emoji-test.txt` の正確な版付き出所とハッシュを記録する。実際の取得パス、範囲展開、既定プロパティ、集合の和、合意した qualification と複数スカラーの選別を記録する。再現可能な生成・検査、出所・版・ハッシュとデータ・スキーマ互換性の検査、該当する Unicode ライセンス通知を含める。ネイティブコードやデータの欠落・破損・不整合は明示的な配布・初期化障害とし、セッションを使わない解析も同じ検査に従う。実行時ダウンロードや OS データへの代替は行わない。

今後の検証では、固定版の公式 GraphemeBreakTest と、独立して定めた幅・配置・内容の期待値を通常の interface から確認する。旧マネージドの推測規則、生成済み検索処理自身、画面上の合成グリフを独立した正解にしない。関係するバイト・スカラー・ページ分割、最終入力の不正、受信元・投影の分離、観測の所有期間、255/256/257 と極長の継続、厳密な送信と Stop を含める。heart + VS16 + acute accent 254 個 + VS15 では、257 番目の省略された VS15 が幅を縮めないこと、accent が 253 個なら 256 番目に保持されて幅を縮めることを確認する。woman + acute accent 254 個 + ZWJ + laptop + grinning face では、省略する laptop も分割状態を進め、grinning face が新しい保存範囲になることを確認する。これらは必要な将来の観測であり、適合試験や性能測定を実行した結果ではない。

## 解釈規則の共有（Q6 合意済み）

受信元ごとの増分デコード、BOM・文字集合の扱い、VT の区切り、引数の解釈、完了した単位の分類、パーサーの上限、継続状態の規則を一つの Rust module に集約する。
検査と実行は、別々の対応一覧や独立実装の decoder/parser 状態機械を持たず、同じ定義を使う。現在の部分実装に限定せず、ADR 0007 に従って契約済みの全エンコーディングと制御を対象とする。

規則の共有は、受信元の状態を統合したり、独立した検査用状態を禁止したりするものではない。DATA/stderr の独立性、受信元ごとの直前文字と REP の意味、チャンク終端と EOF の違い、ローカルエコーの順序、未完了単位の記録区間情報を維持する。制御列に埋め込まれた C0 の独立した実行も含む。

容量検査と端末実行は別の責務として保つ。検査は操作全体を検証し、本番のネイティブ状態を変更する前に、状態・作業メモリ・出力効果のピーク必要量を予約する。実行は受け付けた意味を適切な Rust 投影へ反映する。
解釈 module は画面・履歴、記録ファイル、セッションの順序制御、通信を所有しない。画面状態に依存する効果は実行側の責務であり、その資源増加の見積もりは検査側の責務である。解析できたことだけでは、予算内で適用できることを意味しない。

### 共通規則による検査と実行の走査（Q7 合意済み）

一つの内部解釈 interface に、Estimate と Execute の二つの利用側を設ける。正常な操作では、まず独立した受信元状態と上限付きの見積もり用領域で入力を走査する。状態・出力効果のピーク必要量を予約し、入力と準備の前提を検証した後、元の本番受信元状態から同じ入力を Execute で走査する。検査後の状態から実行を始めてはならない。両者は同じ解釈規則を使い、CSI の再解釈や独立した対応一覧を持たない。

マネージド adapter がこの操作全体を所有し、必要に応じてネイティブの事前検査・予約・実行の呼び出しも内部に隠す。C# はセッションの順序とアプリ全体の容量管理を引き続き所有する。通常の呼び出し側に、パーサー状態・準備結果のハンドル、命令列、出力効果の排出責務を公開しない。

Estimate はネイティブ効果を発行せず、本番の受信元・投影・記録状態を変更しない。状態に依存する検査では、読み取り専用の実状態と課金済みで上限のある変更情報、共有する画面遷移定義、または十分な場合の保守的な上限を使う。削除した第二のパーサーを第二の画面処理エンジンで置き換えてはならない。文字数だけの見積もりで、クラスタ、モード・リセット、記録区間情報への影響を見落とさない。全画面の複製を前提とせず、検査用メモリは増設前に計上する。

入力と、関係する受信元・設定・投影・記録・画面寸法・未配送効果・確保容量の前提を、実行まで有効に保つ。内部段階の間に関係する変更を許す場合は、変更前に再検証し、古い準備を破棄して準備し直す。内部キャッシュも正確な入力と現在の許容量を検証し、表示・内容のリビジョンだけに頼らない。過去の 1024-byte キャッシュ構造は必須としない。失効時には通常の二度より多く走査する場合がある。
保有する予約と、想定した容量計上の変化を明示的に追跡する。再検証では当該操作が既に持つ予約を使い、同じ予約を二重計上したり、自分の予約が成立したことだけを理由に準備を無効化したりしない。想定外の前提変更では引き続き準備を無効化する。

受信元の複製、入力の所有、検査領域、展開、出力効果、同時に存在するネイティブ・マネージドのコピーを、確保・増設前に計上する。小さな入力や REP を無制限の出力に展開してはならない。容量に収めるために保持量を減らしたり、履歴を早く除去したり、拒否した操作の先頭だけを反映したりしない。既に受理した操作と C# の Raw 受付は、それぞれの所有権を維持する。

本番状態の実行前に取り消された場合は、ネイティブの先頭部分の効果を発生させず、内部の準備を解放する。実行開始後に待機を取り消しても、結果を巻き戻したり配送・後処理を放棄したりしない。検査成功後の予期しない実行障害は、ロールバックを保証する通常の容量拒否ではなく、再実行せず該当セッションの障害方針に従う。記録だけの拒否は Q5 を維持し、正常な端末更新と無関係な効果を保つ。検査では本番の記録資格を変更しない。

この選択は、検査・実行の構造を維持して解釈定義の重複をなくすものであり、測定前に速度やメモリの改善を示すものではない。独立した期待値、機能・過負荷・性能の検証を引き続き必要とする。[アーキテクチャのヒアリング](../drafts/terminal-architecture-deepening.md)の Q8 で、候補2の設計全体と検証条件を確定した。内部型の配置やネイティブ ABI の詳細は実装設計に残し、実装・試作は承認しない。

## 記録と観測の連続性

記録グループの選択、開始・停止要求、パートの所有権、ファイルの失敗は、セッションの順序付けの下で C# が引き続き扱う。
Rust は、端末側の適格性の変更、未完了のデコーダー・パーサー単位、通常画面・代替画面の Text 規則、正規化した Terminal 操作、シリアライズした Text の列・書記素状態を扱う。
一時停止中も受信と投影の更新を維持する。再開では過去の出力を補完せず、新たに適格となる内容から始める。
正常なカットオフ、最終 EOF、致命的な中止は、それぞれ異なる結果を維持する。

記録の受付または I/O の失敗は、引き続き選択したすべての記録形式を停止させる一方、健全な端末接続は継続する。
最初の記録準備は、トランスポートの起動前に成功していなければならない。
回復不能な端末状態の失敗は、[リソースと検証](resources-and-validation-ja-jp.md)の該当セッションに対する方針に従う。
合意済みの Q3 に従い、一部の投影だけ準備できた場合も、新しい記録区間は選択した全形式で未開始に揃える。
記録 module がそのグループ全体の結果と実際のファイルの後処理を所有し、端末 module が自身の接続状態と適格性を後処理する。呼び出し側による修復は不要とする。
Rust の端末状態が正常なら受信を継続する。すべての効果をロールバックするわけではなく、書き込み済みのバイト列は書き込み済みのままとなる。

### 記録操作の interface（Q4 合意済み）

C# の記録 module は、マネージド adapter を通じて三つの名前付き操作を使用する。名前は端末側の意味を表し、新たなネイティブ ABI を定めるものではない。

| 操作 | 端末側の意味 | C# での用途 |
| --- | --- | --- |
| `BeginRecording(projections)` | 選択された全 Rust 投影で新しい適格な区間を開始し、有効化失敗時は内部で後処理する | 全形式のファイルと writer 受付を準備した後の開始・再開・再試行 |
| `CutoffRecording()` | 適格な末尾を一度提出し、正常な締め切り規則に従って記録資格を終了する | 一時停止・最終終了。その後、実際の writer 完了・flush・close を行う |
| `AbortRecording()` | 通常の末尾提出をせず、記録資格を終了して未提出の記録専用 pending state を破棄する | 記録受付または writer の失敗 |

投影の選択は固定した接続スナップショットに従う。C# が記録グループの状態、パート番号、Raw の受付、再試行方針を所有する。Rust は Opening/Pausing/Paused/Failed を重複して持たず、再開と再試行も区別しない。
受信専用投影を構成した場合は、記録が無効な間も更新を続ける。Cutoff と Abort は端末状態を破棄しない。
受信 EOF はその受信元を確定する操作であり、保持する端末の寿命を終わらせたり、記録の締め切りを代替したりしない。後続の Cutoff で、EOF 時に確定した内容を再提出してはならない。

adapter が上限付きで不変なネイティブ結果、その順序付き Text/Terminal 配送、解放、記録失敗時の後処理を所有する。記録の呼び出し側が受け取るのは結果であり、ネイティブ結果を排出する手順、callback の修復作業、公開された区間ハンドルではない。
固定の内部出力 seam に、本番の writer 受付、またはテスト用の収集・拒否 adapter を接続する。同期的な受付失敗では、順序付き操作が戻る前にグループ受付と端末側の記録資格を終了する。非同期の writer 失敗では、グループ受付を直ちに閉じ、セッションの順序を通じて端末側の後処理を行う。

ネイティブ側の Cutoff 完了とディスクへの永続化は異なる。C# の記録 module がファイル操作全体を所有し、セッションの変更を保護する区間の外で受付済み writer 作業の完了を待つ。その完了と後処理の責務を UI や別の記録呼び出し元へ渡してはならない。

合意済みの Q5 で、この interface の契約を以下のように確定した。

- 結果は、適用済み・既に無効で変更なし・拒否を区別し、端末側の記録状態、端末の継続利用可否、失敗理由を返す。C# が全形式のグループ結果を所有する。ネイティブ側の記録状態は Raw の受付状態を表さない。
- 有効な区間がある間の Begin は変更前に拒否し、既存の区間とシリアライズした Text の位置を保つ。Q3 は有効な新規区間要求の準備失敗に適用する。既に記録中の公開 Resume は C# が何もしない操作として扱い、Begin を呼ばない。
- 無効な状態での Cutoff/Abort は出力、区間の増加、decoder/parser/位置の変更を起こさず完了する。記録無効の接続が、これらの操作で接続設定にない形式を有効化することはできない。
- 完了・失敗を適用する同じ順序付きイベント内で、セッションと記録所有者の識別を検証する。古い writer や準備要求が、新区間を中止したり古いパートを有効化したりしてはならない。識別情報は内部に隠す。
- 有効化前の取消し・失効では開始を確定せず、準備済みファイルの後処理を所有者に残す。確定後の待機取消しは、結果を巻き戻したり後処理を放棄したりせず、永続化完了も意味しない。後続の停止はセッションの順序に従う。一時停止がファイルを開く処理に先取りして割り込むことはない。
- Begin 成功では、同じイベント内でネイティブ有効化と、失敗を伴わない C# グループの状態確定が完了する。Cutoff 成功では、端末側の最終提出・受付と記録資格の終了が完了する。C# の Pause 成功には writer 完了・永続 flush・close も必要であり、その失敗を正常な Paused として報告しない。
- 記録提出が失敗しても、同じ操作の正常な端末更新と応答などの非記録効果を維持する。記録失敗を理由に操作を再実行したり、それらの効果を捨てたりしない。内部の後処理は発行済み資源を実際の完了まで所有する。回復不能な端末障害は従来の該当セッション終了方針に従う。

### 観測の連続性

AI の内容・リビジョン・保持状態の検査は Rust モデルを使い、編集してから元に戻したことも検出する。最終的なテキストの一致だけでは不十分である。
Text 記録の内容リビジョンと AI の変更の証拠は、それぞれ異なる意味を維持する。
リテラル検索は、契約した Ordinal/OrdinalIgnoreCase の比較、UTF-16 によるクエリと重なりの上限、クラスタ全体を単位とする位置、UTF-8 による応答上限を維持する。
Rust の小文字化や正規化は、これらの比較規則の代わりにはならない。

[順序付けした公開](ai-history-observation-ja-jp.md#順序付けした一つの結果としての公開)を維持する。
端末の検証、C# の権限・有効期限・キャンセルの検査、ブロックしないキュー受付、仮登録ハンドルの有効化は、端末状態の変更を排他した一つの順序付き結果を構成する。
Rust でコピーまたは検証した後に排他を解除し、再検証せずに後から公開すると、この契約に違反する。
内部の遷移は処理量に上限を持つ同期処理とし、外部の呼び出し元は端末のゲートや生の検証コールバックを管理しない。
MCP と権限の方針は C# に残す。

将来の受信観測者は、描画に依存せず、端末やロガーからデータを奪わずに順序付きの結果を使用する。
[将来のマクロ制約](../drafts/future-macro-design.md)を維持する。この再設計では初期リリースにマクロランタイムを追加しない。
SFTP がコーデックを共用する場合も、端末処理へのマネージドコーデックのコールバックを追加せず、既存のファイル名規則と厳密性を維持する。
