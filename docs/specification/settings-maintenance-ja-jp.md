# 設定のメンテナンスと ZIP バックアップ

2026-11-28 合意仕様。[English](settings-maintenance.md)

## メンテナンスタブ

ハンバーガーメニューの［ツール］に、［設定］と同じ階層で［メンテナンス］を置く。選ぶと操作元のウィンドウで独立した［メンテナンス］タブを開き、同じウィンドウにすでに開いていればそのタブを選択する。設定タブからメンテナンスのカテゴリを削除し、ハンバーガーメニューから SSH ホスト鍵の管理項目を取り除く。

メンテナンスタブでは、各行のボタンを左から次の順に横並びにする。英語と日本語のラベルを各言語のリソースで管理する。

| 項目 | ボタン |
| --- | --- |
| TabTty のファイル形式を Windows に登録 | ［登録］［登録解除］ |
| 接続プロファイルの信頼を管理 | ［個別解除］［一括解除］ |
| マクロの信頼を管理 | ［個別解除］［一括解除］ |
| SSH ホスト鍵の管理 | ［管理］ |
| アプリ設定の管理 | ［バックアップ］［復旧］［バックアップを検証］［既定値で再作成］ |

マクロの行はマクロ対応ビルドに適用する。［アプリの保存ファイルを復旧］タブと、そのタブから個別の `.bak` や `.json` を復元する機能は廃止する。ファイル選択には Windows のダイアログ、復旧項目の選択にはメンテナンスタブを表示しているウィンドウを所有元とする別ウィンドウを使う。各操作は保存済みの設定を対象とし、設定タブの下書きを確定しない。

### Windows のファイル形式

非パッケージ版では、現在の Windows ユーザーについて、［登録］で既存の登録方式に従って必要な登録を作成または更新する。［登録解除］では、既存のアンインストール補助と同じ範囲の TabTty 所有の関連付け候補、動詞、アイコン、アプリ登録を取り除く。共有キーにある他のアプリの値と、Windows の既定アプリの設定を保持する。登録内容が変わった場合は Windows シェルに通知する。どちらのボタンでも、完了、変更なし、失敗を操作元のダイアログに表示する。部分的な変更があれば、その範囲も示す。

関連付け候補は `.ttty` と `.tttykey`、マクロ対応ビルドでは `.tttym` も対象とする。`.tttylog` はアイコン登録のみを扱う。登録解除では、既存の TabTty のマクロ登録も対象に含める。

[エクスプローラーからの操作](persistence-and-windows-ja-jp.md#エクスプローラーと編集ウィンドウ) · [Windows のファイル形式](https://learn.microsoft.com/ja-jp/windows/win32/shell/fa-file-types) · [Windows の既定アプリ](https://learn.microsoft.com/ja-jp/windows/apps/develop/windows-integration/default-apps-platform)

### 信頼の個別解除と一括解除

- 接続プロファイルの［個別解除］は、マクロの信頼画面と同じ様式のダイアログを開く。正規化されたファイルパスを一覧から一つ選び、その場所に保存された版の信頼を解除する。未登録または現在は存在しないファイルの記録も表示する。記録が空なら空の画面を開く。登録、お気に入り、利用履歴は保持する。
- マクロの［個別解除］は、記憶済みの許可または拒否を一つ選んで解除する。既存の指紋、定数ファイルの版、引数による検索を使った選択方法を維持する。記録がなくても空の画面を開く。
- 各［一括解除］は、その種類の信頼だけを対象とする。確認ダイアログに対象を明示し、既定は［キャンセル］とする。すでに開始を許可した接続と実行中のマクロは続行する。次回の判断にはその時点の信頼記録を使う。

[接続プロファイルの信頼と処理順序](profile-trust-ja-jp.md#信頼の解除と保留中の操作)

### SSH ホスト鍵の管理

［管理］は、メンテナンスタブを表示しているウィンドウを所有元とするダイアログを開く。承認済みの接続先、ポート、鍵の形式、フィンガープリントを表示し、確認後に選んだ鍵を個別に削除する。削除しても既存セッションは続行する。接続時のホスト鍵の承認は、それぞれの接続で行う。

[接続先とホストレコード](transports-and-authentication-ja-jp.md#接続先とホストレコード)

## ZIP バックアップと検証

［バックアップ］はバックアップウィンドウを開く。保存先は Windows の保存ダイアログで指定し、全項目を一つの ZIP として保存する。バックアップウィンドウには「vault はこの ZIP に含まれません。［vault の管理］→［暗号化バックアップを作成］から保存できます」と表示する。

| 項目 | 収録する内容 |
| --- | --- |
| 設定 | 保存済みのアプリ設定。接続プロファイルフォルダーと vault のパス設定も含む。既定位置の指定は復旧先の PC でその既定位置を表す。 |
| 強調セット | 共有の強調セットとルール。参照に使う識別子を保持する。 |
| 接続プロファイル本体 | 現在設定されている接続プロファイルフォルダーの直下にある `.ttty` ファイル。登録の有無を問わない。 |
| 接続プロファイルの登録情報 | 収録したプロファイルに対応する確定済みの登録情報。お気に入りと最終利用日時を含む。本体が収録範囲外または存在しない登録の件数も記録する。 |

プロファイルの信頼、マクロの信頼、SSH ホスト鍵、vault 本体、`state.json` の全項目、ログ、以前の `.bak`、作業途中のファイルは対象外とする。まだ作られていない項目は「データなし」と記録する。対象に既存の破損ファイルや読み取りエラーがあれば、どの項目かを示してバックアップを失敗とし、完成した ZIP として公開しない。保存を検証できたら、保存先を示す。

ZIP はバージョン付きの目録を持つ。項目の有無、格納名、長さ、ダイジェスト、プロファイル本体と登録情報の対応を検証できるようにする。既存の形式ごとの読み込み制限に加え、展開サイズと収録数の上限を適用する。絶対パス、親ディレクトリ参照、重複した格納先など、想定外の格納名を拒否する。実際の復旧先はアプリが決定する。

［バックアップを検証］では ZIP を選択し、目録と収録ファイルの整合性、対応バージョン、各ファイルを読み込めることを検証する。結果はダイアログで示す。検証は読み取り専用とし、［復旧］でも書き込み前に同じ検証を行う。

## ZIP からの復旧

同じ PC と別の PC の両方をサポートする。ZIP を選んだら、収録内容と復旧可能な項目を別ウィンドウに表示する。チェックは初期状態ですべて外す。［接続プロファイルの登録情報］を選ぶと［接続プロファイル本体］も自動で選択し、登録情報を選んでいる間は外せない。［実行］の前に、対象項目、保存先、置き換え、ごみ箱への移動を確認できるようにする。

### 保存先

- ［設定］を選んだ場合は ZIP 内の設定パスを使う。選ばなかった場合は現在の設定パスを使う。既定以外の接続プロファイルフォルダーを適用または使用する際、フォルダーが存在すればそこを使う。存在しなければ書き込み前にパスを示し、別のフォルダーの選択か中止を求める。既定のフォルダーは本体の復旧に必要なら作成する。
- vault のパス設定を復旧する場合、指定ファイルが存在しなくても、親フォルダーがあればそのパスを反映する。既定以外で親フォルダーが存在しない場合は、別のフォルダーの選択か中止を求める。別のフォルダーを選んだ場合は指定された vault のファイル名を使う。vault のファイルの復元や初期化は発生しない。
- フォルダーが存在しないことと、アクセス権や I/O の問題で存在を確認できないことを区別する。設定を復旧する場合は、確認を経て決めたパスを設定に反映する。設定を選んでいない状態で別のプロファイルフォルダーを選ぶ場合は、その復旧操作の保存先として使う。結果には保存先と、そのフォルダーの登録を一覧に表示するための設定の変更方法を示す。

### 置き換えと結果

- プロファイルは ZIP の内容を検証し、書き込み候補を準備してから配置する。同名で同じ内容のファイルは書き直さず、復旧済みとして扱う。内容が異なる同名ファイルは、確認時から変化していないことを再検証し、Windows のごみ箱に移動してから ZIP 内の版を配置する。移動に失敗した場合や成否を確認できない場合は、置き換えを実行せず復旧失敗として止める。完全削除へ切り替えない。移動後に配置が失敗した場合も止め、旧版を移動した事実、新版の配置結果、ごみ箱から戻す方法を示す。結果ダイアログにはごみ箱へ移動したすべてのファイルを示す。
- 登録情報を選んだ場合、復旧を確認できたプロファイルだけについて保存先に登録を付け替え、お気に入りと最終利用日時を反映する。同じ保存先に登録がある場合は重複を作らず、復旧対象外の既存登録は保持する。本体が ZIP に含まれない登録は取り込まず、件数を結果に表示する。本体だけを復旧した場合は登録を追加しない。復旧は接続を開始せず、信頼を付与しない。
- 選択したすべての項目と保存先を変更前に検証する。保存先の競合や外部変更があれば、既存の保存規則に従う。書き込み開始後の失敗ではそこで止め、復旧済み・失敗・未実行の項目と、確認できたファイルの変更を結果ダイアログに表示する。

## 保存先の分離とローカル復旧

`profile-catalog.json` は登録情報を持つ。vault パスの設定は `settings.json` に一本化する。未リリースの旧形式や Windows 資格情報マネージャーの開発版マクロ信頼からの移行は不要とする。

`state.json` は共通の形式情報 `schemaVersion`、`requiredFeatures` と、次のローカル状態を持つ。

| フィールド | 内容 |
| --- | --- |
| `lastWindow` | 最後に保存したメインウィンドウの通常時の位置とサイズ、モニター ID、作業領域、DPI、最大化状態。通常の起動時に参照する。 |
| `recordingMappings` | 任意項目。ログ保存先のドライブ割り当ての変化を検出するために、その PC で記憶したパスと割り当てのダイジェスト。 |

`state.json` はこの PC の通常動作で保存・読み込みする。ZIP や個別ファイルによるバックアップ・復旧の対象から外し、検証済みの通常保存や再作成が完了したあとは、前の版をバックアップとして保持しない。書き込み結果の検証や成否不明時の再確認に必要な一時ファイルは、その確認に必要な間だけ保持する。

プロファイルの信頼、マクロの信頼、SSH ホスト鍵は、アプリが管理する独立した三つのファイルに保存する。各ファイルは Windows DPAPI-NG の `LOCAL=user` で保護し、現在の Windows ユーザーと PC に結び付ける。保護・検証・保存処理を共用できる。保護したデータに保存形式の版と記録の種類を含め、異なる種類のファイルの取り違えを検出する。信頼記録が読めない、壊れている、または保存が未確定の場合は、その記録を使った新しい許可を停止し、影響を受けた保存先を明示する。有効な記録がない初回の判定と読み込み障害は区別する。以前のコピーを自動で採用して解除済みの判断を復活させない。

通常の新規登録では、登録と自動信頼を一つの操作として報告する。両方の保存を検証してから完了を表示し、該当する接続を開始する。片方が失敗した場合は、その操作で確定した変更を取り消して結果を検証する。成否が不明なら実際の保存先を確認してから取り消す。その操作より前の記録や独立した後続の変更は保持する。取り消しにも失敗した場合は、登録・信頼・取り消しそれぞれの結果と、残った変更をダイアログに表示する。その操作から接続を開始せず、再起動後も未完了の操作による新しい信頼を有効にしない。[登録と信頼の整合性](profile-trust-ja-jp.md#信頼の解除と保留中の操作)

プロファイルの登録解除では、信頼を先に削除する。信頼の解除だけが成功した場合はその結果を確定し、信頼と一覧それぞれの結果を表示して［登録解除を再試行］を用意する。[登録解除の規則](profile-trust-ja-jp.md#信頼の解除と保留中の操作)

［前回の保存を再確認］は、結果が不明な保存の通知から実行できるようにする。その保存の実際の結果を照合する操作であり、ZIP の検証と区別する。［既定値で再作成］は、対象の保存ファイルと影響範囲を示し、明示的な確認後に実行する。設定、強調セット、プロファイル登録、ローカル状態、SSH ホスト鍵をファイル単位で選べる。プロファイル登録の再作成では登録情報を初期化する。ローカル状態の再作成ではウィンドウ配置とドライブ割り当て確認履歴を初期化する。SSH ホスト鍵を再作成した場合、以後は通常のホスト鍵の確認から始める。破損したプロファイルまたはマクロの信頼ファイルは、対応する信頼管理の［一括解除］で対象と影響を明示して空の状態に再作成できる。

## 受入条件

1. 日本語・英語で［ツール］の［メンテナンス］からタブを開き、同じウィンドウで再度選ぶと既存のタブに切り替わることを確認する。設定にメンテナンスのカテゴリがなく、SSH ホスト鍵の一覧と個別削除がメンテナンスタブから使えることを確認する。各行のボタンを確認し、Windows 登録・解除を繰り返して他アプリと既定アプリの設定を検証する。結果はダイアログで確認する。
2. 登録済み、未登録、移動済みのプロファイルを含む信頼から一件を解除する。空のマクロ信頼画面を開き、許可と拒否の両方を個別・一括で解除する。別の種類の信頼と登録情報が維持されることを確認する。
3. ZIP を作成し、未作成項目、破損した元ファイル、正しい ZIP、破損・未対応の ZIP を検証する。別の PC でも選択復旧でき、検証だけでは何も反映されないことを確認する。
4. 既定と独自のフォルダー、存在しないフォルダー、親フォルダーだけが存在する vault パスで、確認と反映が仕様どおり行われることを確認する。
5. 同一内容と異なる内容の同名プロファイル、ごみ箱への移動失敗、移動成功後の配置失敗を再現し、途中結果とごみ箱への移動が正確に報告されることを確認する。
6. 本体だけの復旧と、登録情報と本体の復旧をそれぞれ行う。登録情報の対応と対象外件数を確認する。ZIP に `state.json` とその項目が含まれず、復旧操作で `state.json` や信頼ファイルに変更がないことを確認する。`state.json` の保存・再作成に成功した後に旧版のバックアップが残らないことを確認する。
7. 保護ファイルの一つを別 PC にコピーするか、破損させる。該当する信頼だけが利用できないことと、対象を限定して再作成できることを確認する。新規登録で各保存と取り消しを失敗させ、再起動を挟んでも未確定の新しい信頼で接続しないことを確認する。
