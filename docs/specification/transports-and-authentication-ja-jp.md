# トランスポートと認証の契約

2026-11-10 時点の仕様。合意済みの SSH/OpenSSL ADR と Q131～Q143、Q161 を判断基準とする。アルゴリズム名と順序は `../drafts/ssh-transport-policy-proposals.md` に記載する。この文書では弱いフォールバックを追加せず、フレーミング、状態、識別情報、リソースの契約を確定する。実行時の証跡は[実装状況](implementation-status-ja-jp.md)を参照。

## 接続先とホストレコード

DNS 解決と信頼の照会で同じ正規接続先を使う。DNS 名または明示的な IPv4/IPv6 を受け付け、ポートは別に指定する。IPv4 は 0～255 の十進オクテット四つに限る。8 進数、16 進数、単一整数の省略記法は使えない。角括弧付き IPv6 は完全なホストリテラルとしてのみ解析する。識別には括弧を外し、アドレスのバイト列を正規化して数値スコープ ID を保持する。IPv4 マップド IPv6 は IPv6 のままとする。ホスト欄では URI スキーム、認証情報、パスやクエリ断片、空白や制御文字、曖昧な host:port の組み合わせを拒否する。

DNS には Win32 IdnToAscii を直接使う。UTF-16 入力長を明示し、IDN_USE_STD3_ASCII_RULES だけを設定する。IDN_ALLOW_UNASSIGNED、IDN_RAW_PUNYCODE、IDN_EMAIL_ADDRESS は設定しない。環境によって ICU と NLS を選ぶ .NET IdnMapping を使わず、Windows NLS に固定する。Unicode の区切りはその処理系に従って変換し、明示的な末尾ドット一つを除いてラベルごとに 63 バイト、全体で 253 バイトの上限を適用し、結果を ASCII の小文字にする。末尾ドットの有無は保持する。DNS 検索、別名、正規名の結果を信頼キーに反映しない。別のマッピングを自作せず、この処理系を使う。得られた ASCII の接続先をセッションに記録する。サポートする Windows とランタイムの組み合わせごとにラベルと正規化のベクトルを検証する。OS の変換に変更があれば信頼上の識別の互換性を確認し、既存レコードを黙って別の接続先へ移行しない。

`host-keys.json` は共通のバージョンフィールドと `destinations` を持つ。各項目は `kind`（`dns/ipv4/ipv6`）、正規の `host`、null 許容の `scopeId`、`port`、`keys` を含む。鍵ごとに `format`、正規 Base64 の `publicBlob`、SHA-256 フィンガープリント、UTC の `approvedAt` を持つ。接続先ごとに同じ形式の鍵は一つ。ECDSA は曲線ごとに形式が異なり、RSA SHA-2 署名は `ssh-rsa` 鍵ブロブを共有する。読み込み時にブロブの種類、サイズ、フィンガープリントを検証する。ホストレコードは vault から独立する。

ホスト署名の優先順は ssh-ed25519、ecdsa-sha2-nistp256、ecdsa-sha2-nistp384、ecdsa-sha2-nistp521、rsa-sha2-512、rsa-sha2-256。その接続先で承認済みの鍵形式を未知の形式より前に移し、グループ内の相対順は保持する。別の鍵や新しい鍵が提示された場合は、合意済みの初回または変更時の承認を要する。信頼の提示や認証情報の使用前に交換署名を検証する。RSA は PKCS#1 v1.5 と SHA-2 を使う。SHA-1 と RSA-PSS は使わない。ホストの別名に信頼を継承せず、機会に応じた鍵の自動学習を行わない。

## SSH トランスポートのフレーミングと鍵世代

SSH 2.0 または互換の 1.99 の識別を受け付ける。SSH1 パケットは受け付けない。識別行は CRLF を含めて 255 バイトまで。先行するサーバー行は 64 KiB と 256 行まで。端末データより前にあり、Raw/Text/Terminal には出力しない。通常の接続期限を適用し、バイナリや NUL を含む不正な識別は拒否する。

受け付ける完全なバイナリパケットの最大値は、長さと MAC またはタグを含めて 256 KiB。割り当てやディスパッチの前に整数加算、利用可能バイト、暗号のアラインメント、4 以上のパディング長、ペイロード範囲、アルゴリズム固有のフレーミングを検査する。RFC 4253 が求める 32768 バイトのペイロードと 35000 バイトのパケットの処理能力を満たす。より大きな上限は TabTty の防御上の選択。未認証の平文をディスパッチしない。成立しない状態、種別、長さの組み合わせは拒否し、MAC やタグに失敗した後に再同期を試みない。

GCM と CTR+EtM には別の保護アダプターを使う。OpenSSH GCM では平文の長さを AAD とし、暗号化本体にパディング長、ペイロード、パディングを含める。ノンスは SSH で導出した固定の 4 バイトの接頭部と 8 バイトの呼び出しカウンター、タグは 16 バイト。再利用せずに進め、カウンターが枯渇する前に失敗とする。MAC リストに共通項目がないことだけで GCM を拒否しない。EtM では内容の復号や公開より先に、シーケンス番号、平文のパケット長、暗号化本体を選択済みの HMAC で認証する。OpenSSH の厳密な構成に従う。

KEXINIT はカテゴリと方向ごとに許可済みアルゴリズム一つを交渉する。first_kex_packet_follows は必要に応じて誤った推測パケットを厳密に一つ破棄する。最初の交換ハッシュをセッション識別子として保持し続ける。NEWKEYS 自体には旧保護を使う。送信後は TX だけ、受信後は RX だけを切り替える。旧方向の状態は必要な間だけ保持し、その後消去する。

ext-info-c と、合意済みの strict KEX のクライアント名二つを通知する。厳密な初回 KEX では接続先の最初のバイナリパケットが KEXINIT であることを確認し、禁止される非 KEX メッセージや重複メッセージを拒否する。鍵再交換では RFC のトランスポート順序に従い、合法な送信済み通信も処理する。初回専用の厳密な除外をすべての再交換に適用しない。strict KEX を交渉した場合は初回も含め、各 NEWKEYS の後でその方向のシーケンス番号をリセットする。それ以外ではプロトコルどおり 2^32 を法として連続させる。

EXT_INFO は任意。NEWKEYS 後と認証成功前の許可された位置で解析する。正しい形式はパケット上限まで受け入れ、残りバイト数から個数の上限を求める。拡張や値に任意の小さい上限は設けない。未知の値は NUL を含めてバイナリとし、読み飛ばせる。server-sig-algs 拡張はユーザー署名に適用する。ホスト鍵の交渉には使わない。

保護バイト数は方向と鍵世代ごとに長さ、暗号化本体、MAC またはタグの合計を数える。NEWKEYS は旧世代に計上する。交換完了から 1 GiB または 1 時間で鍵再交換を開始する。KEX が必要とする間は通常の送信ペイロードを止め、上限付きの入力キューを維持する。世代ごとの厳格な上限は保護データ 2 GiB、2^31 パケット、2^32 AES ブロック、GCM 呼び出しカウンターが周回しないこと。最初に達した上限を適用する。厳格な境界に達する前に最大サイズのパケット一つと KEX 作業を予約する。残り予算で交換を完了できなければ切断する。1 GiB の開始条件を満たしても厳格な上限は適用する。双方の同時または接続先からの鍵再交換に対応し、既存の期限と信頼ダイアログの除外を適用する。

共有秘密には SSH 固有の符号化を使う。ハイブリッドの mlkem768x25519-sha256 は HASH(K_PQ || K_CL) を RFC の厳密な長さと順序に従って SSH 文字列にする。TLS ハイブリッドの符号化や mpint への代用は行わない。X25519 の共有秘密がすべてゼロの場合や長さが違う場合は拒否する。ECDH の名前付き曲線上の点と有限体の公開値は、固定グループごとの要件で検証する。暗号プリミティブは OpenSSL が実行し、アダプターがすべての戻り値を確認して不要な秘密情報を消去する。両方向とも圧縮は none。

## 認証とユーザー向けメッセージ

暗号化とホストの検証の後でのみ ssh-userauth サービスに入る。方式固有のメッセージ 60 は未完了の方式と要求に対応付けて処理する。保存済みの方式の許可リストと順序、選択した鍵一つ、パスワードのみの既定値に従う。server-sig-algs があれば使う。ない場合は、選択した RSA 鍵で SHA-512、次に SHA-256 を一度ずつ試し、SHA-1 は使わない。PK_OK だけでは認証は成立しない。認証段階が変わらない限り同じ鍵や署名の試行を繰り返さない。部分成功では段階を進め、受理された静的要素を使用済みにする。別の識別情報として再送しない。

段階ごとにパスワード送信または対話の開始は 3 回まで。内部上限は要素成功の段階 8、異なる公開鍵の試行は合計 8、対話ごとのラウンド 32、要求ごとのプロンプト 32、プロンプトまたは指示ごとに UTF-8 で 8 KiB、要求または応答ごとの合計 64 KiB。プロンプト 0 件なら応答も 0 件とし、空の応答は空のままにする。未回答の対話要求は最大一つ。各プロンプトを失敗回数として数えず、認証応答のタイムアウトは追加しない。上限に達したら明示的に失敗とし、キャンセルは常に表示して使えるようにする。

パスワード変更要求は有効なサーバー手順だが初期段階では未対応。理由を表示し、設定済みの別方式またはキャンセルを選べるようにする。パスワード変更 UI は追加せず、旧パスワードを黙って再送しない。キーボード対話では、プロンプトの内容やエコーフラグから保存パスワードを自動入力しない。SSH のパスワードと応答はプロトコルの UTF-8 を使い、端末コーデックでは変換しない。合意済みの認証期間だけ秘密情報を所有する。

バナー、切断、デバッグ、指示の本文は端末ログの外で、効果を持たないネイティブ UI テキストとして描画する。通常のレイアウト用空白以外の制御はエスケープする。タブごとに最大 64 メッセージまたは 256 KiB、非対話の本文は最大 16 KiB を表示し、切り詰めは明示する。対話プロンプトの上限を超えた場合は、質問を黙って短縮せず失敗とする。任意のサーバー本文や秘密の応答を診断出力に永続化しない。ネイティブエラーの診断は上限付きのコードや分類を使い、秘密素材を除く。

## チャネルと終了

起動時に対話端末用のセッションチャネルを一つ開き、want-reply=true で PTY、次にシェルを要求する。両方が成功して初めて Connected とする。exec や PTY なしへのフォールバック、自動起動コマンド、環境変数転送、転送機能、エージェントは追加しない。[ADR 0003](../adr/0003-reuse-the-tabs-ssh-connection-for-sftp.md)に従い、初期リリースにはタブの認証済み接続内で必要時に別サブシステムチャネルを使う [SFTP ファイル転送](file-transfer-ja-jp.md)を含める。以下の契約は端末チャネルに適用する。転送契約で SFTP のライフサイクル、チャネル分離、共有トランスポートのスケジューリングを定義する。PTY は取得した通知用端末種別、現在の文字単位の寸法、送信が UTF-8 の場合の IUTF8 を使う。確定したグリッド変更では window-change を送信する。合成した端末出力を生成せず、応答を待たない。

受信ウィンドウ 1 MiB、チャネルデータ最大 32768 を通知する。DATA と stderr の種類 1 は同じバイトウィンドウを消費する。下流の端末処理が受け付けたペイロードを解放した後でのみクレジットを返す。消費が 512 KiB に達したときか、残りが少なく進行が止まる場合にまとめて返す。ログの完了待ちでチャネルクレジットを保持しない。ログ障害は独立した方針に従う。未知の拡張データの種類はクレジットを消費し、端末とログに渡さず破棄してクレジットを戻す。ウィンドウ演算は検査付き uint32。相手の超過やオーバーフローはプロトコル障害とする。TX データは相手のウィンドウと最大パケットに従う。

未対応のチャネルの開設要求は拒否する。未知のチャネル要求やグローバル要求には want-reply が設定されている場合だけ失敗を返す。要求への応答は送信順で追跡し、新しい世代には対応付けない。SSH の死活監視には認証済みのグローバル要求 keepalive@openssh.com を応答ありで使う。成功や失敗の応答と他の有効な認証済み通信が生存の証拠になる。端末文字は送らない。合意済みの任意の間隔と回数を使う。

EOF はチャネルの受信方向全体を閉じる。一つの受信元だけを閉じることはない。一つのリデューサー境界で通常 DATA、次に stderr のデコーダーとパーサーを確定する。完了済み操作の順序を保ち、不完全な文字は一度だけ置換する。不完全な制御は破棄する。終了ステータスだけでは確定も閉鎖も行わない。CLOSE は EOF なしでも発生し得る。一度だけ確定し、最大一度応答し、双方の CLOSE を処理してからチャネルを解放する。ローカルの切断は未送信入力をキャンセルし、接続先の後処理に最大 2 秒を与える。exit や Ctrl+D は送らない。記録の排出には独自の所有権と待機の選択肢がある。再接続は明示的に新規接続する。

## Telnet

BINARY、ECHO、SGA、TERMINAL-TYPE、NAWS に RFC 1143 の Q method をオプションと方向ごとに独立して実装する。初期状態で TTYPE/NAWS を提示し、接続先の ECHO を要求し、SGA を提示かつ要求する。BINARY の開始は既定オフの保存済みスイッチに従う。接続先からの BINARY 要求は受け入れ可能とする。ローカル ECHO と未知のオプションは交渉ループなしで拒否する。実効エコーは交渉済みの接続先方向のみから追跡する。ログイン検出、保存パスワード、vault は使わない。

IAC IAC はデータ 1 バイトに復号する。非バイナリ RX では CR NUL は CR、CR LF は CRLF とし、その他のデータの前にある CR は CR を出力してそのデータを再処理する。交渉バイトは端末ペイロードに含めない。保留中の CR は EOF またはその方向のバイナリ解釈を変更する前にフラッシュする。それ以外の 8 ビットデータは保持する。非バイナリ TX では直後に LF がない CR を CR NUL にし、CRLF を維持してから IAC を二重化する。バイナリ TX でも IAC は二重化する。ストリームの CR 状態を送信単位の境界と調整し、無関係なユーザー入力を無期限に待たないようにする。

受理した TTYPE SEND には取得済みの端末種別を返す。NAWS は現在の列数と行数を 16 ビットで送信し、副交渉内でも IAC をエスケープする。完結した上限内の未知の副交渉はテキストに漏らさず消費する。NOP/GA/AYT/BRK/IP/AO/EC/EL/DM はプロトコルコマンドとして認識し、受信テキストや暗黙のローカル編集にはしない。初期 UI が送るのは合意済みの AYT と BREAK のみ。不正な IAC/SB フレーミングや 64 KiB を超える副交渉は該当接続の失敗とする。TCP の断片化でオプション、副交渉、保留中の CR の状態はリセットしない。

## シリアル

合意済みの他のハンドシェイクと DSR/DTR を利用できる Microsoft Win32 通信 API を使う。選択した COM 名をオーバーラップ I/O で排他的に開き、DCB とタイムアウトを設定および検証し、Connected にする。ドライバーの失敗や未対応の設定は値を代用せず拒否する。ボーレートはドライバーが受け付ける範囲の正の uint32。データ、パリティ、ストップビットの選択肢は固定する。

RTS/CTS では CTS の出力ゲートと RTS ハンドシェイクを使う。DSR/DTR では DSR の出力ゲートと DTR ハンドシェイクを使う。XON/XOFF は DC1/DC3 によるソフトウェアの入出力フロー制御を使う。ハンドシェイクの管理外では保存した DTR/RTS を適用する。既定は On。端末バイトを黙って編集する追加の DSR 感度、NUL やパリティの置換は有効にしない。一時的な手動の制御線操作や 1000 ms の BREAK はプロファイルを書き換えない。キャンセルや閉鎖時にハンドルがまだ使える場合は BREAK を解除する。切断や取り外しは I/O 所有権を無効にする。USB の識別情報に自動で再バインドしたり、保留中の入力を再送したりしない。

CE_OVERRUN/CE_RXOVER はデータ損失またはリソースエラーとして報告し、該当セッションを切断する。利用可能な出力を保持し、記録が不完全と表示する。フレーミングとパリティのエラーは明示的に報告する。ドライバーが渡していないバイトは Raw に含まれない。ログ保存が遅くても読み取りは独立して続ける。キャンセル要求を発行しても、実際に完了するまでバッファーを解放しない。

## 根拠と今後の検証

SSH の規範的なフィールド符号化と許可されるメッセージは RFC 4251/4252/4253/4254、4256、5656、8308、8332、8731、9142、10042、OpenSSH の EtM/GCM プロトコル記述、固定した strict KEX ドラフトに従う。選択した正確な名称は、既定どおり実装開始時とリリース前にセキュリティの観点で再確認する。上記の合意済み上限は TabTty の選択であり、RFC 全般の最大値ではない。

今後の検証対象は、独立した暗号プリミティブと通信上のベクトル、許可した全アルゴリズムの組、現行 OpenSSH とサポート対象の strict KEX 非対応ピア、不正パケット、最大サイズの EXT_INFO、初回交換と同時の鍵再交換、ホスト鍵の置き換え、MFA のラウンド、stderr の混在と EOF、残りウィンドウが小さい場合の動作、Telnet のオプションループと CR/IAC の断片化、シリアルの使用中、取り外し、ハンドシェイク、オーバーラン。独立した SSH とセキュリティのレビューはリリース条件。この文書の段階では、これらのテストとレビューは未実施。
