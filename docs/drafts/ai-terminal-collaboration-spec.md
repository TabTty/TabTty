## Problem Statement

People using TabTty want to work with an AI in the terminal session they already
have open. Copying output into a separate chat loses context, and an AI opening
another shell cannot see or operate the same interactive application. This is
especially limiting for full-screen applications such as top and vim.

The person needs to delegate a bounded task, including editing configuration,
saving files, and restarting services when the task requires it, while watching
the same output and retaining a dependable way to take control back. The
integration must also work with selectable external AI applications and local
models in closed environments, without requiring a built-in cloud service.

## Solution

Expose explicitly shared existing terminal sessions to an external AI application
on the same PC through MCP. A bundled stdio bridge connects the AI host to the
running TabTty application. The external host owns conversation, model selection,
inference, and planning; TabTty owns the terminal, output sharing, and input
authority.

The person first shares one tab with an identified AI sharing counterpart in
read-only mode and separately grants AI control. The AI reads positioned terminal
text and retained history, sends one bounded terminal action, observes again, and
returns control when finished. The person can take over from the tab menu or
status bar at any time. Taking over preserves AI output sharing; End AI sharing
revokes both reading and control. Tab icons distinguish read sharing from AI
control without changing the connection-name label.

## Implementation Decisions

- **Existing-session architecture.** Follow the accepted local-MCP architectural decision. Add one application-owned AI collaboration module above the existing terminal session and broadcast coordinator. Its interface covers counterpart attachment/loss, human sharing/grant/revocation, bounded observation, input, and state results. WPF commands and the MCP adapter use the same authorization owner. Keep terminal parsing, codecs, transport, recording, credentials, and clipboard responsibilities in their existing modules. Do not create a second terminal or receive stream for the AI.
- **Permission model.** Start unshared. Only the human can share a tab or grant control; the AI can return control but cannot obtain, renew, transfer, or broaden a grant. One counterpart may have several independently shared tabs, but one tab has only one counterpart. Replacing it ends the previous sharing. Permission belongs to an identified integration, potentially used by several conversations, and does not enforce a natural-language task or a per-chat sandbox.
- **Identity.** Use opaque counterpart, session-sharing, control, observation, and continuation identities. Bind session references to the tab, connection generation, sharing generation, and counterpart. A control ID names one human-granted interval. Possession of an ID alone is insufficient. Unshared discovery reveals no names, endpoints, profiles, tab counts, or window layout. It may return static schemas and this attachment's pairing/readiness data.
- **Control admission.** Grant only when the connection is input-ready, no active or paused macro owns input, and manual sends, paste, pressed-button gestures, and IME composition have finished or been cancelled. Include an originating broadcast gesture even when its source session is unchecked and receives no bytes. Do not queue a grant to activate later. Protocol-required replies alone do not make a session permanently busy.
- **Human takeover.** Revoke new AI input locally without an AI acknowledgement, stop the unsent tail at a valid encoded/grapheme boundary, and finish only required encoder, bracketed-paste, or matching mouse-release cleanup. Admit human input afterward. While cleanup remains, show Taking control, keep viewing/copy and Disconnect usable, and after five seconds explain that cleanup is still pending. Never inject Enter, Escape, Ctrl+C, or an exit command; never disconnect a healthy session solely to make takeover appear immediate.
- **Read revocation.** End sharing revokes future reading and input while preserving the usable connection. Cancel uncommitted observations/waits and invalidate handles. Recheck reading authority at the GUI's final admission of a bounded result into the private bridge delivery channel. No terminal payload is newly committed after revocation. Previously committed or OS/host-buffered output may arrive later and cannot be recalled; the bridge drops responses it can still cancel without claiming a truncated JSON frame is valid.
- **Lifetime.** Explicit AI return and human takeover preserve read sharing. Thinking or waiting has no grant idle deadline. Completion cannot be inferred from external chat; the AI must return control and later tasks require a fresh human grant. Remote disconnect ends control and can retain read sharing on a retained tab. Reconnect invalidates sharing before the new connection starts. Counterpart loss, tab close, and application exit invalidate affected permissions; restart never restores them. Tab moves, inner splits, background tabs, and minimization preserve session identity and permissions.
- **Broadcast exclusion.** Apply sharing, broadcast selection, and moves through one ordered coordinator transition. An active checked target, including an unready checked tab, cannot start sharing until the human unchecks it or stops the mode. Inactive remembered checks do not block sharing; starting sharing clears them. Throughout read sharing and control, keep the check off and disabled with a reason across Start, Select All, scope-reset selection, manual checking, and cross-window auto-selection. End sharing leaves it off; ordinary Stop/Start preserves off, while later ordinary explicit/bulk/first-or-reset selection may select it. Preserve frozen paste/mouse recipient sets and existing scope-move barriers. Read-only shared tabs may originate human broadcast to other targets; AI-controlled tabs cannot originate human input. AI sends never enter broadcast fan-out.
- **Macro exclusion.** Permit read-only observation where otherwise authorized, but retain exclusive macro input ownership during execution and pause. Stopping a macro does not grant AI control. This feature adds no macro runtime, attachment API, or launch API.
- **Current-screen data.** Read the combined terminal display, including permitted local echo, independently of painting, pane focus, and scroll position. Return normal/alternate source, dimensions, cursor position/visibility/style, positioned whole grapheme clusters, actual text, cell widths, blank/continuation information, rendition attributes, and supported keypad/cursor-key/mouse/bracketed-paste modes. Conceal remains a display flag, not redaction. Export neither raw ANSI/OSC nor application chrome, pane-local selection/search decoration, or IME composition. Include only cached highlight overlays matching current text/rule revisions and report pending highlights without blocking reception.
- **Screen captures.** Pages for one bounded region share an immutable capture with explicit coverage and expiry. Default to the full active grid; if it exceeds the capture budget, return region_required with dimensions and a fitting suggested region. Never silently crop or claim several region captures form one atomic screen. Expand each row's horizontal bounds to include complete clusters intersecting the requested cells and report the actual coverage.
- **Observation suitability.** Increment a layout epoch on every normal/alternate selection change, dimension change, and relevant reset, including change-and-change-back. Ordinary text/cursor/color refreshes may wake a wait but do not invalidate input. Validate connection and layout at preflight and first input admission. Bind action observations to the current control generation. Require read-state after every grant and completed send, with no AI send in flight at capture and a matching session-wide completion watermark. Keep these ordinals separate from grant-local action sequence. A capture during a send, or wait metadata alone, cannot authorize the next send. Remote application state may still change after admission; this is not an atomic transaction with the peer.
- **Retained history.** Read only the currently retained normal buffer, including its parked state while an alternate screen is active and content predating sharing. Do not read disk recordings, retain every alternate-screen redraw, or extend retention. Preserve Unicode, actual spaces, meaningful trailing spaces, hard boundaries, and soft-wrap relationships; do not invent LF at page boundaries. Use non-reused logical-line identities and stable content-span anchors/revisions, complete-cluster offsets, continuation and retained-prefix/suffix information. Appends outside a requested unchanged span, including a suffix on the same long line, do not invalidate that span. Never silently renumber surviving offsets after prefix eviction.
- **History ranges.** Make each returned page coherent at its capture point, with bounded metadata rather than a frozen unlimited transcript. Distinguish changed surviving content, erased/evicted ranges, and expired cursors. Initial reads return a recent chronological tail; opaque range and earlier_range handles allow revisiting it or walking backward. Search context_range handles use the same range argument. Ranges have inclusive start and exclusive end anchors; next_cursor continues forward inside the requested range when response bounds require it. Clients never manufacture row-number ranges.
- **Search.** Use literal OrdinalIgnoreCase by default and optional Ordinal comparison, with a nonempty query of at most 1024 UTF-16 units, no line breaks, normalization, or width/kana folding. Join soft wraps but never cross hard logical lines. Scan oldest to newest to an initial fixed end anchor. Use immutable windows of at most 256 KiB, with query-length overlap rounded to complete clusters and no duplicate boundary matches. Validate the entire advanced range, negative areas, context, and remaining-range proof; report changes without advancing stale progress. Return explicit coverage and continuation on budget exhaustion, even with no matches. Completion describes that fixed scan, not absence of matches in all current history.
- **Input actions.** Support text, key, paste, and remote mouse. Text is nonempty printable Unicode without C0/C1/DEL and adds no Enter. Keys include Enter, Backspace, Tab, Escape, named arrows/navigation, F1-F12, numeric keypad, and printable scalars, with valid Shift/Alt/Ctrl combinations mapped through existing terminal rules. Reject local UI shortcuts. Paste accepts literal nonempty text with TAB/CR/LF but no other C0/C1/DEL, optional character/line delays from 0 to 10000 ms, no implicit Enter or newline conversion, existing encoding preflight, and captured bracket framing. It neither reads the clipboard nor changes manual paste settings. Mouse supports mode-valid press/release/move/wheel in one-based cells, with tracked presses and existing single-session coordinate encoding; report effective coordinates when classic format clamps. Move never moves the Windows pointer. Only a matching live connection/reporting generation can receive cleanup release.
- **Input ordering and deduplication.** Use the existing session input owner, full-unit encoding preflight, local echo/recording rules, and ordered protocol replies. Permit one admitted AI send per session and grant-local action_seq from 1 through 2147483647, strictly next-only. After basic authority checks, check the duplicate ledger before new-send stale-observation/encoding/resource validation. A definitely-unadmitted rejection leaves sequence reusable. Atomically record high-water sequence, canonical-argument SHA-256 digest, and pending result before sending. Cache 256 outcomes; identical admitted retries return the cached result, changed arguments conflict, and older evicted outcomes report already_processed without sending. New RPC IDs do not bypass this rule. Exhaustion needs a new human grant.
- **Delivery and cancellation.** Distinguish pending, not_sent, submitted, possibly_partial, and unknown; report whether the sequence was consumed. Submitted is not remote execution success. Possible partial/uncertain send failure ends control, retains reading where allowed, and never retries automatically. A remote command's error text is not a transport-send failure. Cancelling a read/search/wait affects only that operation; cancelling an admitted send stops its tail and ends control through takeover cleanup. A host timeout alone is not proof of cancellation. No stale grant or lost response may authorize replay.
- **Waits.** Support bounded change and delay waits, default 1000 ms and inclusive range 0-10000 ms, at most one per shared session. Atomically compare/register changes to avoid missed wakeups. Count text/cursor/rendition/screen/mode changes, excluding caret blinking and pane overlays. Return changed, no_change, elapsed, or interruption, never an inferred exit code. Reads, listing, and human takeover remain available during a wait; permission or connection loss interrupts it.
- **Tool schemas and errors.** Expose the seven tools below in fixed order with closed JSON Schema 2020-12 inputs and a structured success/error output schema. Validate unknown fields, Unicode, enum combinations, and bounds before side effects. Opaque ASCII IDs have at most 256 characters. Initial and continuation forms are exclusive; continuation sends only session where applicable and cursor, inheriting options. Return structured data plus the same JSON serialized as text, accounting for both and escaping. Operational failures use tool errors; malformed protocol envelopes use protocol errors. Unknown/foreign sessions return not_shared without metadata, invalid controls return control_required only within an authorized session, and invalid/foreign observations or cursors uniformly return stale_observation or cursor_expired. Verified ranges may report range_changed or range_evicted. Other bounded codes include invalid_request, busy, resource_limit, region_required, unsupported_action, sequence_gap, sequence_conflict, already_processed, send_uncertain, and cancelled.

| Tool | Contract |
| --- | --- |
| tabtty_list_shared_sessions | Optional limit 50 by default, maximum 200; continuation cursor. Return this counterpart's ID, pairing code, interface version 1, authorized descriptors, and continuation. No unshared metadata. Current control ID is available only to the authorized counterpart. |
| tabtty_read_state | Session plus optional cell region and include_highlights default true, or continuation. Return source, cursor/modes, coherent cells, observation/capture metadata, coverage and continuation. |
| tabtty_read_history | Session plus optional opaque range, row/text limits, or continuation. Default to recent retained tail; return chronological fragments and earlier/forward handles. |
| tabtty_search_history | Session plus either an initial query with case, result-limit and context options, or continuation. Return matches, context handles, scanned coverage, completion and remaining work. |
| tabtty_wait | Session, change/delay kind, optional timeout, and observation for change waits. Return outcome and bounded current metadata, not implicit screen cells or action authorization. |
| tabtty_send_input | Session, control, action sequence, eligible observation, and one tagged input action. Return delivery, sequence consumption and surviving authority metadata. |
| tabtty_return_control | Session, control, and optional inert reason of at most 256 Unicode scalars. Return revoked/read-only/cleanup-pending state; old returns cannot revoke a newer control interval. |

- **Transport and compatibility.** Supply a local stdio bridge launched directly by the AI host, using a private Windows named pipe to the already running GUI. Ship the bridge, runtime, and resources together for offline startup; private-interface versions must match. Target MCP 2025-11-25 legacy initialize/initialized and 2026-07-28 per-request metadata/discovery as separately tested wire modes with the same tools. Modern requests require their own version/capabilities, use complete result envelopes, and static discovery/tool lists have a 300000 ms public cache scope. Never publicly cache terminal results or copy modern-only fields into legacy responses. Legacy ping and private heartbeats are distinct. Advertise tools only; add no sampling, elicitation, subscriptions, prompts, resources, model calls, or background-task extension.
- **Local attachment security.** Restrict pipe access to the current Windows logon, explicitly reject remote clients, and verify same user/logon/elevation. Fail closed on endpoint squatting or mismatched executable/installation/version. Obtain peer process IDs from the pipe, retain live process handles, and verify creation time/token/canonical sibling image with race checks; PID or product name alone is insufficient. Bind a random 128-bit counterpart ID to this app run, pipe instance, and bridge process; use independent handshake nonces and a unique eight-hex-digit display code. Claimed client names are bounded, inert, and unverified. This binds an integration channel, not a publisher, chat, model, or semantic task, and does not sandbox hostile same-user process access or a modified installation.
- **Bridge lifetime.** Use a five-second attach deadline, private heartbeat every five seconds, and twenty-second lost-health, blocked-write, and incomplete-frame deadlines. Heartbeats do not require model activity. Check elapsed deadlines on resume. Monitor the directly launching host process through a retained handle; inherited streams do not preserve grants after observed launcher exit. EOF, process loss, failed identity, framing failure, or broken channels ends attachment. Absent/closing GUI is an actionable unavailable result, not permission to launch it. Do not transparently reattach, recreate sessions, or keep TabTty alive.
- **Dependencies and setup.** Use a small TabTty-owned MCP adapter built from Microsoft .NET facilities and narrowly scoped documented Windows interop. Adopt no third-party SDK or policy exception. Preserve the own-SSH/OpenSSL boundary. Provide host-specific manual instructions and copyable executable/argument configuration; do not modify third-party files, install hosts/models, or fetch packages on startup. Keep model/provider credentials and endpoints out of connection profiles. Saved configuration never saves permissions.
- **UI.** Order the applicable broadcast checkbox, existing connection indicator, AI icon, unchanged profile name, and ordinary attention/close elements. Use an outlined eye for read sharing and a terminal rectangle with a play triangle for control, with distinct silhouettes and theme-aware strokes, no flashing or color-only distinction. Keep the disconnected icon alongside sharing. During cleanup retain the control icon with a transitional accessible description. Provide English/Japanese resource text, system-language/theme behavior, keyboard menu access, UI Automation names/states, and selected-tab counterpart/status/takeover controls. Announce state changes rather than incoming characters. Do not reserve an ordinary terminal key as an implicit takeover shortcut or forward a triggering key.
- **Secrets and assistance.** Keep password/OTP interaction with the human, followed by a new grant. Expose no vault-value retrieval or saved-secret submission tool. Help explanations stay in external chat; TabTty may display a bounded inert handoff reason without a modal dialog, clipboard access, or foreground activation. Output itself may contain secrets; no universal prompt detection, redaction, prompt-injection immunity, or retraction of delivered data is promised. Treat terminal text as untrusted task data, never an authorization instruction.
- **Recording and diagnostics.** Preserve ordinary session recording policy and add no AI transcript, injected terminal markers, or payload audit log. Diagnostics contain bounded operation/outcome/timing categories only, excluding terminal/input/search text, reasons, complete frames, credentials, pairing nonces, grant values, client metadata, process command lines, and exception dumps. AI work must not consume receive data away from existing terminal and logging observers.

Initial resource guards are delegated engineering choices, not measured results:

| Resource | Initial guard |
| --- | --- |
| Wire | UTF-8 JSON-RPC object per stdio line; no batches, BOM, banners, or nonprotocol stdout. Public/private JSON frames at most 2 MiB; private frame length checked before allocation. JSON depth 32, no duplicate properties or invalid UTF-8. |
| Results | 1 MiB combined serialized tool result including structured/text copies and escaping. Paginate at complete-cluster boundaries with explicit coverage. |
| History pages | 200 rows / 64 KiB text by default; maximum 1000 rows / 256 KiB UTF-8 text. JSON budget can require a smaller page and continuation. |
| Screen captures | 16 MiB per capture, two per counterpart, 64 MiB application total; fixed 60-second expiry, early release after completion/revocation. Oversize full grids require explicit regions. |
| Observation/range metadata | 256 handles per counterpart, 4096 per application, fixed 60-second expiry; no history-text pins. Expiry requires rereading, not loss of an idle grant. |
| Attachments/work | Eight bridge attachments per app and sixteen ordinary requests per counterpart; reserved return/cancel/revoke/health capacity. |
| Rates | Ordinary calls 20/s with burst 40 per counterpart, 100/s with burst 200 app-wide; new sends additionally 5/s with burst 10 per tab. Reject excess with a bounded busy/retry delay, without automatic replay or sequence consumption. |
| Search | 50 matches default / 200 maximum; two context logical lines per side default / ten maximum; 20 ms cooperative scan slices and 100 ms work per call before continuation. |
| Input | AI text at most 256 KiB UTF-8 before terminal encoding; retain existing 1 MiB finalized paste and 2 MiB/256-unit session queue bounds. One admitted AI send at a time. |
| Transient work | 64 MiB app-wide outside the separately charged snapshot pool; adapter payload at most 8 MiB per counterpart within that shared total. Count managed/native ownership until underlying I/O completes, including cancelled work. |
| Metadata | 16 KiB aggregate client metadata; displayed name/version at most 128 Unicode scalars each; never fetch supplied icons/URLs. |

Resource shortage rejects new AI work without shortening terminal retention,
blocking receive/logging, disconnecting a healthy terminal, or starving local
revocation. Engineering limits may be tuned from measurements without silently
changing accepted retention, authority, or failure behavior.

## Testing Decisions

- Use one primary application-level collaboration interface for GUI operations and MCP requests. Exercise sharing/grant/revocation, observation, sends, and state outcomes through that interface, over the existing real terminal/session model. Reuse controlled session-wire completion and a monotonic clock/scheduler at environmental boundaries; do not build a second fake collaboration implementation or assert private collection layouts.
- Judge tests by observable authority, returned captures/ranges, ordered submitted bytes, UI state, and independent remote effects. Production encoders decoding their own output, a model declaring success, and a quiet screen are insufficient oracles. Keep unauthorized payload submissions and automatic payload replays at zero; distinguish required session-owned cleanup in traces.
- Reuse existing terminal-output snapshot tests, independent receive-source/Unicode/alternate-screen tests, search ranges surviving unrelated append and reflow, and session queue rejection with a deliberately paused wire. Existing broadcast/split WPF tests and loopback TCP peers provide prior art for routing, frozen paste recipients, scope changes, window moves, and cancellation. Their synthetic IME coverage does not replace real Windows IME evidence.
- Test the collaboration module and its coordination with existing input ownership, terminal observation, broadcast selection, and connection/tab lifetime. Cover empty start, independent tabs/counterparts, identical claimed names, separate read/control permission, old return versus new grant, and denial of all unshared discovery and unsupported operation surfaces.
- Test current-screen and retained-history behavior at normal and maximum supported dimensions, including Japanese/combining/wide clusters, row-wise region expansion, captured highlight revisions, normal versus alternate source, parked history, expired snapshots, immutable screen pages, and explicit region-required fallback.
- Test literal search and history pagination with edits/erasure/eviction between calls, unchanged prefixes of growing long lines, soft-wrap versus hard-line boundaries, query overlap between scan windows, and changes to negative scanned regions or context before publication. Verify cursor-only continuations, range error distinctions, coverage, and every boundary at one below/exact/one above.
- Test grant and takeover races with queued manual input, paced paste, IME composition, multiple pressed buttons, and source-only broadcast gestures. Observe immediate local revocation, no further unapproved payload, bounded valid cleanup, visible pending state, and human input only after ownership is safe.
- Test per-control sequence, admission/completion ordinals, and observation generations under change-and-change-back, reconnect, grant changes, sends captured while still in flight, repeated lost-response requests, expired observations, argument mismatch, and ledger eviction. The duplicate path must never report a submitted action as a reusable definitely-unsent rejection.
- Place deterministic barriers before authorization, after admission, before first write, between partial writes, before result commit, and after response loss. Permute takeover, End sharing, disconnect, resize, duplicate requests, and late completions. Verify that no new result crosses the GUI disclosure commit after revocation while accurately describing already committed output.
- Test broadcast Start, Select All, manual checking, stop/start, scope reset, cross-window selection, frozen operations, and source/target distinction with read sharing and control. Represent active/paused macro ownership at the existing owner boundary without implementing macros.
- Test the packaged bridge through an independent protocol client before introducing an LLM. Cover both MCP revisions, discovery/cache/error envelopes, initialization/per-request metadata, cancellation response rules, malformed/oversize/slow frames, bounded diagnostic output, schema validation, and saturation of rate, queue, memory, and attachment limits without starving reserved control traffic.
- Use real Windows processes and named pipes for different users/logons/elevations, remote rejection, endpoint squatting, stale/PID-reused peers, wrong executables, lost launcher with inherited streams, suspend/resume, and all attach/heartbeat/write/frame deadlines. Mocks cannot establish Windows access control or real process lifetime behavior.
- Use actual WPF event routing, Windows Japanese IME, clipboard, pointer capture, keyboard-only operation, UI Automation/Narrator, supported DPI and themes for native behavior. Verify localized icon/tooltips/status, the retained disconnected shared tab, manual clipboard confirmations, and no focus stealing. ## Out of Scope

- Implementation, prototyping, package/model installation, and runtime validation during this specification/publication task. Development still requires an explicit request.

- Built-in AI chat, model hosting, provider selection UI, inference orchestration, or an ACP chat panel.
