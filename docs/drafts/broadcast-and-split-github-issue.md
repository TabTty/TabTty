## Problem Statement

Operators working with several SSH, Telnet, or serial connections must repeat the same terminal input separately and switch tabs to compare output. They also need to compare the current screen with earlier output from one connection without opening another connection or losing their reading position.

TabTty needs both selectable broadcast input and two levels of split display in the initial release. These features must work together across tab movement, connection changes, input failures, and window closure while preserving each session's encoding, terminal behavior, and recording. Settings and profile-editor tabs must remain ordinary application forms rather than terminal input recipients.

## Solution

Add Broadcast Input, available from terminal-tab context menus and the main menu. While it is active, terminal-tab checkboxes select the sessions that receive terminal input. The default scope is one window; an application setting enables an application-wide mode. Show the effective scope and the number of selected recipients that are ready. Retain selection across ordinary Stop/Start, reset selection to all-selected after changing scope, and make failures and cancellation visible.

Add recursively splittable tab groups, each with its own tab bar, for arranging different connections. Also allow recursive splitting inside a terminal tab into independent views of the same session. Both levels support side-by-side and top/bottom layouts. Inner panes share one terminal grid, output, and connection while maintaining independent browsing positions, selections, and search navigation. Splitting and removing splits do not connect or disconnect sessions.

## Implementation Decisions

- **Existing architecture:** retain the native WPF application and existing session, terminal model, encoding, recording, settings, and transport boundaries. Extend the application window/tab command and presentation layer for groups/panes and broadcast coordination. Extend existing session input admission only as needed for coordinated preflight and bounded delivery; do not create parallel send/receive owners for each view. Keep the Microsoft/OpenSSL dependency policy and existing transport/authentication boundaries.
- **Ownership:** one terminal tab represents one session and belongs to one group/window. A pane is a view of that session. The application-wide broadcast coordinator routes user-originated operations to stable session identities and connection generations once each. A tab carries all its panes through movement. Existing recording and SFTP ownership remains session-based.
- **Setting:** add the optional application boolean `broadcastAcrossWindows`, default false. Store the chosen scope preference only. Modes, checks, first-use flags, pending reset state, and both split layouts are application-run state, not persisted data.
- **Local/global scope:** disabled means independent modes per window; enabled means one mode across the application. Capture effective scope at Start. An active global mode and local modes cannot overlap. Global Start is unavailable until old local modes stop. Saving preferences does not change active input scope or restart any mode.
- **Stop semantics:** once the saved preference is global, ordinary Stop ends all active broadcasts, including old local modes. There is no separate Stop All item. A global mode remains stopped as a whole even after the saved preference changes to local. Display any difference between effective scope and the next-start preference.
- **Source versus recipient:** an input-capable terminal pane may originate input even if unchecked. Send only to checked, input-ready sessions in effective scope; the source receives it only if checked. Include hidden terminal tabs in selection. Settings/editor tabs are neither sources nor targets. Zero eligible recipients sends nothing and displays its state; it never falls back to the source.
- **First use:** the first local Start in a window selects its existing terminal tabs, including retained disconnected tabs. The first global Start selects existing terminal tabs across all windows. Ordinary Stop/Start without a scope-setting change preserves checks, including deliberate zero selection, regardless of the invoking tab.
- **Scope-change reset:** Q197/Q199 replace preservation across scope changes. A successfully saved scope change invalidates remembered selection in every window, while active recipients remain unchanged. Local-to-global checks every terminal tab at the next global Start. Global-to-local checks all tabs in each window at that window's next local Start without starting other windows. Changing and saving back before Start still leaves reset pending. Saving the same value, cancelling, or failing to save does not introduce a reset. There are no separate remembered selections for local/global modes.
- **Tab lifetime:** new terminal tabs start unchecked except when included in first-use or pending-reset initialization. Disconnect/reconnect in the same tab preserves its check; unready sessions receive no input and no replay. A committed cross-window move sets the check ON, including moving back. Same-window moves preserve it; unsuccessful moves do not change it. Closing the tab deletes its remembered selection. All runtime selection state ends at application exit.
- **New global windows:** a window joining an already-active unchanged global mode participates immediately; newly created tabs are unchecked, transferred tabs checked. Joining counts as first participation, preventing a delayed reset on later unchanged-scope restarts.
- **Commands/status:** provide Start, Stop, Select All, and Clear All in terminal-tab context menus and the main menu. Show checkboxes only on terminal tabs in participating windows while active. Bulk selection uses effective scope and respects operation locks. Show mode, effective scope, and ready-selected/total-selected counts in each participating window, distinguishing no selection from all selected sessions being unready.
- **Semantic input:** support ordinary text, once-committed IME text, terminal keys including Enter/arrows/control keys, paste, and source-classified remote mouse reports. Interpret each through the recipient's encoding, Enter/Backspace choices, key mode, mouse format, bracketed-paste mode, local echo, and recording rules. Do not duplicate a source's encoded bytes or recursively rebroadcast a delivery.
- **Excluded input:** local copy/selection/scroll/search/zoom, connection/disconnection, BREAK and other connection controls, resize notifications, automatic terminal replies, authentication-dialog input, and received output do not broadcast. Manual login typed into a terminal is ordinary terminal input.
- **Admission/order:** capture eligible recipients and connection generations per operation. Preflight required conversions and reserve bounded admission for all before releasing user payload to any recipient. Serialize admission for a mode and retain per-session ordering against other permitted input and automatic replies. Do not acquire multiple session locks while waiting or create another transport writer.
- **Failure:** preflight failure sends none of the operation. A conversion, admission, or send failure after sending begins stops the affected broadcast mode, cancels remaining work where possible, preserves checks, and reports per-recipient not-sent, submitted/possibly-delivered, or failed outcomes. Submission is not proof of remote execution. No rollback, automatic replay, or synchronized remote-execution guarantee. Already-unready selected tabs are excluded before an operation rather than failures solely because they are selected. Old input never targets a new connection generation.
- **Paste:** capture one immutable payload and freeze its intended recipients from preparation/preview through completion/cancellation. Show one required newline confirmation including the targets and shared character/line pacing controls; no-newline paste keeps the existing no-confirmation rule. Revalidate readiness/generation before commit rather than silently changing the approved list. Apply each target's codec/bracketing. Show per-target progress and one Stop for the whole paste. Reject additional terminal input during paste. Cancelled preview sends nothing; Stop cancels unsent payload and performs valid started-frame cleanup where possible without undoing delivery.
- **Input bounds:** preserve the 2 MiB/256-unit owned input limit per session, including preflight/in-flight data; finalized paste payload is at most 1 MiB per recipient with separately reserved closure capacity. Preserve pacing values from 0 to 10000 ms and their existing application-run-only remembering. A slow recipient does not grant unbounded queueing or silent omission; admission/send failure follows the visible stop policy.
- **Frozen selections:** disable checkbox and bulk-selection edits during paste or a remote button gesture until completion/cancellation. Record press recipients per button and unlock after all buttons complete. Stop cancels active work. Ordinary keys, wheel reports, and unbuttoned motion use fresh per-operation selection snapshots. Cross-window movement may reset a tab's remembered check during a frozen operation but changes only subsequent operations.
- **Mouse ownership/coordinates:** determine local/remote ownership at the source using its reporting mode and Shift override. Convert source view coordinates, including view offsets, to logical terminal cells. Local scrollbars and history browsing never emit remote reports. Respect each recipient's supported report types and modes. Skip out-of-grid or unrepresentable presses/motion rather than ratio-mapping or clamping them.
- **Mouse release:** leaving a recipient's grid does not end its drag; valid re-entry resumes motion. A recipient without the corresponding press cannot join midway. At physical button-up, release matching valid press recipients with coordinates clamped to their current grid and representable protocol range. For example, press at column 50 and release at column 70 yields a release at 60 for a 60-column recipient at the actual release time, with out-of-grid motion skipped. Classic encoding retains its 223-cell representability bound; SGR uses numeric coordinates. Do not invent releases for wheel/press-only protocols, changed reporting generations, or new connections.
- **Capture/loss:** keep gesture ownership independent of UI hosting, check capture success, and observe physical release once through permitted movement. Unexpected capture loss cancels with best-effort matching cleanup at the last known valid position only while the connection/mode permits it; report cancellation rather than pretending to have observed physical release. Grid exit is not capture loss. Do not infer missed release time/location from present button state.
- **Movement during sending:** global operations permit moves across windows; local operations permit same-window group moves. Moving into/out of an active local frozen operation's scope waits for completion or Stop; check both affected windows without blocking unrelated scopes. Keep frozen session/generation identities and the operation owner stable, including when the input-source tab moves.
- **Transfer commit:** prepare destination and input/capture handoff, commit destination insertion, then remove source placement and close an empty source. A failed/cancelled move preserves original ownership. If capture cannot be maintained, perform explicit gesture cancellation and report it rather than silently losing a release or claiming uninterrupted transfer. Do not dispose the last input host before the handoff decision.
- **Two layout trees:** use recursive binary splits for window-level groups and separately for panes within each terminal tab. Support left/right and top/bottom division at both levels, equal initial division, and draggable boundaries. Outer split creates an empty group; inner split creates a same-session view at the source position. No implicit connection creation. Saved profiles remain required to open connections.
- **Split removal:** inner removal closes only that view and collapses the branch; the last pane cannot be removed this way. Outer removal offers other groups in the same window labeled by position and selected-tab name; append source tabs in order to the chosen destination, preserve connections/checks, focus it, and collapse the removed branch. The last group cannot be removed. Tab closure remains a separate session lifecycle operation.
- **Placement/lifetime:** settings/editor tabs may occupy any group but cannot split internally. Keep empty groups while the window has any tabs. New tabs open in the active group; external profile activation uses the last active group of the existing last-active-window destination. Do not persist layouts or restore sessions/tabs; start a new run with one group and no inner splits, preserving existing window geometry policy.
- **Final-tab closure amendment:** removal of the final tab of any kind closes the window, including automatic/bulk closure and committed transfer. Settings/editor tabs count; empty groups do not. This explicitly replaces the older automatic/bulk-empty-window retention behavior. Initial window construction before attaching content is distinct from removing the final tab. Last-tab transfer establishes a surviving destination first, preserving the application run and vault unlock state. Closing the final application window ends the run normally.
- **Close invariants:** retain live/connecting-tab confirmation, combined window confirmation, and cancellation preserving content. Confirmed closure cancels affected unsent input and follows receive-cutoff/recording-drain rules; preserve associated SFTP cancellation/ownership behavior. Split removal alone disconnects nothing.
- **Shared grid:** derive terminal dimensions from the entire tab content rectangle as though no inner splits existed, using the shared font/zoom. Do not reduce that hypothetical rectangle separately for each pane's dividers/scrollbars. Inner splitting, pane focus, divider moves, and pane scrolling do not resize the remote terminal. Outer allocated geometry and shared font/zoom changes can resize it using existing normal reflow/alternate clipping rules.
- **Independent view state:** each pane owns horizontal/vertical position, text selection, and current search result/navigation anchor over shared retained content. Query/case and temporary zoom stay tab-shared. Use stable anchors through edits/reflow; eviction clamps affected anchors to surviving content, never extends retention for a pane. Search controls operate on the active pane. New output follows only views already following live output; history views retain position. Accepted keyboard/paste input reveals the operated pane's caret; cancelled/rejected input and broadcast delivery do not jump other history panes.
- **IME/accessibility:** composition belongs to its originating pane/session; changing terminal pane, tab, or disconnecting cancels uncommitted input without sending. Menus/dialogs retain Windows IME semantics and committed text remains once-only input. Each pane exposes a distinct accessible identity with its own visible range/selection backed by the shared model. Preserve existing UIA retained-range/snapshot rules and no default live announcements. Output never steals focus.
- **Usability bounds:** initial engineering minima are a terminal drawing viewport of 160 by 96 DIPs with room for at least two columns/one row at effective font size, and a group shell of 240 by 160 DIPs plus required controls/chrome. Include scrollbars/dividers and child requirements in recursive minimum calculations; sum on the split axis, take the maximum across it. Keep the documented outer-window minimum of 480 by 320 DIPs. These are initial engineering guards, not measured usability results.
- **Layout pressure:** reject new splits that cannot fit both usable child minima in the currently allocated region; do not enlarge virtual extent just to permit more splits. Existing layouts that no longer fit after resize/font change retain their tree and allocations with layout-level scrolling, rather than automatic deletion/merging. Divider ratios respect minima. Scrolling a layout changes visibility rather than terminal dimensions. Reject an inadmissible layout mutation before commit and keep the previous layout usable.
- **Resources/scheduling:** share terminal buffers and snapshots instead of multiplying retention, parsing, logging, or input allowances by pane count. Preserve existing terminal-grid and retained-row caps, session/application state budgets, application-wide cache/UIA limits, and fair scheduling with the existing per-visible-tab frame target. Charge pane view/cache state to existing budgets. Hidden sessions continue receiving and recording.
- **Keyboard/localization/theme:** expose group/pane splitting, removal, activation, movement, dividers, and target selection through keyboard-accessible commands and UIA. Distinguish group splits from inner pane splits. Do not add fixed shortcuts that consume ordinary terminal keys. Remote-owned terminal right-click stays remote; context/menu access remains available through existing local ownership rules. Provide English/Japanese resources and stable internal identities; retain system/default language and theme policies, fixed black/white terminal defaults, and existing ANSI/highlight behavior.

## Testing Decisions

- **Primary seam:** extend the existing WPF application integration harness at the application command/input boundary. Drive the same user-facing menus, checkboxes, terminal input, focus, move, close, and split operations as the application, then observe visible/accessibility state, live connection identity, received peer bytes, and recording results. This is the primary seam for the feature as a whole; do not introduce separate mock seams for every coordinator, pane, or divider.
- **Existing lower seam when needed:** reuse the session API and its existing replaceable session-wire boundary for deterministic blocked writes, admission failure, disconnect/generation transitions, and cancellation timing that cannot be reliably forced through a live peer. Keep production dispatch and encoders real. Observe submitted bytes, completion/failure, and retained state rather than private helper calls or internal collection structure. Prefer loopback peers for normal multi-session flows.
- **Good tests:** assert externally meaningful behavior and negative side effects: exact intended recipients, no unexpected bytes, no duplicate delivery/log entries, stable session ownership, correct accessible state, and bounded outcomes. Avoid assertions about private method calls, incidental WPF child order, or layout-tree implementation. Use explicit synchronization/deadlines and independent expected output; do not rely on arbitrary sleeps or expectations computed by the production conversion being tested.
- **Prior art:** the application harness already hosts real WPF input surfaces, drives native keyboard input, and checks bytes received by loopback Telnet peers. It also covers settings across open windows, menu/management-tab behavior, disconnected-tab lifecycle, rendering, and UIA text ranges across reflow/eviction. Core tests cover negotiated paste bracketing and Stop, rejected queue overflow using a paused wire, per-session recording, codec behavior, and retained-output/resource behavior. Extend these patterns rather than adding another test framework or external UI automation dependency. Existing tests asserting that automatic/bulk final-tab closure leaves the window open must be updated for the deliberate lifecycle change.
- **Scope/selection matrix:** test default local scope, independent local modes, global mode, hidden tabs, an unchecked source, settings input exclusion, no selected targets, all selected but unready, first use per window, new global windows, ordinary restarts, cross-window move/back, same-window moves, failed moves, close/reopen, reconnect without replay, scope change in both directions, saved change/back, same-value/cancelled/failed saves, and next-Start reset without mutating active operations. Verify ordinary Stop reaches all old local modes after global scope is saved.
- **Delivery matrix:** use recipients with different encoding, Enter/Backspace, key and bracket modes and verify each independently. Confirm one delivery per selected session despite multiple panes, one receive/log stream per session, no echo/reply recursion, preflight failure sending nowhere, and post-start failure exposing partial/uncertain outcomes without replay. Include ready-to-unready and generation-change races.
- **Paste matrix:** cover multiline confirmation target list, no-newline behavior, immutable text, whole-payload conversion/admission, common pacing, different target rates, per-target progress, Stop and frame cleanup, additional-input rejection, checkbox locking, and permitted movement while recipients stay frozen. A newly ready or newly checked moved tab must never join an active paste.
- **Mouse matrix:** vary source/target tracking and classic/SGR modes, grids, pane scroll offsets, Shift/local ownership, unsupported reports, overlapping buttons, wheel/press-only reports, grid exit/re-entry, and matching press membership. Verify the 100-column source/60-column target example: press at 50, out-of-grid motion at 70 skipped for the small target, then release at 60 only at physical button-up. Include protocol-coordinate bounds, changed generations, capture refusal/loss, and Stop.
- **Native input validation:** synthetic state tests are insufficient for capture, IME, and focus. Run Windows integration checks for actual capture handoff and exactly-once physical release while moving the source within a window and across windows, including final-source-window closure, DPI changes, and drag-and-drop. Do not assume ordinary mouse-position queries remain reliable during native drag-and-drop. Verify same-tab cross-pane IME cancellation, once-only commits, subsequent Enter, and unchanged menu/dialog behavior. Record manual evidence for OS interactions not reliably automated.
- **Layout/view matrix:** exercise both axes at both levels, recursive mixed layouts, equal split, divider resizing, empty-group creation, same-session pane creation, settings-tab eligibility, group destination selection/order/focus, last-pane/group protection, and all final-tab removal paths. Verify independent scroll/selection/current-match anchors, tab-shared query/case/zoom, no inner-split/focus grid resize, correct outer-resize behavior, preserved history, and new-tab/activation placement. Movement must preserve sessions, panes, recording, and associated transfer ownership.
- **Pressure/accessibility matrix:** verify rejected too-small splits, retained layouts and reachable controls after shrinking/font/DPI changes, allocation refusal without partial layout mutation, and no duplicate buffer/recording work. Exercise keyboard-only workflows and Narrator/UIA in English/Japanese and both application themes. Reuse the existing fair-workload approach to verify hidden receiving/logging sessions remain serviceable as visible panes increase; do not present engineering bounds as measured performance.
- **Completion evidence:** implementation must satisfy the accepted behavior and these tests with documented runtime results, including the native input cases. No runtime or benchmark result is claimed by this specification-writing task.

## Out of Scope

- Implementing or prototyping the feature as part of publishing this specification. Development starts only after an explicit implementation request.
- Macro execution, macro-language/runtime design, and automation of credentials or login prompts.
- Named or multiple independent broadcast groups within global mode, or broadcast to other application processes.
- Broadcasting local view operations, automatic terminal replies, authentication forms, connection controls, or resizing.
- Remote execution synchronization, transactional rollback across connections, automatic resend, or input queued for unready/reconnected sessions.
- Different sessions within one terminal tab, creating extra connections by splitting, or duplicating a session across separate tabs/windows as independent clones.
- Independent zoom or search query/case per inner pane, or resizing the shared terminal grid to whichever pane has focus.
- Persisting split layouts, broadcast mode/checks, or restoring tabs/connections at startup.
- New remote mouse protocols, proportional coordinate mapping, or general edge clamping of broadcast presses/motion.
- New fixed terminal-key shortcuts, external test frameworks, transport replacements, or dependency-policy exceptions.
- Redesigning existing profiles, SSH/authentication/vault, SFTP, recording formats, retention, language/theme, or packaging beyond the explicit integration and lifecycle amendments above.

## Further Notes

- This specification synthesizes accepted Q162-Q199. Q199 confirmed the complete shared understanding, including next-Start selection reset and group-removal behavior. The accepted ADR, "Two levels of splitting with one terminal session per tab," supplies the ownership/grid decision. Later answers supersede earlier withdrawn recommendations; in particular, cross-window moves check ON, scope changes reset all selection, and grid exit does not trigger an early physical-release report.
- RLogin provided reference behavior, not an automatic compatibility contract. Its [split FAQ](https://kmiya-culti.github.io/RLogin/faq.html#SPLIT) and [main documentation](https://kmiya-culti.github.io/RLogin/) informed the distinction between multi-connection arrangement and same-connection views. TabTty's separate tab bars, ownership, input safety, and lifecycle rules are the accepted product choices above.
- WPF [mouse capture](https://learn.microsoft.com/en-us/dotnet/api/system.windows.input.mouse.capture?view=windowsdesktop-10.0) can direct input outside an element and reports success; this does not establish lossless cross-window handoff. [Mouse position during drag-and-drop](https://learn.microsoft.com/en-us/dotnet/api/system.windows.input.mouse.getposition?view=windowsdesktop-10.0) requires the documented alternative coordinate paths.
