# Include shared macro constants in launch approval

A shared constants file can change which profile a macro opens, what it sends
or what prompt it waits for. Bind the remembered allow or block to the macro
source bytes, the ordered arguments and the exact bytes of every declared
constants file. The user reviews the same snapshots that the run consumes.

Byte identity lets a user recognize and restore a previously reviewed version
without depending on normalization or which branches the macro will take.
A formatting edit therefore requires review if that combination is new.
Identical copies of the complete set share the decision on the same PC.
The first macro-enabled release uses one v1 macro trust record format. The
same fingerprint calculation covers empty and nonempty declaration lists.
This keeps lookup, listing and removal independent of the number of declarations.
Development-build allows and blocks require fresh review. The macro language
header remains `#tttym 1`.
See the [accepted decisions](../drafts/macro-issue.md#shared-macro-constants-follow-up)
and the [trust contract](../drafts/macro-specification.md#remembered-macro-trust).
