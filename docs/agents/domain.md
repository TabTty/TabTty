# Domain docs

## Layout

TabTty uses a single-context layout.

- Glossary: `GLOSSARY.md` at the repository root.
- Architecture decision records: `docs/adr/`.

## Consumer rules

- Before exploring or designing code, read the glossary and ADRs relevant to
  the area being changed.
- If these documents do not exist, proceed silently.
- Use the domain-modeling skill to document terms and design decisions when
  they are resolved.
- Use the glossary vocabulary in issues, designs, code, and tests.
- If a proposal contradicts an existing ADR, identify the ADR and explain
  why the decision should be reconsidered.
