# TabTty

TabTty は Windows 11 x64 で動作します。フォルダー全体を展開し、`TabTty.exe` を実行してください。.NET ランタイム、ネイティブライブラリ、ライセンスファイルは、展開時の配置のままにしてください。

現在の Windows アカウントにファイル形式を登録するには、設定タブの **メンテナンス** で **TabTty のファイル形式を Windows に登録** を選びます。`.ttty`（接続プロファイル）、`.tttym`（マクロ）、`.tttykey`（認証情報 vault）の「プログラムから開く」に TabTty が追加されます。これらの形式と `.tttylog`（Raw および Terminal セッションログ）には、エクスプローラー用のアイコンも登録されます。実行ファイルと同じ場所に Assets フォルダーを置いてください。

アンインストールするには、TabTty のウィンドウをすべて閉じてください。同じ Windows アカウントで展開先のフォルダーを PowerShell で開き、以下を実行します。管理者権限は不要です。

```powershell
Unblock-File -LiteralPath .\Uninstall-TabTty.ps1
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Uninstall-TabTty.ps1
```

信頼できる ZIP に含まれるスクリプトを使ってください。2 行目の末尾に `-WhatIf` を付けると、レジストリへの変更を事前に確認できます。スクリプトは、現在のアカウントで展開先にかかわらず共通に使われる TabTty のファイル形式登録を解除します。Windows の既定のアプリの選択は変更しません。必要に応じて **設定 → アプリ → 既定のアプリ** から変更してください。アプリ本体、設定、プロファイル、vault、マクロ、ログは削除しません。実行後、展開先に保存したデータがあれば残し、アプリ本体のファイルを手動で削除してください。再登録するには、設定タブの同じボタンを使ってください。

タブバー右側のメニューボタンから、ファイル、編集、表示、ウィンドウ、接続、ツールの各メニューを開けます。タブバーの空いている部分をドラッグするとウィンドウが移動します。右端には最小化、最大化、閉じるボタンがあります。設定、登録済みプロファイル、認証情報 vault、SSH ホスト鍵、強調セットはタブで開きます。タブを閉じるには、タブ上の × を押します。

タブバー左側の **タブ一覧** から、そのタブグループ内の任意のタブを選べます。タブバーの端が薄く表示されている場合、その先にもタブがあります。タブバー上でマウスホイールを下に回すと次のタブ、上に回すと前のタブが選ばれます。先頭と末尾は循環します。

未保存の変更がある編集タブを閉じると、変更を破棄するか確認されます。**保存** は変更を適用し、タブを開いたままにします。**変更を破棄** は最後に保存した値に戻します。新規プロファイルの場合は初期値に戻ります。どちらの場合もタブは開いたままです。

TabTty のダイアログにはアプリのテーマが適用されます。Windows のファイル選択ダイアログには、Windows が提供する外観が適用されます。

## 接続

タブの横にある + メニューで登録済みプロファイルの名前を選ぶと接続できます。同じメニューから **新規プロファイル…** と **プロファイルを開く…** も選べます。プロファイルエディターで Telnet、SSH、COM のいずれかを選び、`.ttty` ファイルに保存します。プロファイルの新規作成、編集、複製は別ウィンドウで開きます。プロファイルエディターと設定では、左側のカテゴリ一覧から各セクションに移動できます。保存してもエディターは開いたままです。未保存の変更がある状態で閉じると、破棄するか確認されます。

保存したファイルを選ぶと接続できます。プロファイル一覧では、登録、お気に入りへの追加、検索、編集、複製ができます。以下の操作を使うには、Windows で `.ttty` と `.tttykey` を TabTty に関連付けます。

- `.ttty` の［開く］、ダブルクリック、Enter で、元の場所のプロファイルを登録して接続します。複数選択では、最後にアクティブだった端末ウィンドウに、ファイルごとの接続タブが追加されます。
- `.ttty` の［編集］では、選択したファイルごとに編集ウィンドウが開き、元のファイルに保存します。［編集］は［その他のオプションを表示］から選べます。
- `.tttykey` の［開く］、［編集］、ダブルクリックでは、一度に一つの vault を編集ウィンドウで開きます。選択中の vault は、編集ウィンドウ、TabTty 内の管理タブ、接続でロック解除状態を共有します。

ほかの人から受け取ったプロファイルは、［編集］で接続を開始せずに接続先、認証情報の参照先、記録設定を確認できます。記録が有効な場合、TabTty は端末に接続する前にログファイルを開きます。保存先がネットワーク共有の UNC パスである場合や、共有上のプロファイルが相対パスを指定している場合、Windows がその共有先に認証し、端末出力がそこに保存されることがあります。

プロファイルの変更は次回の接続から有効になります。既定のフォントと保持行数も次回の接続から適用されます。言語、アプリのテーマ、ベル、強調ルールは保存すると適用されます。端末の既定色は黒背景と白文字で固定され、受信した ANSI 色指定も反映されます。言語とテーマは既定で Windows の設定に従います。Windows の表示言語の優先リストに対応言語がなければ、UI は英語で表示されます。

タブは別ウィンドウに移動できます。ウィンドウの外にドラッグすると分離できます。接続中のタブを閉じると確認が表示されます。既定では、切断済みのタブは自動的に閉じます。切断後も出力を確認するには、設定で **切断済みタブを自動で閉じる** をオフにします。切断後も残っているタブには、接続名の横に切れたリンクのアイコンが表示されます。現在のウィンドウにある切断済みタブを閉じるには、タブバーを右クリックし、**切断済みをすべて閉じる** を選びます。最後のタブを閉じてもウィンドウは開いたままなので、その場から新しいタブを開けます。最後のタブを別ウィンドウに移動した場合は、移動元を閉じます。

## マクロ

マクロ対応ビルドでは、**ファイル → マクロを実行** から信頼できる `.tttym` ファイルを選びます。通常の引数は一つずつ別の項目として追加します。`TabTty.exe --macro "C:\ops\check.tttym" -- "argument with spaces"` でも実行できます。Windows の「プログラムから開く」で `.tttym` を TabTty に関連付けることもできます。ファイルの関連付けから起動した場合、引数は渡されません。

初めてのマクロ本体・宣言した定数ファイル・順序付き引数の組み合わせでは、実行前に読み込んだ内容を確認できます。マクロはコマンドや保存パスワードを接続先に送信できます。既定は **キャンセル** です。今回だけ実行するか、この組み合わせの許可・拒否を記憶できます。本体と定数ファイルが同じ内容で引数も同じなら、別の場所にあるコピーにも同じ判断が適用されます。判断は、この PC の Windows アカウント用の資格情報マネージャーに保存されます。取り消すには **設定 → メンテナンス → マクロの許可・拒否を管理** を開きます。外部起動でマクロ本体を読み込む際や、定数ファイルを読み込む際にネットワークへアクセスする可能性があれば、読み込み前に確認します。管理者権限での実行にも確認が必要です。

ソースの先頭には `#tttym 1` を記述します。マクロは新しいタブを開き、保存済みプロファイル一つを使って接続できます。プロファイルの相対パスはマクロのあるディレクトリが基準です。次のスクリプトはプロファイルで接続し、指定した文字列と完全に一致する部分文字列がプロンプトに現れるまで待ちます。

```text
#tttym 1
Connect(@"profiles\server.ttty");
WaitPrompt(Literal("$ "));
```

値を共有するには、`{"Prompt":"$ ","TimeoutMs":5000}` のような JSON オブジェクトを `common.json` に保存します。各マクロのバージョン行の後に `#constants Common "common.json"` を追加すると、接続後に `WaitPrompt(Literal(Common.Prompt), Common.TimeoutMs)` と指定できます。実行中は起動時の値を使い続けます。次回起動時には、整形だけの変更も実行許可の照合に反映されます。パスワードは vault に保存してください。

マクロの操作ボタンで、一時停止、再開、終了ができます。マクロを終了した時点で接続が正常なら、そのまま手動で入力できます。記録に失敗した場合は、記録を再試行したあと、マクロを明示的に再開します。受信履歴に欠落があった場合は、タブで継続か終了を選べます。保存済みパスワードを送信するときは、vault の項目名を `WritePassword` または `WritePasswordLine` に指定します。vault の管理画面でパスワード項目を選び、**マクロ用参照をコピー** を使うと、引用符付きの項目名をコピーできます。[マクロ言語リファレンス](docs/drafts/macro-language.md)を参照してください。

## 同時送信

端末タブを右クリックし、**同時送信 → 同時送信を開始** を選びます。**接続** メニューからも同じコマンドを実行できます。入力を送る端末タブそれぞれにチェックを入れます。ステータスには、有効な送信範囲と、選んだ接続のうち送信可能な数が表示されます。端末タブは、自身のチェックが外れていても入力元になれます。Enter、端末キー、確定した文字入力、貼り付け、接続先へのマウス報告は、送信先ごとにそのセッションの設定を使います。ローカルでのスクロール、選択、検索は現在のビューに対して行います。設定やプロファイルエディターには送信先のチェックボックスがありません。

初回の開始時には、範囲内にある既存の端末タブが選択されます。選択を変更するには、**すべての送信先を選択** または **送信先をすべて解除** を使います。終了後に同じ設定で再開すると、選択が引き継がれます。新しく開いた端末タブはチェックされています。タブを別ウィンドウに移動すると、以降の操作に向けてチェックが入ります。

複数のウィンドウに同時送信するには、**設定 → タブの動作** で **全ウィンドウでの同時送信を許可** を有効にします。次回の開始時に新しい範囲が適用され、範囲内の接続タブすべてが選択されます。実行中の同時送信では、終了するまで現在の範囲が使われます。全ウィンドウを対象とする設定が保存されている間は、**同時送信を終了** で全ウィンドウの同時送信が終了します。

同じタブで再接続すると、オン・オフの選択が保持されます。接続先が変わると、変更前と変更後の宛先が最前面に表示されます。通知を開いたまま、端末への入力と同時送信を続けられます。チェックボックスにポインターを合わせると接続先を確認できます。複数行の貼り付けでは、各宛先とタブ名を示す確認が一度表示されます。貼り付けや接続先に伝えるマウスドラッグの途中では、送信先が固定されます。**貼り付けを停止** を選ぶと、すべての送信先への残りの貼り付けが停止します。送信に失敗した場合は、再試行する前に送信先ごとの結果をステータスで確認してください。

同じウィンドウ内に限定した貼り付けや接続先へのドラッグ中は、そのウィンドウ内のグループ間でタブを移動できます。別のウィンドウに移動するには、操作の完了を待ちます。全ウィンドウを対象とした同時送信では、操作中もウィンドウ間で移動できます。

## タブグループと端末ペイン

**ウィンドウ → タブグループ** から、現在のグループを左右または上下に分割できます。各グループにタブバーがあります。既存のタブをグループのタブバーにドラッグするか、**ウィンドウ → タブを移動…** から移動先を選びます。グループの + メニューでは、保存済みプロファイルで接続できます。**グループを解除してタブを移動** では、解除するグループに含まれるタブの移動先を選べます。

**ウィンドウ → 端末ペイン**、または端末ペインのコンテキストメニューから、選択中の端末ビューを分割できます。各ペインには同じ接続が表示されます。スクロール位置、選択範囲、現在の検索結果はペインごとに独立しています。検索文字列、大文字と小文字の区別、ズームは共有されます。ペインを閉じても接続は続きます。

分割境界をドラッグすると、隣り合う領域のサイズを変更できます。分割境界にフォーカスを当てて矢印キーで変更することもできます。グループとペインのメニューから、領域間でフォーカスを移動できます。分割後にウィンドウが小さくなり、表示しきれなくなった場合は、レイアウトをスクロールすると他の領域に移動できます。アプリを起動するたびに、分割されていない一つのグループから始まります。

## 認証情報とホスト鍵

共有の `.tttykey` vault には、SSH ユーザー名とパスワード、または SSH ユーザー名とインポート済みの秘密鍵を組にして保存します。設定でパスを指定したあと、**ツール → 認証情報 vault** から **vault のロックを解除** または **vault の管理** を選びます。設定先が不在または 0 バイトの場合は、マスターパスワードの設定画面が開きます。14～1,024 Unicode スカラー値のパスワードを設定して **保存** を選ぶと、作成または初期化の成功後に管理タブが開きます。一度ロックを解除すると、TabTty を終了するか、選択中の vault を変更または退避するまで、すべてのプロファイルとウィンドウで利用できます。別の PC に移行する場合は、プロファイルファイルと一緒に vault をコピーしてください。プロファイルは、大文字・小文字を区別した名前の完全一致で vault の項目を参照します。

認証情報を変更する前に、暗号化バックアップを作成してください。バックアップには、作成時点のマスターパスワードが引き続き使われます。**vault の管理** で認証情報を追加またはインポートできます。編集や削除を行うには、該当項目を選びます。項目を改名する際は、その項目を参照する登録済みプロファイルも更新できます。バックアップの作成、復元、マスターパスワードの変更は、**vault ファイル** セクションで行います。

プロファイル編集の認証情報選択画面からも **vault の管理** を開けます。項目を追加したら選択画面を開き直してください。選んだ認証情報の方式が有効な間は、その認証情報のユーザー名が SSH ユーザー名欄に表示され、読み取り専用になります。接続時に vault が不在・0 バイトの場合や鍵が見つからない場合は、理由を表示し、許可された別の認証方式が利用可能なときに続行します。

秘密鍵のインポートでは、仕様で定めた OpenSSH、PKCS#8、RSA、EC の格納形式に対応します。暗号化されたインポート元の鍵のパスフレーズは UTF-8 で扱い、インポート後に破棄されます。インポート元のファイルはそのまま残ります。マスターパスワードとバックアップは別々に保管してください。忘れたマスターパスワードを TabTty で復元することはできません。

新しい vault を作り直すには、**認証情報 vault → vault を退避して作り直す…** を選びます。既存の vault は、同じフォルダー内の重複しない名前のファイルに移動されます。次にロックの解除または管理を選ぶと、設定済みのパスに新しい vault を初期化します。退避した vault を参照していたプロファイルでは、新しい認証情報を選び直してください。

初めて接続するサーバーや SSH ホスト鍵が変わったサーバーでは、承認前に、サーバーの管理者から別の経路で入手したフィンガープリントと照合してください。キーボード対話認証の回答は、質問欄の上に表示された SSH サーバーに送られます。TabTty の vault のマスターパスワードは、vault の画面でのみ入力してください。
保存済みのホスト鍵は、認証情報とは別に管理します。

新規プロファイルの初期選択は SSH です。Telnet は手動ログインで、パスワード、コマンド、端末出力が平文で送られます。接続中はタブに「Telnet（暗号化なし）」と表示されます。

## SSH ファイル転送

接続済みの SSH タブの見出しを右クリックし、**ファイル転送** を選びます。左ペインには Windows のドキュメントフォルダーが表示されます。右ペインには、ウィンドウに表示されている SSH アカウントに対するサーバー側の既定フォルダーが表示されます。移動するには、いずれかのフォルダーパスを編集して Enter を押すか、**親フォルダー** または **更新** を使います。

ファイルやフォルダーを選び、**送信 →** または **← 受信** を押すか、選択した項目をペイン間でドラッグします。フォルダー上にドロップすると、その中にコピーされます。ファイル上や空白部分にドロップすると、表示中のフォルダーにコピーされます。

同名のフォルダーは統合され、転送先にだけある項目は保持されます。同名のファイルがある場合は、名前、サイズ、最終更新日時を比較し、**上書き**、**スキップ**、**キャンセル** のいずれかを選びます。キャンセルしても保存済みのファイルは残ります。元の接続が利用できる間に **失敗した項目を再試行** を選ぶと、該当項目を最初から転送します。接続先のファイル名には、転送ウィンドウを開いた時点でそのタブに適用されている送信エンコーディングを使います。

SFTP でダウンロードしたファイルには、Windows のインターネットゾーン情報（Mark of the Web）が付きます。保存先には NTFS など、名前付きストリームに対応する場所を選んでください。ゾーン情報を保存できない場合は、新規作成や上書きを確定する前にダウンロードが失敗します。
ダウンロードしたファイルのアクセス権は現在の Windows ユーザーだけに付与します。共有フォルダー内の一時ファイルと上書き先にも適用します。他の利用者と共有するには、ダウンロード後にファイルのプロパティの［セキュリティ］でアクセス権を付与してください。アップロードではファイル作成時に所有者のみが読み書きできる権限（0600）を要求します。実際のアクセス権は接続先が管理します。

両方のペインで、フォルダーの作成や、ファイルとフォルダーの名前変更、削除ができます。フォルダーを削除すると、中の項目も削除対象になります。接続先での削除は完全削除です。ローカルでの削除には、利用できる場合に Windows のごみ箱を使います。タブが切断された場合は、転送ウィンドウで結果を確認し、再接続後にファイル転送を開き直してください。サーバーは SFTP v3 サブシステムに対応している必要があります。接続先のファイルを上書きするには、安全な置き換えにも対応している必要があります。

## 記録と端末入力

接続する前に、プロファイルで記録形式と保存先を選びます。相対ディレクトリは、プロファイルファイルを開いた場所を基準に解決されます。

- Raw は受信した端末ペイロードのバイト列を `.raw.tttylog` ファイルに保存します。
- Text は受信内容だけを表示テキストとして `.log` ファイルに保存します。LF を受信すると論理行が確定します。CR と BS による編集は反映されます。画面上の折り返しでは改行を挿入しません。代替画面の出力は簡略化した形式で記録します。
- Terminal はローカルエコーも含め、処理済みの表示操作を UTF-8 で `.term.tttylog` ファイルに保存します。

記録を一時停止すると、現在のパートが確定します。再開時には新しい番号のパートを作り、一時停止中の出力は補いません。記録の失敗は画面に表示されます。再試行では新しいパートを使い、書き込み結果を確認できなかったデータは再送しません。終了処理に時間がかかる場合は、そのまま待つか、未書き込みのログデータが失われる可能性を了承して閉じるかを選べます。

複数行の貼り付けでは、プレビューが表示され、文字間と行間の待ち時間をそれぞれ 0～10,000 ミリ秒で設定できます。待ち時間を記憶する設定は、その起動中にすべてのウィンドウに適用されます。**貼り付けを停止** は完了済みの入力境界を保ちます。ブラケットペーストの途中で接続がまだ使える場合は、終了シーケンスを送信します。初期状態では待ち時間は 0 で、記憶は無効です。

端末のコンテキストメニューとキーボードショートカットから、コピー、貼り付け、文字列検索ができます。検索対象は通常画面の保持済み出力です。接続先のアプリケーションがマウス報告を受け取っている場合は、Shift を押すとローカルで選択できます。名前付きの強調セットは正規表現に一致した箇所だけにスタイルを適用し、先に並んでいるルールが優先されます。タイムアウトしたルールはそのタブで一時停止され、明示的に再開できます。

## AI コラボレーション

端末タブのコンテキストメニューで **AI の接続設定** を選びます。表示された実行ファイルと stdio 引数を外部 MCP ホストに登録し、ホストが連携を開始する前に TabTty を起動します。**AIと出力を共有** では、ホストに表示された照合コードが一致することに加え、Windows が報告した起動元の実行ファイルのパスとプロセス ID を確認してください。ホストによっては補助プロセスがブリッジを起動します。ホストの表示名は自己申告です。起動元の情報から識別できるのはローカルのプロセスまでで、AI 製品、モデル、個々のチャットの真正性は確認できません。

権限は選んだブリッジ接続に付与されます。同じ表示名でも別の接続に共有されているタブは最初はゼロです。ブリッジを再起動した場合は、共有と入力の許可を改めて行います。一つのブリッジ接続を複数のチャットが使うホストでは、その権限を各チャットが使える場合があります。

共有は閲覧のみで始まります。AI は現在の端末画面と、タブが保持しているテキストを参照できます。端末入力を許可するには、**AIに操作を任せる** を選びます。閲覧のみの共有には目のアイコンが、AI による操作中には再生マーク付きの端末アイコンが表示されます。ステータスバーには連携先が表示されます。**AI操作を中断して引き継ぐ** を選ぶと、新たな AI 入力が止まり、共有は続きます。端末入力の後処理が必要な場合は、**引き継ぎ中** の表示が消えるまで待ちます。**AIとの共有を終了** を選ぶと、閲覧と入力の権限が取り消されます。連携先がすでに受け取ったデータは連携先に残ります。

Windows のロック、ユーザーの切り替え、リモートデスクトップの切断後も、連携先が接続されている間は付与した権限が続きます。離席中のアクセスを止めるには、タブのステータスバーで **AIとの共有を終了** を選びます。

端末にパスワードやワンタイムコードを入力する前に、**AIとの共有を終了** を選びます。タブを共有すると、その時点の画面と保持履歴が連携先に公開されます。共有開始前や共有を止めていた間の出力、ローカルや接続先からのエコー、端末の非表示属性で隠れている文字も含まれます。機密情報が画面や履歴に含まれた場合は、そのタブの共有を終了したまま、新しい端末セッションで AI コラボレーションを再開してください。

共有中のタブは同時送信の対象にできません。実行中または一時停止中のマクロは引き続き入力権限を持ち、AI は共有された出力を参照できます。

閉域ネットワークで利用する場合は、AI ホスト、推論ランタイム、モデルを事前に用意してください。ホストには、ローカル推論またはそのネットワークで利用が許可されたサーバーを使うように設定します。TabTty のパッケージには、stdio ブリッジとそのランタイムが含まれます。

## アプリケーションファイル

パッケージ外のアプリケーションデータは `%LOCALAPPDATA%\TabTty` に保存されます。設定、強調表示、登録情報とウィンドウの状態、SSH ホスト鍵は、それぞれ独立した JSON ストアに保存されます。設定からバックアップを明示的に復元したり、ストアを再作成したりできます。復旧では、以前のファイルを重複しない復旧用の名前で保存します。一時的に適用された既定値は、明示的に復旧するまで読み取り専用です。登録を解除してもプロファイルファイルは残ります。プロファイルファイルを削除する場合は、Windows のごみ箱への移動を要求します。

TabTty はテレメトリを送信せず、自動更新機能も備えていません。更新するには展開先のアプリケーションフォルダーを置き換えます。プロファイル、vault、アプリケーションデータは、それぞれ指定した場所に残ります。
